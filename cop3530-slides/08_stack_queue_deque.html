Stacks

Stack ADT: definition & behavior

  • Stack = collection where insertion/removal happen at one end (the top).

  • Discipline: LIFO (Last-In, First-Out).

Core operations

  • push(x): insert x at the top

  • pop(): remove the top item (pre: not empty)

  • peek(): read top item without removing (pre: not empty)

  • isEmpty(), size()

Stacks (linked lists): interface & invariants

  • top points to the current top node (or nullptr if empty)

  • size_ is updated on every push/pop

  • Push/pop are O(1) because they work at the head

template <typename T>
class Stack {
public:
  Stack() = default;
  ~Stack();                   // frees nodes

  void push(const T& x);
  void pop();                 // pre: !isEmpty()
  T& peek();                  // pre: !isEmpty()
  const T& peek() const;

  bool isEmpty() const { return top == nullptr; }
  std::size_t size() const { return size_; }

private:
  struct Node { T val; Node* next; };
  Node* top = nullptr;
  std::size_t size_ = 0;
};

Linked-list stack: push/pop/peek (core idea)

Push is just “prepend to a singly linked list.” Pop removes the head node.

template <typename T>
void Stack<T>::push(const T& x) {
  Node* newNode = new Node{x, top};
  top = newNode;
  ++size_;
}

template <typename T>
void Stack<T>::pop() {
  if (isEmpty()) throw std::runtime_error("pop on empty stack");
  Node* old = top;
  top = top->next;
  delete old;
  --size_;
}

template <typename T>
T& Stack<T>::peek() {
  if (isEmpty()) throw std::runtime_error("peek on empty stack");
  return top->val;
}

Linked-list stack: destructor

Destructor repeatedly pops until empty.

template <typename T>
Stack<T>::~Stack() {
  while (!isEmpty()) pop();
}

Stack (array-based): what we track

  • capacity: allocated array size

  • size: number of items currently stored

  • top index: top = size - 1 (or -1 if empty)

Bottom is at index 0; top item is at index size-1.

Unbounded stack (resizing idea)

  • Unbounded = no fixed maximum length

  • When full, allocate a bigger array (typical: double capacity)

  • Copy old elements, then continue the push

capacity=1: [12]
push(33) needs space -> resize to 2: [12, _] then store 33: [12, 33]
push(21) needs space -> resize to 4: [12, 33, _, _] then store 21

Bounded stack (max capacity)

  • Bounded = cannot exceed a maximum length

  • If size == maxCapacity, disallow pushes (return false or throw)

  • May still resize up to maxCapacity, then stop growing

Example maxCapacity = 3
- can grow up to 3
- push when size==3 is disallowed

One design: bounded or unbounded with maxCapacity

  • maxCapacity < 0 → unbounded (no max)

  • maxCapacity >= 0 → bounded (respect max)

  • Push rule: disallow when size == maxCapacity

Pseudocode: ArrayStackPush + resize

ArrayStackPush(stack, item):
  if stack.length == stack.maxLength:
    return false

  if stack.length == stack.allocationSize:
    ArrayStackResize(stack)

  stack.array[stack.length] = item
  stack.length = stack.length + 1
  return true

ArrayStackResize(stack):
  newSize = stack.allocationSize * 2
  if stack.maxLength > 0:
    newSize = min(newSize, stack.maxLength)
  newArray = allocate(newSize)
  copy old array into newArray
  stack.array = newArray
  stack.allocationSize = newSize

Array stack vs linked-list stack (trade-offs)

  • Array: great cache locality, low per-item overhead; resizing costs O(n) occasionally

  • Linked list: grows one node at a time, no resizing copy; extra pointer overhead

memorymay have unused slotspointer per node
localityexcellentweaker

Queues

What is a Queue?

  • Queue stores items in FIFO order: First-In, First-Out.

  • Insert at the rear, remove from the front.

Core operations

  • enqueue(x): insert x at rear

  • dequeue(): remove & return the front item

  • peek(): read front without removing

  • isEmpty(), size()

Queue using a linked list

  • Node holds data and next

  • Maintain two pointers:

    • front (head): first node

    • end (tail): last node

  • Invariant: empty queue → front == nullptr and end == nullptr

Enqueue (linked list)

Two cases: empty vs non-empty.

void enqueue(int new_data) {
  Node* node = new Node(new_data);

  if (isEmpty()) {
    front = end = node;
  } else {
    end->next = node;
    end = node;
  }
}

Only pointer updates at the tail → O(1).

Dequeue (linked list)

Remove from the front; if the queue becomes empty, fix end.

int dequeue() {
  if (isEmpty()) {
    std::cout << "Queue Underflow\n";
    return -1;
  }

  Node* temp = front;
  int removedData = temp->data;

  front = front->next;
  if (front == nullptr) end = nullptr; // now empty

  delete temp;
  return removedData;
}

Queue class (compact implementation)

class Node {
public:
  int value;
  Node* next;
  Node(int value = 0) : value(value), next(nullptr) {}
};

class Queue {
  int size;
  Node* head;  // front
  Node* tail;  // end
public:
  Queue() : size(0), head(nullptr), tail(nullptr) {}
  ~Queue() { while (head != nullptr) dequeue(); }

  int peek() { return head ? head->value : -1; }
  int length() { return size; }

  void enqueue(int value) {
    Node* node = new Node(value);
    if (head == nullptr) head = node;
    else tail->next = node;
    tail = node;
    ++size;
  }

  int dequeue() {
    if (head == nullptr) return -1;
    int value = head->value;
    Node* node = head;
    head = head->next;
    --size;
    if (head == nullptr) tail = nullptr;
    delete node;
    return value;
  }
};

Queue (array-based): basic idea

  • Keep an array arr and a size

  • In a basic approach, dequeue shifts elements left (costly)

  • Better real-world approach: circular buffer (no shifting)

Unbounded queue (resizing)

  • If array is full, allocate bigger array (double capacity)

  • Copy existing elements to new array

capacity=1, size=0
enqueue(12) -> capacity=1, size=1
enqueue(33) -> resize to 2, size=2
enqueue(21) -> resize to 4, size=3

Bounded queue (max capacity)

  • Bounded = cannot exceed maxCapacity

  • When size == maxCapacity, disallow enqueue

One design: bounded or unbounded with maxCapacity

  • maxCapacity < 0 → unbounded

  • maxCapacity >= 0 → bounded

  • Enqueue rule: disallow when size == maxCapacity

Array enqueue (resize when needed)

void enqueue(int x) {
  if (size == capacity) {
    int newCapacity = capacity * 2;
    int* newArr = new int[newCapacity];

    for (int i = 0; i < size; i++) newArr[i] = arr[i];

    delete[] arr;
    arr = newArr;
    capacity = newCapacity;
  }

  arr[size] = x;
  size++;
}

Basic array dequeue (shifting) — why it’s slow

This version is correct but costs O(n) per dequeue because it shifts.

void dequeue() {
  if (size == 0) {
    std::cout << "Queue Underflow\n";
    return;
  }
  for (int i = 1; i < size; i++) {
    arr[i - 1] = arr[i];
  }
  size--;
}

Better: circular array keeps front index and avoids shifting.

Array queue without shifting (front index + circular buffer)

  • Keep front (index of the current front item) and size

  • The rear index is computed: rear = (front + size) % capacity

  • Dequeue just moves front forward (wraps around) — no shifting

capacity = 6
indices:   0   1   2   3   4   5
arr:     [ _ | _ | A | B | C | _ ]
                   ^
               front=2, size=3

dequeue() removes A, then:
front = (front + 1) % 6 = 3
(no elements moved)
int peek() const {
  if (size == 0) return -1;
  return arr[front];
}

void enqueue(int x) {
  if (size == capacity) resize();                 // optional (unbounded)
  int rear = (front + size) % capacity;
  arr[rear] = x;
  ++size;
}

int dequeue() {
  if (size == 0) {
    std::cout << "Queue Underflow\n";
    return -1;
  }
  int value = arr[front];
  front = (front + 1) % capacity;                 // the key line
  --size;
  return value;
}

With a circular buffer, enqueue and dequeue are O(1) (amortized if you resize).

Deque

Deque (double-ended queue)

  • A deque supports insert/remove at both ends.

Operations

  • push_front(x): insert at the front

  • push_back(x): insert at the back

  • pop_front(): remove & return the front item

  • pop_back(): remove & return the back item

Common implementations: doubly linked list or circular buffer.

Deque: quick mental model

front  <-- operations happen here too -->  back

push_front(x)  puts x at front
push_back(x)   puts x at back
pop_front()    removes from front
pop_back()     removes from back

When is a deque useful?

  • Sliding window problems (keep candidates at both ends)

  • Undo/redo structures (two-ended adjustments)

  • Palindrome checks (compare front/back)

Complexity & Pitfalls

Typical time complexity

  • Stack (LL): push/pop/peek → O(1)

  • Stack (array): push/pop → O(1) amortized (resize occasionally O(n))

  • Queue (LL): enqueue/dequeue/peek → O(1)

  • Queue (basic array + shift): dequeue → O(n)

  • Deque: push/pop at either end → O(1) in typical implementations

Bug checklist

  • Calling pop/peek/dequeue on an empty structure (missing precondition checks)

  • For linked lists: forgetting to update both pointers when removing last node

  • Memory leaks: removed nodes not deleted

  • Dangling pointers: using a node after deletion

  • For arrays: forgetting to update size or copying wrong range on resize

If your invariant is always true, most operations become straightforward.

Wrap-up

  • Stacks: LIFO, work at the top

  • Queues: FIFO, insert rear / remove front

  • Deque: both ends

  • Implementation choices change performance and memory behavior
