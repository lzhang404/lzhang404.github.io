Raw vs Parameterized

List raw = new ArrayList();
raw.add(new BankAccount());
raw.add("my savings");                     // Allowed.

BankAccount b = (BankAccount) raw.get(1);  // ClassCastException.

List<BankAccount> accounts = new ArrayList<>();
accounts.add("my savings");                // Compile-time error.

BankAccount a = accounts.get(0);           // No cast needed.

  • The raw type allows the mistake.

  • The cast fails later.

Generic Class and Generic Method

public class Pair<T, U> {           // Declared after the class name.
    private final T first;
    private final U second;

    public Pair(T first, U second) {
        this.first = first;
        this.second = second;
    }

    public T getFirst()  { return first; }
    public U getSecond() { return second; }
}

public static <T> void printAll(T[] values) {   // Declared before the
    for (T value : values) {                    // return type.
        System.out.println(value);
    }
}

  • A class type is fixed when the object is created.

  • A method type is inferred at each call.

Bounds and Wildcards

Two Kinds of Bounds

A bound limits what type is allowed.

// Type parameter bound: declares and restricts T.
<T extends Number>

// Wildcard upper bound: unknown type, Number or below.
? extends Number

// Wildcard lower bound: unknown type, Integer or above.
? super Integer

  • <T extends Number> gives a class or method its own named type variable.

  • ? extends Number and ? super Integer are wildcard bounds inside a parameterized type.

  • Type parameter bounds use extends; wildcard bounds can use extends or super.

Upper Bound Example

A type parameter bound lets generic code use methods from the bound.

public class Box<T extends Number> {
    private final T value;

    public Box(T value) {
        this.value = value;
    }

    public double asDouble() {
        return value.doubleValue();
    }
}

  • T must be Number or a subclass of Number.

  • Box<Integer> and Box<Double> are allowed.

  • Box<String> is rejected.

  • The bound is what makes doubleValue() available.

  • Run: GenericMethodDemo.java

  • Uses: Box.java

Type Parameter Bound: Comparable Values

A method that finds the maximum value needs values that know how to compare themselves.

public static <T extends Comparable<T>> T max(List<T> items) {
    T best = items.get(0);

    for (T item : items) {
        if (item.compareTo(best) > 0) {
            best = item;
        }
    }

    return best;
}

  • T extends Comparable<T> means T can compare itself to another T.

  • The bound is what makes compareTo available.

  • The JDK uses a more flexible version: Comparable<? super T>.

  • Run: GenericMethodDemo.java

Why Wildcard Bounds?

Ordinary generic types are invariant, so related element types do not automatically make related list types.

class Animal { }
class Dog extends Animal { }
class Cat extends Animal { }

// Arrays are covariant.
Dog[] dogs = new Dog[2];
Animal[] animals = dogs;       // Allowed.
animals[0] = new Cat();        // Runtime error.

// Generic lists are invariant.
List<Dog> dogList = new ArrayList<>();
List<Animal> animalList = dogList;  // Compile-time error.

// Wildcard bound gives a controlled view.
List<? extends Animal> animalView = dogList;  // Allowed for reading.

  • Covariant: same direction, such as Dog[] used as Animal[].

  • Invariant: no subtype relationship, such as List<Dog> and List<Animal>.

  • Wildcards provide controlled flexibility without making List<T> itself covariant.

  • Run: WildcardsDemo.java

Wildcard Upper Bound: ? extends T

Use ? extends T when the parameter mainly produces values for your method to read.

public static double sum(List<? extends Number> numbers) {
    double total = 0;

    for (Number n : numbers) {
        total += n.doubleValue();
    }

    // numbers.add(1);      // Compile-time error.
    return total;
}

sum(List.of(1, 2, 3));      // List<Integer>
sum(List.of(1.5, 2.5));     // List<Double>

  • The list contains some unknown subtype of Number.

  • Reading as Number is safe.

  • Adding a non-null value is unsafe because the exact list type is unknown.

  • Run: WildcardsDemo.java

Wildcard Lower Bound: ? super T

Use ? super T when the parameter mainly consumes values written by your method.

public static void addIntegers(List<? super Integer> target) {
    target.add(1);
    target.add(2);

    Object o = target.get(0);
}

addIntegers(new ArrayList<Integer>());
addIntegers(new ArrayList<Number>());
addIntegers(new ArrayList<Object>());

  • The list element type is Integer or a supertype of Integer.

  • Adding an Integer is safe in all three cases.

  • Reading yields only Object because the exact list type is unknown.

  • Run: WildcardsDemo.java

The PECS Rule

The parameter is Use You can
Read from only List<? extends T> Read as T
Write to only List<? super T> Write a T
Read and write List<T> Read and write 
public static <T> void copy(List<? super T> dest,
                            List<? extends T> src)

  • src produces values: use extends.

  • dest consumes values: use super.

  • Wildcards describe data flow.

Exercise: Wildcard Bounds

// 1. Print every element.
static <T> void printAll(List<___> items)

// 2. Add all given elements into a target list.
static <T> void addAll(List<___> target, T[] values)

// 3. Run an action on every element.
static <T> void forEach(List<___> items, Consumer<___> action)

  • Does the method read from this parameter?

  • Does the method write to it?

  • Choose an upper bound, lower bound, or exact T.

Exercise: Answers

static <T> void printAll(List<? extends T> items)

static <T> void addAll(List<? super T> target, T[] values)

static <T> void forEach(List<? extends T> items,
                        Consumer<? super T> action)

  • 1. The list is only read from, so it uses an upper bound.

  • 2. The list is only written to, so it uses a lower bound.

  • 3. The list produces values; the Consumer receives them.

  • Iterable.forEach uses Consumer<? super T>.

  • Stream.forEach uses the same pattern.

Type Erasure

Type Erasure

Java checks generic types at compile time, but most generic type information is removed before the program runs.

// No bound: T erases to Object
class Box<T> {
    T value;
}

// Conceptually at runtime:
class Box {
    Object value;
}
// With a bound: T erases to the bound
class NumberBox<T extends Number> {
    T value;
}

// Conceptually at runtime:
class NumberBox {
    Number value;
}

  • An unbounded type parameter such as T erases to Object.

  • A bounded type parameter such as T extends Number erases to Number.

Restrictions from Erasure

class Holder<T> {
    // T value = new T();          // No runtime class or constructor guarantee.
    // T[] items = new T[10];      // Generic array creation.
    // static T shared;            // T is unavailable in a static context.
}

// if (obj instanceof List<String>) { }   // Not reifiable.
if (obj instanceof List<?> list) { }      // Allowed.

// void f(List<String> s) { }
// void f(List<Integer> i) { }            // Same erasure: name clash.

  • At runtime, Java does not know the exact type argument for T.

  • List<String> is not reifiable, so Java cannot test it with instanceof.

  • Overloads that differ only by generic type arguments erase to the same method signature.

  • Class type parameters cannot be used in static members.

Unchecked Warnings and Heap Pollution

List<String> names = new ArrayList<>();

List raw = names;              // Raw alias to the same list.

raw.add(123);                  // Unchecked warning, but it compiles.

String first = names.get(0);   // ClassCastException here.

  • Heap pollution: a parameterized variable refers to data that does not match its declared type.

  • Unchecked warning: the compiler cannot fully verify type safety.

  • @SuppressWarnings("unchecked") hides the warning only when you have manually verified safety.

  • Run: RawVsGeneric.java

Erasure and Raw Types

List<String> names = new ArrayList<>();
List raw = names;

System.out.println(names.getClass() == raw.getClass());   // true

System.out.println(new ArrayList<String>().getClass()
        == new ArrayList<Integer>().getClass());          // true

  • All type arguments use one runtime ArrayList class.

  • Erasure supports calls to pre-generics code.

Rule: raw types are a migration tool. Use parameterized types in new code.

  • Run: TypeErasureDemo.java

Keeping a Type at Runtime: Class<T>

Generic type T is mostly erased at runtime. If a method needs the actual class, we can pass it explicitly.

static <T> T cast(Object value, Class<T> type) {
    return type.cast(value);
}

String name = cast("Alice", String.class);

  • String.class is an object that represents the String class at runtime.

  • Its type is Class<String>.

  • Passing String.class tells the method that T is String.

Important: List.class tells us only that something is a List. It does not preserve String from List<String>.

  • Run: TypeErasureDemo.java

Summary

Key Takeaways

  • Parameterized generic types are invariant.

  • List<String> is not a List<Object>.

  • Arrays are covariant and reified; parameterized generic types are invariant and erased.

  • Bounds tell the compiler which operations are safe on a type parameter.

  • Producer Extends, Consumer Super. Wildcards describe how a parameter is used.

  • Erasure rules out new T() and new T[].

  • It also rules out instanceof List<String>.

  • Class type parameters are unavailable in static members.

  • An unchecked warning means heap pollution is possible. Raw types exist for migration only.
