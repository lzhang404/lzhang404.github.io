Streams Using Strings

One Idea: Read Text From Different Sources

A stream is a flow of data that a program can read from or write to.

SourceCommon objectExample
KeyboardScannernew Scanner(System.in)
StringScannernew Scanner(reviewLine)
FileScannernew Scanner(fileStream)

  • The parsing methods are familiar: next(), nextInt(), nextLine().

  • The main change is the source of the input.

String Input Stream: Parse One Review Line

import java.util.Scanner;

public class ReviewLineParser {
    public static void main(String[] args) {
        String reviewLine = "Campus Cafe 5 friendly-service";

        Scanner lineScanner = new Scanner(reviewLine); // Scanner reads from a String
        String restaurantName = lineScanner.next();
        String restaurantType = lineScanner.next();
        int rating = lineScanner.nextInt();
        String comment = lineScanner.next();

        System.out.println("Restaurant: " + restaurantName + " " + restaurantType);
        System.out.println("Rating: " + rating);
        System.out.println("Comment: " + comment);

        lineScanner.close();
    }
}

  • example: ReviewLineParser.java

StringWriter and PrintWriter

Sometimes we want to build text first, then use that text later. These two classes work together for that job.

  • StringWriter: a character output stream that stores the output in a String in memory.

  • PrintWriter: a writer that gives us familiar methods such as print(), println(), and printf().

  • We often connect them like this: PrintWriter reportWriter = new PrintWriter(reportStream);

  • This is useful when we want to build a formatted report before printing it or saving it.

StringWriter reportStream = new StringWriter();
PrintWriter reportWriter = new PrintWriter(reportStream);

Example: Build a Report in Memory

This example writes formatted output into a string stream, then prints the finished report.

import java.io.PrintWriter;
import java.io.StringWriter;

public class ReviewStringReport {
    public static void main(String[] args) {
        String restaurantName = "Campus Cafe";
        int reviewCount = 3;
        double averageRating = 4.3333;

        StringWriter reportStream = new StringWriter();
        PrintWriter reportWriter = new PrintWriter(reportStream);

        reportWriter.println("Restaurant Review Summary");
        reportWriter.println("Restaurant: " + restaurantName);
        reportWriter.printf("Average rating: %.2f%n", averageRating);
        reportWriter.println("Number of reviews: " + reviewCount);

        reportWriter.close();
        String reportText = reportStream.toString();
        System.out.print(reportText);
    }
}

  • example: ReviewStringReport.java

File Input

Opening a Text File for Reading

File input uses the same scanner idea, but the scanner reads from a file stream.

FileInputStream fileStream = new FileInputStream("restaurant_reviews.txt");
Scanner fileScanner = new Scanner(fileStream);

// read from fileScanner

fileScanner.close();
fileStream.close();

  • FileInputStream opens the file.

  • Scanner converts the file bytes into tokens or lines.

  • The file must exist in the program's working directory.

Example: Print All Review Lines From a File

import java.io.FileInputStream;
import java.io.IOException;
import java.util.Scanner;

public class ReviewFileReader {
    public static void main(String[] args) throws IOException {
        FileInputStream fileStream = new FileInputStream("restaurant_reviews.txt");
        Scanner fileScanner = new Scanner(fileStream);

        while (fileScanner.hasNextLine()) { // read until no lines remain
            String reviewLine = fileScanner.nextLine();
            System.out.println(reviewLine);
        }

        fileScanner.close();
        fileStream.close();
    }
}

  • example: ReviewFileReader.java

Reading Until the End of the File

Files often contain an unknown number of rows.

MethodUse when
hasNextLine()Each row should be processed as a full line.
hasNext()The file is read token by token.
hasNextInt()The next token must be an integer before reading.
 
while (fileScanner.hasNextLine()) {
    String line = fileScanner.nextLine();
    // process one line
}

  • The condition is checked before each read.

Example: Compute Average Rating From a File

This example reads one review line at a time and keeps a running total.

while (fileScanner.hasNextLine()) {
    String line = fileScanner.nextLine();
    Scanner lineScanner = new Scanner(line); // parse one review line

    lineScanner.next(); // restaurant first word
    lineScanner.next(); // restaurant second word
    int rating = lineScanner.nextInt();

    ratingSum += rating;
    reviewCount += 1;
    lineScanner.close();
}

double average = (double) ratingSum / reviewCount;

Closing Files Safely

File resources should not be left open after the program is done with them.

  • Close output first if the output writer depends on an output stream.

  • Closing a writer flushes remaining text into the file.

  • Closing becomes harder when an exception happens before the normal end of the program.

ApproachBeginner meaning
close()You close the resource manually.
try-with-resourcesJava closes the resource automatically after the block.

Try-With-Resources

A try-with-resources statement opens resources in parentheses after try.

try (Scanner inputScanner = new Scanner(new FileInputStream("restaurant_reviews.txt"));
     PrintWriter outputWriter = new PrintWriter(new FileOutputStream("review_summary.txt"))) {

    // read from inputScanner
    // write to outputWriter
}
catch (IOException excpt) {
    System.out.println("File problem: " + excpt.getMessage());
}

  • The scanner and writer close automatically after the try block.

  • This is usually cleaner than manually closing file resources.

Example: Try-With-Resources Summary

This example uses try-with-resources so the input and output resources close automatically.

try (Scanner inputScanner = new Scanner(new FileInputStream("restaurant_reviews.txt"));
     PrintWriter outputWriter = new PrintWriter(new FileOutputStream("review_summary.txt"))) {

    while (inputScanner.hasNextLine()) {
        Scanner lineScanner = new Scanner(inputScanner.nextLine());
        lineScanner.next();
        lineScanner.next();
        int rating = lineScanner.nextInt();
        // update total and count
        lineScanner.close();
    }

    outputWriter.printf("Average rating: %.2f%n", average);
}
catch (IOException excpt) {
    System.out.println("File problem: " + excpt.getMessage());
}

  • example: ReviewTryWithResources.java

Handling Exceptions

What an Exception Means

An exception is a runtime problem. The program compiled, started running, and then hit a situation it could not handle normally.

  • Normal path: the statement works, and the program continues to the next statement.

  • Exception path: the statement fails, Java creates an exception object, and normal execution stops at that point.

  • Java then looks for a matching catch block.

  • The catch block decides what to do next: print a message, ask again, skip bad data, or stop cleanly.

int rating = scnr.nextInt();
// If input is 5: continue normally
// If input is five: throw InputMismatchException

try and catch Blocks

This example shows the full pattern: catch bad input, remove it, and ask again.

while (!ratingAccepted) {
    try {
        System.out.print("Enter rating 1-5: ");
        rating = scnr.nextInt();
        ratingAccepted = true;
    }
    catch (InputMismatchException excpt) {
        System.out.println("Please enter a whole number.");
        scnr.next(); // remove the bad token before trying again
    }
}

  • The try block contains the read that may fail.

  • If the read succeeds, ratingAccepted becomes true, and the loop can stop.

  • If the read throws InputMismatchException, the matching catch block runs.

  • scnr.next() removes the bad token before the next attempt.

  • example: RatingInputRetry.java

Common Exception Types

Different problems create different exception types.

ExceptionCommon cause
FileNotFoundExceptionA file cannot be opened.
IOExceptionA file or stream operation fails.
InputMismatchExceptionA scanner read expects one type but sees another.
NumberFormatExceptionA string cannot be converted to a number.
ArithmeticExceptionAn arithmetic operation fails, such as integer division by zero.

  • The catch type should match the problem you are prepared to handle.

Handling Invalid Text While Reading

A common exception in file processing happens when text should be a number but is not numeric.

String ratingText = "excellent";
int rating = Integer.parseInt(ratingText); // NumberFormatException

  • "5" can be converted to an integer.

  • "excellent" cannot be converted to an integer.

  • When one row is bad, the program can skip that row and continue processing the rest.

Example: Skip Invalid Rating Text

public class NumberFormatReport {
    public static void main(String[] args) {
        String[] ratingTexts = {"5", "4", "excellent", "3"};
        int ratingSum = 0;
        int reviewCount = 0;

        for (String ratingText : ratingTexts) {
            try {
                int rating = Integer.parseInt(ratingText); // may throw NumberFormatException
                ratingSum += rating;
                reviewCount += 1;
            }
            catch (NumberFormatException excpt) {
                System.out.println("Skipping invalid rating: " + ratingText);
            }
        }

        System.out.printf("Average rating: %.2f%n", (double) ratingSum / reviewCount);
    }
}

  • This example skips one bad rating value and keeps processing the remaining values.

Throwing Exceptions

What throw Does

throw is how a program creates an exception on purpose.

  • Use it when the program detects a rule violation that Java cannot know by itself.

  • The exception object stores a message that explains the problem.

  • After throw runs, the current normal path stops.

  • Java looks for a matching catch block in the current method or in the caller.

throw new Exception("clear problem message");

Example: Validate a Rating With throw

The program checks a course rating rule: the rating must be from 1 to 5.

import java.util.Scanner;

public class RatingValidatorThrow {
    public static void main(String[] args) {
        Scanner scnr = new Scanner(System.in);

        try {
            System.out.print("Enter rating 1-5: ");
            int rating = scnr.nextInt();

            if (rating < 1 || rating > 5) {
                throw new Exception("Rating must be between 1 and 5.");
            }

            System.out.println("Rating saved: " + rating);
        }
        catch (Exception excpt) {
            System.out.println(excpt.getMessage());
        }
    }
}

  • If the rating is valid, the success message prints.

  • If the rating is outside the range, throw creates an exception and the catch block prints the message.

  • example: RatingValidatorThrow.java

Example: Throw From a Method

The method checks the rating and passes the exception back to main().

public static int readRating(Scanner scnr) throws Exception {
    int rating = scnr.nextInt();

    if (rating < 1 || rating > 5) {
        throw new Exception("Rating must be between 1 and 5.");
    }

    return rating;
}

// in main:
try {
    int rating = readRating(scnr);
    System.out.println("Rating saved: " + rating);
}
catch (Exception excpt) {
    System.out.println(excpt.getMessage());
}

  • throw creates the exception inside readRating().

  • throws Exception tells the caller that this method may pass an exception back.

  • example: RatingValidatorMethodThrows.java

User-Defined Exception Type

Sometimes a program needs a clearer exception name for a specific problem in its own data.

class InvalidRatingException extends Exception {
    public InvalidRatingException(int rating) {
        super("Invalid rating: " + rating);
    }
}

  • The class extends Exception.

  • The constructor passes a clear message to the base Exception class.

  • The catch block can now catch exactly InvalidRatingException.

Example: Custom Invalid Rating Exception

The catch block handles the custom exception type directly.

try {
    System.out.print("Enter rating 1-5: ");
    int rating = readRating(scnr);
    System.out.println("Rating saved: " + rating);
}
catch (InvalidRatingException excpt) {
    System.out.println(excpt.getMessage());
}

Checked and Unchecked Exceptions

Java treats some exception types differently at compile time.

TypeBeginner meaningExample
CheckedJava requires the method to catch or declare it.IOException
UncheckedJava does not require catch or throws.InputMismatchException

  • File operations often involve checked exceptions.

  • Invalid keyboard input often creates unchecked exceptions.

import java.util.Scanner;
public class CheckedExample {
    public static void main(String[] args) {
        try {
            FileReader reader = new FileReader("data.txt");
            System.out.println("File opened successfully.");
            reader.close();
        } catch (IOException e) {
            System.out.println("Something went wrong with the file.");
        }
    }
}
//handle checked exception with throws 
public class CheckedExample {
    public static void main(String[] args) throws IOException {
        FileReader reader = new FileReader("data.txt");
        System.out.println("File opened successfully.");
        reader.close();
    }
}
//unchecked
public class UncheckedExample {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        System.out.print("Enter a number: ");
        int number = input.nextInt();//may throw InputMismatchException
        System.out.println("You entered: " + number);
    }
}

Catch Order: Specific Before General

When there are multiple catch blocks, Java checks them from top to bottom.

try {
    // code that may throw different exceptions
}
catch (NumberFormatException excpt) {
    System.out.println("Invalid number text.");
}
catch (Exception excpt) {
    System.out.println("Other problem: " + excpt.getMessage());
}

  • Put the more specific exception type first.

  • A general catch block such as Exception belongs later.

Summary

File I/O Problem-Solving Pattern

Most file problems in this chapter follow the same pattern.

  1. Open the input source.

  2. Loop while more data exists.

  3. Parse one line or token at a time.

  4. Validate values before using them.

  5. Update counters, totals, or output text.

  6. Write the result if needed.

  7. Close resources safely.

This pattern is the same whether the data is ratings, dates, food items, or movie rows.

Correct Patterns and Mistakes to Avoid

Most bugs in this chapter happen when the code reads, writes, or catches in the wrong order.

  • Check before reading: use hasNext... before reading an unknown amount of input.

  • Match the method to the data: use nextInt() only when the next token should be an integer.

  • Choose token or line input: next() reads one token; nextLine() reads the rest of the line.

  • Finish file output: close the writer or use try-with-resources.

  • Catch specific first: put specific catch blocks before general catch blocks.

  • Know who handles the exception: throws passes the problem to the caller; catch handles it.

Key Takeaways

  • A Scanner can read from the keyboard, a string, or a file stream.

  • A PrintWriter can write familiar output methods to a string or file.

  • File-reading loops should check whether more data exists before reading.

  • Exceptions are runtime problems that can change the normal flow of execution.

  • try and catch handle expected problems.

  • throw reports a problem; throws passes that possibility to the caller.

  • Try-with-resources is a clean way to close file resources automatically.
