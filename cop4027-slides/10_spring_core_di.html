The Spring Framework Ecosystem

Why Use Spring?

Layered applications contain objects with dependencies.

Controller → Model / Service → Repository → Database

  • Those objects must be created in the right order.

  • Each object needs the correct dependencies.

  • As projects grow, manual startup code becomes harder to maintain.

Spring helps manage that object creation and wiring.

What Is Spring?

  • Spring is a Java framework for building applications.

  • Spring Core creates and connects Java objects.

  • Spring Data supports database access and repositories.

  • Spring Web supports web applications and HTTP requests.

Spring Framework and Spring Boot

Spring Framework

  • Provides the Core container and the bean and injection model.

  • The other Spring modules build on this container.

Spring Boot

  • Starts a Spring application with less setup code.

  • Provides common defaults and configuration conventions used with Spring Data JPA and Spring Web.

Spring Core with Maven

<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-context</artifactId>
    <version>${spring.version}</version>
</dependency>

  • spring-context provides the application context.

  • Maven downloads the required Spring libraries.

Question: Who creates these objects and passes them to constructors?

What Is a Dependency?

A dependency is another object that a class needs to do its work.

public final class TaskModel {
    private final TaskRepository repository;
    ...
}

  • TaskModel needs a TaskRepository.

  • The Repository is a dependency of the Model.

Creating vs. Receiving a Dependency

Creating the dependency inside TaskModel:

public TaskModel() throws IOException {
    DatabaseConfig config = DatabaseConfig.load("/database.properties");
    repository = new JdbcTaskRepository(config);
}

Receiving the dependency from outside:

public TaskModel(TaskRepository repository) {
    this.repository = repository;
    reload();
}

  • The first version chooses JDBC inside the Model.

  • That Model cannot switch storage or be tested without a database.

  • The second version lets another part choose the Repository.

What Is Dependency Injection?

Dependency injection means giving an object its dependencies from outside instead of having the object create them itself.

  • The class declares what it needs.

  • Another part of the application creates the dependency.

  • That dependency is supplied to the class.

TaskModel does not need to decide whether its Repository uses JDBC, memory, JPA, or another storage system.

Injection Styles

  • Constructor injection: pass required dependencies during construction.

  • Setter injection: supply a dependency through a setter after construction.

  • Field injection: write directly to a field.

Constructor injection makes required dependencies explicit at object creation.

Why Constructor Injection?

  • The constructor shows every required dependency.

  • The object starts with complete state.

  • Dependency fields can remain final.

  • Tests can pass small replacement objects.

  • The class stays independent of Spring.

Example: spring-core/task/TaskModelTest.java

Constructor Injection in Plain Java

DatabaseConfig config = DatabaseConfig.load("/database.properties");
TaskRepository repository = new JdbcTaskRepository(config);

TaskModel model = new TaskModel(repository);
TaskView view = new TaskView();
TaskController controller = new TaskController(model, view);

  • Startup code chooses the implementations.

  • Constructors receive the dependencies.

Quick check: Is this dependency injection even though Spring is not used?

Answer: Yes. Startup code passes dependencies to constructors; Spring is not required.

Dependency Injection and Inversion of Control

  • Inversion of control: the object no longer controls how its dependencies are created.

  • Dependency injection is one way to apply inversion of control.

  • TaskModel gives up control of creating its Repository.

The Spring Core Container

What Spring Adds

Spring replaces manual startup wiring.

  • Creates objects and supplies their dependencies.

  • Reports missing or ambiguous dependencies at startup.

  • Application classes keep their ordinary constructors.

Spring Core Vocabulary

  • Bean: an object managed by Spring.

  • Container: creates and connects beans.

  • Application context: gives access to the container.

  • Configuration: describes which beans to create.

  • Injection: supplies one bean to another bean.

Annotations at Runtime

Spring combines annotation metadata with runtime reflection.

  • Annotations provide metadata.

  • Reflection lets code inspect classes and methods at runtime.

  • Spring uses reflection to read annotations during application startup.

@Configuration and @Bean

Spring reads two annotations to learn which beans to create.

@Configuration
public class AppConfig {
    @Bean
    TaskRepository taskRepository() {
        return new JdbcTaskRepository(...);
    }
}

  • @Configuration marks a class that defines beans.

  • @Bean marks a method that creates one bean.

  • The returned object is managed by Spring.

First Bean

A bean method is a factory: By default, Spring creates one shared instance of the bean and keeps it in the application context..

@Bean
TaskRepository taskRepository() throws IOException {
    DatabaseConfig config = DatabaseConfig.load("/database.properties");
    return new JdbcTaskRepository(config);
}

  • The returned JdbcTaskRepository becomes a bean.

  • Declaring the interface type lets other beans depend on TaskRepository, not on JDBC.

A Bean Depending on Another Bean

A bean method declares its dependencies as parameters, just like a constructor.

@Bean
TaskModel taskModel(TaskRepository repository) {
    return new TaskModel(repository);
}

  • Spring matches each parameter to a bean by type.

  • The method still calls the ordinary Java constructor.

Complete Task List Configuration

The four bean methods describe the same object graph as the plain Java startup code.

@Configuration
public class AppConfig {
    @Bean
    TaskRepository taskRepository() { return new JdbcTaskRepository(...); }
    @Bean
    TaskModel taskModel(TaskRepository repository) {
        return new TaskModel(repository);
    }
    @Bean
    TaskView taskView() { return new TaskView(); }
    @Bean
    TaskController taskController(TaskModel model, TaskView view) {
        return new TaskController(model, view);
    }
}

Example: spring-core/explicit/AppConfig.java

What Spring Does at Startup

  1. Reads the configuration class.

  2. Finds the @Bean methods.

  3. Creates beans in a valid dependency order.

  4. Supplies method arguments from existing beans.

  5. Stores the created objects in the application context.

Starting the Explicit Task App

context = new AnnotationConfigApplicationContext(AppConfig.class);
TaskView view = context.getBean(TaskView.class);
TaskController controller = context.getBean(TaskController.class);
controller.connectHandlers();

stage.setScene(new Scene(view, 960, 600));
stage.show();

  • Spring creates and wires the beans; getBean retrieves them.

  • The Controller already holds this View and its Model.

  • The app calls connectHandlers() to display tasks and register button actions, then shows the View.

Example: spring-core/explicit/ExplicitTaskApp.java

Dependency Problems Spring Can Detect

Missing Dependency

Suppose the configuration has the taskModel bean method but no TaskRepository bean.

UnsatisfiedDependencyException: Error creating bean with name 'taskModel'
...
No qualifying bean of type '...TaskRepository' available:
expected at least 1 bean which qualifies as autowire candidate.

  • Spring cannot call the method without a TaskRepository.

  • The application fails during startup instead of failing later during a user action.

Multiple Implementations

When two beans have the same type, matching by type is ambiguous.

@Bean
TaskRepository jdbcRepository() { return new JdbcTaskRepository(...); }

@Bean
TaskRepository memoryRepository() { return new InMemoryTaskRepository(); }

  • The taskModel parameter now has two candidates, so startup fails.

  • Spring needs an explicit choice between the implementations.

Choosing Between Implementations

Spring can resolve the ambiguity with a default for all injection points or an exact choice for one.

@Bean
@Primary
TaskRepository jdbcRepository() { return new JdbcTaskRepository(...); }

@Bean
TaskModel taskModel(@Qualifier("memoryRepository")
                    TaskRepository repository) {
    return new TaskModel(repository);
}

  • @Primary: the preferred bean when multiple TaskRepository beans match.

  • @Qualifier: the exact bean for one parameter; it overrides the default.

Replacing the Repository

Constructor injection lets us change the data layer without changing the Model.

@Bean
TaskRepository taskRepository() {
    return new InMemoryTaskRepository();
}

  • The TaskModel constructor stays the same.

  • The Controller and View stay the same.

  • Only the configuration changes.

Example: spring-core/task/InMemoryTaskRepository.java

Component Scanning and Stereotypes

Explicit Bean Configuration

Explicit @Bean methods make the object graph directly visible.

  • Each method shows one object being created.

  • Each parameter shows one dependency.

Component scanning provides a shorter configuration style.

Component Scanning

Instead of a bean method for every class, Spring can scan a package and create the annotated classes as beans.

@Configuration
@ComponentScan("cop4027.springcore.task")
public class AppConfig {
    @Bean
    DatabaseConfig databaseConfig() throws IOException {
        return DatabaseConfig.load("/database.properties");
    }
}

  • Constructor parameters still describe dependencies.

  • DatabaseConfig has no component annotation, so a @Bean method supplies it.

Example: spring-core/scanned/AppConfig.java

Stereotype Annotations

  • @Component: general Spring-managed class.

  • @Service: application or business logic class.

  • @Repository: persistence or data-access class.

  • @Controller: web MVC controller.

  • @RestController: REST controller.

The annotations describe the role of the class.

Scanned Service and Repository

With scanning, the annotation goes on the class itself, and Spring calls its constructor.

@Repository
public final class JdbcTaskRepository implements TaskRepository {
    ...
}

@Service
public final class TaskModel {
    public TaskModel(TaskRepository repository) { ... }
}

  • Spring passes the JdbcTaskRepository bean to the TaskModel constructor.

  • Apart from the annotations, these classes are the same as in the plain Java version.

Run: spring-core/scanned/ScannedTaskApp.java

Explicit Beans vs. Component Scanning

  • Explicit @Bean: useful when construction needs custom code or explicit control.

  • Component scanning: good when many application classes follow standard patterns.

  • Both styles create Spring-managed beans.

Spring with JavaFX

A desktop JavaFX app can still use Spring for object wiring.

  • JavaFX still owns the window, scene, and UI thread.

  • Spring can create Models, Repositories, Services, and Controllers.

Read the Bean Definition

@Bean
TaskController taskController(TaskModel model, TaskView view) {
    return new TaskController(model, view);
}

  1. Which object becomes a bean?

  2. Which objects are its dependencies?

  3. Who supplies the method arguments?

  4. Who calls the constructor?

Bean Definition: Solution

  • The returned TaskController becomes a bean.

  • TaskModel and TaskView are its dependencies.

  • Spring supplies both method arguments.

  • The bean method calls the constructor.

Key Takeaways

  • Spring is a Java framework; Spring Core manages object creation and wiring.

  • A dependency is an object another object needs.

  • Constructor injection supplies required dependencies from outside.

  • A Spring-managed object is a bean.

  • The container creates beans and injects their dependencies.

  • @Configuration, @Bean, and component scanning define the object graph.

  • The three-tier responsibilities stay the same.
