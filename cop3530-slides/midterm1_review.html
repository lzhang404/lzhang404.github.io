Core Concepts

Algorithm

  • An algorithm is a step-by-step process to solve a problem.

  • We judge algorithms by correctness + efficiency (time/space).

Example

  • Find the maximum number in an array.

Data Structure

  • A way to store and organize data in memory.

  • Choice of structure affects performance and code complexity.

Examples

  • Array, Linked List, Stack, Queue

Abstract Data Type (ADT)

  • A logical description of a data type + the operations you can do.

  • ADT focuses on what operations exist, not how implemented.

  • Stack ADT: push, pop, peek

  • Queue ADT: enqueue, dequeue

Compilation

Compiler command (g++)

  • Typical command starts with g++

  • -o names the output executable

  • -c compiles only (no linking)

g++ main.cpp -o main
g++ -c point.cpp   # produces point.o (no linking)

3 stages of compilation

  • Preprocessing: handle directives (#include, #define)

  • Compilation: compile .cpp into .o object file

  • Linking: combine .o files into an executable

Modular Compilation

Header files (.hpp)

  • Public declarations: classes, function prototypes

  • May include inline methods

  • Can include other headers

  • Must have a header guard

#ifndef FILE_HPP
#define FILE_HPP

// declarations here

#endif

Implementation files (.cpp)

  • Function definitions / implementations

  • Include its own header + other headers it uses

Preprocessor directives

  • #include "filename.hpp": local file

  • #include <system_library>: system header

  • Header guards prevent multiple-include issues

Multi-file compilation: common pattern

  • Module = .hpp/.cpp pair (often one per class)

  • Driver file (main.cpp, test.cpp) contains main()

  • Driver files do not have a matching .hpp

Make & Makefile

Why use make?

  • Automates compilation steps

  • Only rebuilds what changed (saves time)

Makefile syntax

Example

    g++ -o main main.o lib1.o

  • make builds first target

  • make targetName builds specific target

  • Often includes clean target

Memory Management in C++

Memory regions

  • Static: globals, constants

  • Code: program instructions

  • Stack: local variables, function calls (stack frames)

  • Heap: dynamic allocation (new/delete)

Pointers

  • A pointer stores a memory address.

  • & gets the address, * dereferences (reads/writes the pointed-to value).

  • Use nullptr when a pointer points to nothing.

int *p;        // pointer to int
int x = 10;
p = &x;        // p stores address of x
std::cout << *p; // dereference → prints 10

Dynamic allocation (new / delete)

  • Allocate single object vs array differently

  • Deallocate with matching form: delete vs delete[]

  • Memory leak happens when new has no matching delete

int *p = new int;
int *arr = new int[10];
MyClass *obj = new MyClass();

delete p;
delete[] arr;
delete obj;

Memory inside a class

  • If your class owns heap memory, the default copy is usually a shallow copy.

  • Shallow copy can cause double-delete bugs and shared-pointer bugs.

  • That’s why we implement the Big Three (Rule of Three):

  • Destructor, Copy Constructor, Copy Assignment Operator

Rule of Three

Destructor

  • Frees allocated memory

  • Prevents memory leaks

class List {
  int size;
  int *arr;
public:
  List() { size = 0; arr = nullptr; }

  List(int count) {
    this->size = count;
    arr = new int[count];
  }

  List(int count, int value = 0) {
    this->size = count;
    arr = new int[count];
    for (int i = 0; i < count; ++i) arr[i] = value;
  }

  ~List() {
    delete[] arr;
  }
};

Copy constructor (deep copy)

  • Goal: two objects do not share the same dynamic array pointer

  • Allocate new memory and copy values over

List(const List& other) {
  size = other.size;
  arr = new int[size];
  for (int i = 0; i < size; ++i) {
    arr[i] = other.arr[i];
  }
}

Copy assignment operator (deep copy, self-safe)

  • Handle self-assignment

  • Free existing memory, then allocate and copy

  • Return *this by reference

List& operator=(const List& other) {
  if (this == &other) return *this;

  size = other.size;
  delete[] arr;

  arr = new int[size];
  for (int i = 0; i < size; ++i) {
    arr[i] = other.arr[i];
  }

  std::cout << "Copy Assignment called\n";
  return *this;
}

Rule of Three: triggered by usage

List list(5, 10);     // constructor (count, value)
List list2(list);     // copy constructor
List list3;           // default constructor
list3 = list;         // copy assignment operator

Reference Type

References (C++)

  • A reference is an alias for another variable (stores address implicitly).

  • Must be bound when created; cannot be nullptr.

  • Cannot be re-bound to a different variable later.

  • Accessed like the original variable (no * needed).

  • Common use: function parameters/returns to avoid copies.

Algorithm Analysis

Why analyze?

  • Compare efficiency of algorithms

  • Focus on time T(N) and space S(N)

Complexity cases

  • Best case: fastest input

  • Worst case: slowest input (most important)

  • Average case: expected behavior

Growth bounds

  • Big-O (O): upper bound (commonly used)

  • Big-Omega (Ω): lower bound

  • Big-Theta (Θ): tight / exact growth bound

Big-O analysis: simplification rules

  • Treat each statement/expression as constant time

  • Keep only dominant term

  • Addition vs multiplication matters

3n^2 + 5n + 10  = Θ(n^2)
Θ(n) + Θ(log n) = Θ(n)
Θ(n) × Θ(log n) = Θ(n log n)

Common examples

  • Linear search: O(n)

  • Binary search: O(log n)

  • Merge sort: O(n log n)

  • Bubble sort: O(n^2)

Recursion

Function calls & stack frames

  • Each function call creates a stack frame in memory.

  • Stack frame stores local variables + parameters + return address.

  • Too many calls → possible stack overflow.

Recursive functions

  • A function calls itself (directly or indirectly).

  • Can replace loops in some cases.

  • Must have:

  • Base case (stopping point)

  • Recursive case (smaller problem)

  • Sometimes multiple base/recursive cases or helper functions.

Typical recursion examples

  • Factorial

  • Fibonacci

  • Binary search

  • Merge sort

Complexity of recursion (what to ask)

  • How many recursive calls?

  • How does problem size shrink each call?

  • What’s the work per call?

  • What’s the extra stack space used?

  • Use recursion tree intuition when helpful.
