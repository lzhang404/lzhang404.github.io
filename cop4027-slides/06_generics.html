Refresher

Raw vs Parameterized

List raw = new ArrayList();
raw.add(new BankAccount());
raw.add("my savings");                     // Allowed.

BankAccount b = (BankAccount) raw.get(1);  // ClassCastException.

List<BankAccount> accounts = new ArrayList<>();
accounts.add("my savings");                // Compile-time error.

BankAccount a = accounts.get(0);           // No cast needed.

  • The raw type allows the mistake.

  • The cast fails later.

Generic Class and Generic Method

public class Pair<T, U> {           // Declared after the class name.
    private final T first;
    private final U second;

    public Pair(T first, U second) {
        this.first = first;
        this.second = second;
    }

    public T getFirst()  { return first; }
    public U getSecond() { return second; }
}

public static <T> void printAll(T[] values) {   // Declared before the
    for (T value : values) {                    // return type.
        System.out.println(value);
    }
}

  • A class type is fixed when the object is created.

  • A method type is inferred at each call.

Variance

Invariance of Generic Types

List<String> names = new ArrayList<>();

List<Object> objs = names;   // Compile-time error.

// If Java allowed the line above:
objs.add(42);                // Looks fine: Integer is an Object.
String first = names.get(0); // But this would return an Integer.

  • String is a subtype of Object.

  • List<String> is not a subtype of List<Object>.

  • This restriction is invariance.

  • Wildcards provide controlled flexibility.

  • Example: VarianceDemo.java

Arrays vs Generics

// Arrays: covariant, checked when the program runs.
Object[] arr = new String[2];
arr[0] = 42;                                 // ArrayStoreException.

// Generics: invariant, checked when the program compiles.
List<Object> list = new ArrayList<String>(); // Rejected by javac.
Arrays Generics
Subtyping Covariant Invariant
Element type at runtime Kept Erased
Wrong type detected At runtime At compile time

  • Arrays keep the element type and check at runtime.

  • Generics erase type arguments and check at compile time.

  • Example: VarianceDemo.java

Bounds and Wildcards

Type Bounds

public class Box<T extends Number> {
    private final T value;

    public Box(T value) { this.value = value; }

    public double asDouble() {
        return value.doubleValue();   // Safe because of the bound.
    }
}

Box<Integer> count = new Box<>(10);
Box<Double> price  = new Box<>(12.5);

// Box<String> name = new Box<>("Alice");   // Rejected.

  • Without the bound, T is only an Object.

  • Object has no doubleValue() method.

  • Example: Box.java

Self-Bounded Types

public static <T extends Comparable<T>> T max(List<T> items) {
    T best = items.get(0);
    for (T item : items) {
        if (item.compareTo(best) > 0) {
            best = item;
        }
    }
    return best;
}

  • T extends Comparable<T> reads as: T can be compared to other T values.

  • The bound is what makes compareTo available inside the method.

  • The JDK uses Comparable<? super T>.

  • Compare it with the wildcard slides next.

  • Example: GenericMethodDemo.java

Producer: ? extends T

public static double sum(List<? extends Number> numbers) {
    double total = 0;
    for (Number n : numbers) {   // Reading out as Number is safe.
        total += n.doubleValue();
    }
    return total;
}

sum(List.of(1, 2, 3));      // List<Integer>
sum(List.of(1.5, 2.5));     // List<Double>

// numbers.add(1);          // Rejected.

  • The list might be a List<Double>.

  • Reading as Number is safe.

  • Adding a non-null Number is unsafe.

  • Example: WildcardsDemo.java

Consumer: ? super T

public static void addIntegers(List<? super Integer> target) {
    target.add(1);
    target.add(2);              // Writing an Integer is safe.

    Object o = target.get(0);   // Reads come back only as Object.
}

addIntegers(new ArrayList<Integer>());
addIntegers(new ArrayList<Number>());
addIntegers(new ArrayList<Object>());

  • The element type is Integer or a supertype.

  • Adding an Integer is safe.

  • Reading yields only Object.

  • Example: WildcardsDemo.java

The PECS Rule

The parameter is Use You can
Read from only List<? extends T> Read as T
Write to only List<? super T> Write a T
Read and write List<T> Read and write 
public static <T> void copy(List<? super T> dest,
                            List<? extends T> src)

  • src produces values: use extends.

  • dest consumes values: use super.

  • Wildcards describe data flow.

  • Example: WildcardsDemo.java

Exercise: Wildcards

// 1. Print every element.
static <T> void printAll(List<___> items)

// 2. Add all given elements into a target list.
static <T> void addAll(List<___> target, T[] values)

// 3. Run an action on every element.
static <T> void forEach(List<___> items, Consumer<___> action)

  • Does the method read from this parameter?

  • Does the method write to it?

Exercise: Answers

static <T> void printAll(List<? extends T> items)

static <T> void addAll(List<? super T> target, T[] values)

static <T> void forEach(List<? extends T> items,
                        Consumer<? super T> action)

  • 1. The list is only read from, so it is a producer.

  • 2. The list is only written to, so it is a consumer.

  • 3. The list produces values; the Consumer receives them.

  • Iterable.forEach uses Consumer<? super T>.

  • Stream.forEach uses the same pattern.

Type Erasure

Erasure of Type Variables

The compiler checks type arguments, then generates executable code using erased types.

class Box<T> {                  class Box {
    T value;          --->          Object value;
}                               }

class Box<T extends Number> {   class Box {
    T value;          --->          Number value;
}                               }

  • An unbounded type variable erases to Object.

  • A bounded type variable erases to its bound.

  • The compiler inserts the casts your source code no longer has to write.

Restrictions from Erasure

class Holder<T> {
    // T value = new T();          // No runtime class or constructor guarantee.
    // T[] items = new T[10];      // Generic array creation.
    // static T shared;            // T is unavailable in a static context.
}

// if (obj instanceof List<String>) { }   // Not reifiable.
if (obj instanceof List<?> list) { }      // Allowed.

// void f(List<String> s) { }
// void f(List<Integer> i) { }            // Same erasure: name clash.

  • No runtime T or constructor guarantee: no new T().

  • No reified component type: no new T[].

  • Erasure removes the List<String> runtime test.

  • Erased overloads have the same signature.

  • static T fails for a different reason.

  • Class type parameters are unavailable in a static context.

  • Example: ErasureLimits.java

Unchecked Warnings and Heap Pollution

List<String> names = new ArrayList<>();

List raw = names;

raw.add(123);                  // Unchecked warning, but it compiles.

String first = names.get(0);   // ClassCastException here.

  • names is declared as List<String>.

  • The raw alias inserts an Integer.

  • This mismatch is heap pollution.

  • The failure appears at the read, far from the line that caused it.

  • An unchecked warning signals a type-safety risk.

  • @SuppressWarnings("unchecked") hides the warning.

  • It does not remove the risk.

  • Example: RawVsGeneric.java

Erasure and Raw Types

List<String> names = new ArrayList<>();
List raw = names;

System.out.println(names.getClass() == raw.getClass());   // true

System.out.println(new ArrayList<String>().getClass()
        == new ArrayList<Integer>().getClass());          // true

  • All type arguments use one runtime ArrayList class.

  • Erasure supports calls to pre-generics code.

Rule: raw types are a migration tool. Use parameterized types in new code.

  • Example: TypeErasureDemo.java

Type Tokens: Class<T>

Class<?> unknown = String.class;       // Some class, type unspecified.
Class<String> known = String.class;    // Known to describe String.

static <T> T cast(Object value, Class<T> type) {
    return type.cast(value);
}

String name = cast("Alice", String.class);   // T = String.

  • Class<T> supplies one runtime class.

  • It does not restore String in List<String>.

  • Reflection, Spring, and JSON APIs use this pattern.

  • Example: TypeErasureDemo.java

Summary

Key Takeaways

  • Generic types are invariant.

  • List<String> is not a List<Object>.

  • Arrays are covariant and reified; generics are invariant and erased.

  • Bounds tell the compiler which operations are safe on a type parameter.

  • Producer Extends, Consumer Super. Wildcards describe how a parameter is used.

  • Erasure rules out new T() and new T[].

  • It also rules out instanceof List<String>.

  • Class type parameters are unavailable in static members.

  • An unchecked warning means heap pollution is possible. Raw types exist for migration only.

Exit Check

  • Collections.sort accepts a Comparator<? super T>. Why super rather than extends?

  • new T[10] is rejected, but (T[]) new Object[10] compiles with a warning. What changed?

Both questions are about something the compiler knows and the runtime does not.

Exit Check: Answers

  • The comparator only consumes T.

  • A Comparator<Object> can compare strings.

  • It can sort a List<String>.

  • Using extends would reject it.

  • The array cast is still unchecked.

  • The array is still an Object[].

  • A later use may throw ClassCastException.

  • In both cases, the runtime type argument is gone.
