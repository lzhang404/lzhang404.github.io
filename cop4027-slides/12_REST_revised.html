HTTP Requests and Responses

Same Service, New Input

An HTTP request is another way to call the Task List Service.

JavaFX Controller → TaskModel → TaskService → Repository → H2
HTTP request → Web Controller → TaskService → Repository → H2

  • The entity and Repository are reused.

  • The Service gains lookup and filtering operations; task rules and transactions stay there.

  • The web Controller translates HTTP messages into Service calls.

Clients and Servers

A client sends an HTTP request; a server returns an HTTP response.

client                         server
(browser or Java HttpClient)    (Spring application)
           ── request ──→
           ←── response ──

  • HTTP defines message semantics: methods, headers, and status codes.

  • The client and server can run on the same computer or different computers.

  • HTTPS protects HTTP communication with encryption.

https://www.rfc-editor.org/rfc/rfc9110.html

An HTTP Request

An HTTP/1.1 request carries a method, a target, headers, and an optional body.

POST /api/tasks HTTP/1.1
Host: localhost:8080
Content-Type: application/json
Content-Length: 24

{"title": "Review REST"}

  • The request line identifies the operation and resource.

  • Content-Type describes the request body; the blank line starts it.

  • The client library supplies framing headers such as Content-Length.

https://www.rfc-editor.org/rfc/rfc9110.html

An HTTP Response

A response says what happened and carries the result.

HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/tasks/4

{"id": 4, "title": "Review REST", "done": false}

  • Status line: a status code and a short reason.

  • Headers: details such as the body format and the new task's URL.

  • Body: the result, here the created task.

Content-Type and Accept

These headers describe different directions of the exchange.

HeaderMeaning

Content-Type: application/json

The body in this message is JSON.

Accept: application/json

The client can process a JSON response.

  • A POST with a JSON body sets Content-Type.

  • A GET without a body can still send Accept.

  • The response has its own Content-Type.

https://www.rfc-editor.org/rfc/rfc9110.html

Designing a REST API

REST Resources and Representations

REST is an architectural style for client-server interactions around resources.

  • A resource is identified by a URI, such as /api/tasks/4.

  • Clients exchange representations of resources, such as JSON or HTML.

  • A uniform interface uses consistent operations and self-descriptive messages.

  • REST also constrains caching, system layers, and links that guide client actions.

https://ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm

Stateless Requests and Persistent Data

Stateless communication does not mean the server has no database.

PATCH /api/tasks/4
Content-Type: application/json

{"done": true}

  • The request identifies the task and the requested change.

  • The server need not remember which task this client previously selected.

  • Task rows still persist in the database between requests.

https://ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm

URLs Name Things; Methods Name Actions

Use resource names in URLs and HTTP methods for operations.

AvoidPrefer

POST /api/createTask

POST /api/tasks

GET /api/getTask?id=4

GET /api/tasks/4

POST /api/deleteTask?id=4

DELETE /api/tasks/4

Collections use plural nouns: /api/tasks is all tasks; /api/tasks/4 is one.

JSON Represents a Resource

The server sends a representation of the task: its data as JSON, not the Java object itself.

{
  "id": 4,
  "title": "Review REST",
  "done": false
}

  • Spring uses Jackson message converters to read and write JSON.

  • Our response record exposes the keys id, title, and done.

Spring Web MVC

Spring Web Dependencies

The web starter adds Spring MVC, JSON conversion, and an embedded HTTP server.

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

  • The default servlet server is embedded Tomcat.

  • The JPA starter and H2 keep the existing persistence layer.

  • The validation starter checks request constraints.

Example: web/pom.xml

https://docs.spring.io/spring-boot/3.3/reference/web/servlet.html

Start the Web Application

Boot creates the beans and starts the server; the application stays running to accept requests.

@SpringBootApplication
public class WebApp {
    public static void main(String[] args) {
        SpringApplication.run(WebApp.class, args);
    }
}

  • This project listens on localhost:8080.

  • The desktop setting web-application-type=none is absent.

  • The web project has its own H2 file database.

Example: web/WebApp.java

How a Request Reaches a Method

Spring MVC routes requests through its front Controller, DispatcherServlet.

HTTP request → Tomcat → DispatcherServlet
  → handler mapping selects method + URL
  → request arguments → Controller → Service
  → return value → message converter → HTTP response

  • Mapping annotations connect requests to Java methods.

  • For the REST endpoints, Jackson writes the response record as JSON.

https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-servlet.html

@Controller and @RestController

Both use Spring MVC routing. The return value is handled differently.

AnnotationReturn valueResult

@Controller

A String view name + Model attributes

A rendered HTML page

@RestController

A response object

A response body, here JSON

  • @RestController combines @Controller with @ResponseBody.

  • @Controller can also use @ResponseBody on individual methods.

https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-methods/responsebody.html

The Web Controller

The web controller is a new presentation-tier class. It uses the same TaskService as the desktop Task List.

@RestController
@RequestMapping("/api/tasks")
public class TaskApiController {
    private final TaskService service;

    public TaskApiController(TaskService service) {
        this.service = service;
    }
}

  • @RequestMapping sets the base URL for every method in the class.

  • The name differs from the JavaFX TaskController, so both can exist.

  • Spring injects the Service through the constructor, as before.

A Controller for an HTML View

The page Controller places saved tasks in a web Model and returns a view name.

@GetMapping("/tasks")
public String tasks(Model model) {
    model.addAttribute("tasks", service.findAllTaskItems());
    return "tasks"; // View name, not the response body
}

  • This method belongs to @Controller, not @RestController.

  • Spring's web Model contains attributes for rendering one response.

Example: web/TaskPageController.java

https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-methods/return-types.html

Response Records and Entities

A response record defines the public JSON shape independently of the entity mapping.

public record TaskItemResponse(
        Long id, String title, boolean done) {
    public static TaskItemResponse from(TaskItem item) {
        return new TaskItemResponse(
                item.getId(), item.getTitle(), item.isDone());
    }
}

  • A JPA entity has persistence requirements; a response record does not.

  • Adding an entity field need not add a public JSON field.

Example: web/TaskItemResponse.java

GET All Tasks

The Controller obtains task rows and returns response records. A list becomes a JSON array.

@GetMapping
public List<TaskItemResponse> findAll(
        @RequestParam(required = false) Boolean done) {
    List<TaskItem> items = (done == null)
            ? service.findAllTaskItems()
            : service.findTaskItemsByDone(done);
    return items.stream().map(TaskItemResponse::from).toList();
}

  • GET /api/tasks has no filter: done is null.

  • Spring writes JSON with status 200 OK.

Example: web/TaskApiController.java

Send a GET with Java HttpClient

A client constructs the request and reads the status, headers, and body of the response.

HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder(
        URI.create("http://localhost:8080/api/tasks"))
        .header("Accept", "application/json")
        .GET().build();
HttpResponse<String> response = client.send(
        request, HttpResponse.BodyHandlers.ofString());

  • send waits for the response.

  • The response body is text containing JSON; statusCode() reports the status.

Reading Request Data

Path Variables: One Task

Part of the URL can be a value. @PathVariable copies it into a method parameter.

@GetMapping("/{id}")
public TaskItemResponse findOne(@PathVariable Long id) {
    return TaskItemResponse.from(service.getTaskItem(id));
}

  • GET /api/tasks/4 calls findOne(4L).

  • Spring converts the text "4" to a Long.

  • A missing task produces 404 Not Found; an id that cannot be converted produces 400 Bad Request.

Query Parameters: Filter Tasks

Query parameters supply optional criteria, rather than naming one resource.

@RequestParam(required = false) Boolean done

// GET /api/tasks            → done is null
// GET /api/tasks?done=false → done is false

  • Boolean distinguishes an absent parameter from false.

  • The Service chooses all tasks or repository.findByDone(done).

  • A value such as ?done=maybe cannot be converted and produces 400.

Example: web/TaskApiController.java

Request Body: Create a Task

@RequestBody asks a message converter to read the JSON body into a request record.

public record CreateTaskRequest(
        @NotBlank @Size(max = 100) String title) { }

  • JSON key title maps to the record component.

  • The client supplies the title; the server supplies id and done.

  • @Valid applies these constraints before the Controller method runs.

Example: web/CreateTaskRequest.java

https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-methods/requestbody.html

201 Created and Location

ResponseEntity controls the status, headers, and response body.

@PostMapping
public ResponseEntity<TaskItemResponse> create(
        @Valid @RequestBody CreateTaskRequest request) {
    TaskItem saved = service.addTaskItem(request.title());
    URI location = URI.create("/api/tasks/" + saved.getId());
    return ResponseEntity.created(location)
            .body(TaskItemResponse.from(saved));
}

  • created(location) sets 201 and the Location header.

  • The client follows that URI instead of guessing an id.

Example: web/CreateTaskDemo.java

PATCH: Mark a Task Done

This API changes only the done field and returns 204 No Content.

@PatchMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void update(@PathVariable Long id,
        @Valid @RequestBody UpdateTaskRequest request) {
    service.setDone(id, request.done());
}

  • The request record is UpdateTaskRequest(@NotNull Boolean done).

  • {} is invalid; Boolean avoids silently defaulting to false.

  • The transactional Service updates the managed entity.

Example: web/UpdateTaskRequest.java

DELETE: Remove a Task

The resource id comes from the path. A successful delete has no response body.

@DeleteMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void delete(@PathVariable Long id) {
    service.deleteTaskItem(id);
}

  • The Controller translates the request; the Service owns the database operation.

  • The Service throws TaskNotFoundException when the id is absent.

Example: web/TaskService.java

Validation and Errors

Request Validation and Task Rules

Request constraints protect the HTTP boundary. Service checks protect every caller.

public record CreateTaskRequest(
        @NotBlank @Size(max = 100) String title) { }

// The Controller parameter activates validation:
@Valid @RequestBody CreateTaskRequest request

  • @NotBlank rejects null, empty, and whitespace-only titles.

  • @Size(max=100) limits the request title length.

  • The Service also checks the title before persistence.

https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-methods/requestbody.html

A Missing Resource

A specific domain exception distinguishes a missing task from an invalid title.

public class TaskNotFoundException extends RuntimeException {
    public TaskNotFoundException(Long id) {
        super("Task item " + id + " not found");
    }
}

  • The exception contains no HTTP annotations.

  • The web layer maps this meaning to status 404.

Example: web/TaskNotFoundException.java

Look Up a Task in the Service

The Service uses the Repository to find an id and defines the meaning of absence.

@Transactional(readOnly = true)
public TaskItem getTaskItem(Long id) {
    return repository.findById(id)
            .orElseThrow(() -> new TaskNotFoundException(id));
}

  • findById returns an Optional, not an HTTP response.

  • Read, update, and delete use the same missing-task exception.

Example: web/TaskService.java

Map a Domain Error to HTTP

@RestControllerAdvice handles exceptions across the web Controllers.

@RestControllerAdvice
public class ApiExceptionHandler {
    @ExceptionHandler(TaskNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ApiError notFound(TaskNotFoundException exception) {
        return new ApiError(404, exception.getMessage());
    }
}

  • The annotation chooses 404; the return record becomes JSON.

  • Controller methods do not need repeated try/catch blocks.

Example: web/ApiExceptionHandler.java

Map Invalid Input to HTTP

Bean Validation failures occur before the Controller body runs.

@ExceptionHandler(MethodArgumentNotValidException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public ApiError invalidBody() {
    return new ApiError(400, "Invalid task fields");
}

  • Invalid POST titles and missing PATCH done fields use this handler.

  • The advice also maps unreadable JSON and invalid path/query values to 400.

  • Unexpected failures remain server errors; they are not converted into client errors.

Example: web/ApiExceptionHandler.java

https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-methods/requestbody.html

The Error Response

Clients get a small, predictable JSON body for every handled error.

public record ApiError(int status, String message) { }
HTTP/1.1 404 Not Found
Content-Type: application/json

{"status": 404, "message": "Task item 42 not found"}

  • The status code is for programs; the message is for people.

  • The advice gives validation and binding failures the same two-field error shape.

Create, Read, Update, and Delete

Each response determines the next request in the Task List workflow.

GET  {Location}         → 200 + task JSON
PATCH {Location}        → 204, no body
GET /api/tasks?done=true → 200 + filtered array

Test an Invalid Request

A request with a blank title must return 400 and leave the database unchanged.

mvc.perform(post("/api/tasks")
        .contentType(MediaType.APPLICATION_JSON)
        .content("{\"title\":\"   \"}"))
        .andExpect(status().isBadRequest())
        .andExpect(jsonPath("$.status").value(400));
assertEquals(0, repository.count());

  • perform sends the request through Spring MVC.

  • andExpect checks the response contract.

  • The database assertion confirms that invalid input was not saved.

Summary

Common Mistakes

  • Using GET to request a task mutation.

  • Confusing Content-Type with Accept.

  • Returning entities without deciding the public JSON fields.

  • Forgetting @Valid on a constrained request body.

  • Using primitive boolean when an omitted PATCH field must be rejected.

  • Putting task rules in the Controller instead of the Service.

Key Takeaways

  • HTTP methods, headers, and status codes define the exchange.

  • Resource identifiers and representations support a consistent API.

  • Spring MVC binds request data and handles response conversion.

  • Request records validate input; response records define the JSON shape.

  • Both REST and HTML Controllers call the same Service.

  • MockMvc tests the request/response contract and committed database effects.
