The Big Idea

What Is Recursion?

A recursive method is a method that calls itself.

  • The method solves part of the problem.

  • Then it calls itself to solve a smaller part.

  • This continues until the problem becomes small enough to answer directly.

Original problem
Smaller problem
Even smaller problem
Smallest problem that can be answered directly

Recursion Needs a Stopping Point

A recursive method cannot call itself forever.

  • The base case is the condition that stops the recursion.

  • The recursive case is the part that calls the same method again.

  • Each recursive call should move closer to the base case.

if the problem is small enough:
    answer it now
else:
    solve a smaller version of the same problem

Base Case and Recursive Case

Most recursive methods have the same basic shape.

public static void recursiveMethod(int value) {
    if (value is small enough) {
        // base case
        // stop here
    }
    else {
        // recursive case
        recursiveMethod(smallerValue);
    }
}

  • The base case prevents endless recursion.

  • The recursive case keeps the method moving.

First Example: Countdown

Countdown Without Recursion

A loop is a familiar way to repeat a task.

for (int count = 3; count >= 1; count--) {
    System.out.println(count);
}
System.out.println("Go!");

  • The loop repeats while the count changes.

  • Recursion can also repeat, but it repeats through method calls.

Countdown With Recursion

The method prints, then calls itself with a smaller number.

public static void countDown(int count) {
    if (count <= 0) {
        System.out.println("Go!");
    }
    else {
        System.out.println(count);
        countDown(count - 1);
    }
}

Trace countDown(3):

countDown(3) prints 3
countDown(2) prints 2
countDown(1) prints 1
countDown(0) prints Go!

  • Base case: count <= 0

  • Recursive case: countDown(count - 1)

  • The value gets smaller each time.

example: CountDown.java

Recursive Calls Return Backward

  • Each method call must finish before the previous method call can finish.

  • countDown(3) calls countDown(2).

  • countDown(2) calls countDown(1).

  • countDown(1) calls countDown(0).

  • After the base case finishes, the calls return in reverse order.

Each active call has its own stack frame.

Returning Values

Recursive Methods Can Return Values

Some recursive methods print output. Other recursive methods calculate and return an answer.

  • A printing method may use void.

  • A calculation method returns a value such as int or double.

  • The recursive call can be part of the returned expression.

answer for n
= current part
+ answer for a smaller problem

Factorial Code and Trace

Factorial multiplies a number by all positive whole numbers below it.

public static int factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}

  • Base case: n <= 1

  • Recursive case: n * factorial(n - 1)

Trace factorial(4):

factorial(4)
= 4 * factorial(3)
= 4 * 3 * factorial(2)
= 4 * 3 * 2 * factorial(1)
= 4 * 3 * 2 * 1
= 24

The calls go down to the base case, then return values back.

example: FactorialCalculator.java

Fibonacci Numbers

Fibonacci numbers are another example where the definition is recursive.

  • F(0) = 0

  • F(1) = 1

  • F(n) = F(n - 1) + F(n - 2)

public static int fibonacci(int n) {
    if (n <= 0) {
        return 0;
    }
    if (n == 1) {
        return 1;
    }

    return fibonacci(n - 1) + fibonacci(n - 2);
}

Trace fibonacci(4):

fibonacci(4)
= fibonacci(3) + fibonacci(2)
= 2 + 1
= 3

  • This matches the definition.

  • This version is easy to read.

  • For larger values, it repeats work.

example: FibonacciNumbers.java

Using Parameters to Track Progress

Parameters Remember the Current State

Each recursive call can receive different parameter values.

  • In countdown, the parameter is count.

  • In factorial, the parameter is n.

  • In an array problem, the parameter may be the current index.

The parameter tells the method which smaller problem it is solving right now.

Sum an Array Recursively

This method adds values starting from one index to the end of the array.

public static int sumFrom(int[] values, int index) {
    if (index == values.length) {
        return 0;
    }

    return values[index] + sumFrom(values, index + 1);
}

  • Base case: the index has reached the end.

  • Recursive case: add the current value and sum the rest.

Trace with {4, 6, 2}:

sumFrom(values, 0)
= 4 + sumFrom(values, 1)
= 4 + 6 + sumFrom(values, 2)
= 4 + 6 + 2 + sumFrom(values, 3)
= 4 + 6 + 2 + 0
= 12

The index increases each time, so the method gets closer to stopping.

Common Recursion Mistakes

Mistake 1: Missing the Base Case

If there is no stopping condition, the method keeps calling itself.

public static void repeatForever(int value) {
    System.out.println(value);
    repeatForever(value + 1);
}

  • This method has no base case.

  • It does not know when to stop.

  • Java eventually throws StackOverflowError.

Mistake 2: Not Moving Toward the Base Case

A method may have a base case but still fail if the recursive call does not make progress.

public static void countDown(int count) {
    if (count <= 0) {
        System.out.println("Go!");
    }
    else {
        System.out.println(count);
        countDown(count);
    }
}

  • The base case is count <= 0.

  • The recursive call uses the same value again.

  • The method never gets closer to stopping.

Stack Overflow Means Too Many Active Calls

Every active method call uses memory on the call stack.

  • Recursive calls add more active calls.

  • If the recursion does not stop, the call stack fills up.

  • That causes StackOverflowError.

  • The fix is to correct the base case or the recursive step.

Debugging Recursion

Print the parameter values to see how the recursive calls are changing.

public static void countDown(int count) {
    System.out.println("count = " + count);

    if (count <= 0) {
        System.out.println("Go!");
    }
    else {
        countDown(count - 1);
    }
}

  • If the values move toward the base case, the recursion is making progress.

  • If the values repeat forever, check the recursive call.

When Should We Use Recursion?

Recursion Is Useful for Some Problems

Recursion is helpful when the problem naturally contains smaller versions of itself.

  • Counting down from a number.

  • Computing formulas such as factorial.

  • Working through nested structures.

  • Exploring choices one step at a time.

For this course, focus on recognizing the pattern and tracing short examples.

Sometimes a Loop Is Clearer

Many simple repetition problems can be solved with either a loop or recursion.

ProblemUsually Clearer Choice
Print numbers from 1 to 10Loop
Add all values in an arrayLoop or recursion
Factorial formulaLoop or recursion
Nested choicesRecursion

Choose the approach that makes the code easier to understand.

Recursion Checklist

Before writing a recursive method, ask these questions.

  • What is the smaller version of the problem?

  • What is the base case?

  • What value should be returned or printed at the base case?

  • How does each recursive call move closer to the base case?

  • What happens after the recursive call returns?

Summary

Key Takeaways

  • A recursive method calls itself.

  • The base case stops the recursion.

  • The recursive case calls the method with a smaller problem.

  • Each recursive call has its own parameter values.

  • Recursive calls return in reverse order.

  • A missing base case can cause StackOverflowError.

  • Recursion is useful when the problem naturally breaks into smaller versions of itself.

  • For simple counting, a loop may be easier to read.
