Templates in C++

Liting Zhang

University of West Florida

Roadmap

  • Why templates exist: same logic, many types

  • Function templates: replace the changing type with T

  • Instantiation: what the compiler does with T

  • Class templates: the same idea for classes

  • Common requirements and common errors

The Main Idea

  • Templates help when the logic stays the same but the type changes.

  • We replace the changing type with a placeholder such as T.

  • The compiler uses the template to create the concrete function or class it needs.

  • This happens at compile time.

Motivation

Problem: Same Logic, Many Types

Suppose we want a function that returns the minimum of three items.

  • For int: compare three integers

  • For char: compare three characters

  • For string: compare three strings

  • The algorithm is the same: keep the smallest value seen so far

Without Templates: Repeated Code

//int version
int TripleMinInt(int item1, int item2, int item3) {
  int minVal = item1;
  if (item2 < minVal) minVal = item2;
  if (item3 < minVal) minVal = item3;
  return minVal;
}
// char version
char TripleMinChar(char item1, char item2, char item3) {
  char minVal = item1;
  if (item2 < minVal) minVal = item2;
  if (item3 < minVal) minVal = item3;
  return minVal;
}

  • Only the type changes.

  • Copying the same logic makes maintenance harder.

What Actually Changes?

Compare the two versions.

  • Return type: int becomes char.

  • Parameter types: int becomes char.

  • Local variable type: int becomes char.

  • Algorithm: does not change.

Template idea: keep the algorithm, replace the changing type.

Template Solution: Replace the Type with T

template <typename T>
T TripleMin(T item1, T item2, T item3) {
  T minVal = item1;
  if (item2 < minVal) minVal = item2;
  if (item3 < minVal) minVal = item3;
  return minVal;
}

  • T is a placeholder for a type.

  • The algorithm is written once.

  • The compiler fills in a real type when the template is used.

Function Templates

Function Template Syntax

template <typename T>
T name(T p1, T p2) {
  // use T like a normal type
}

  • template <typename T> introduces the placeholder type T.

  • T can be used as a return type, parameter type, or local variable type.

  • Inside the function body, read T as “some type chosen later.”

Calling a Function Template

Most of the time, call it like a normal function.

int a = TripleMin(10, 5, 7);
char b = TripleMin('z', 'a', 'm');

std::string s1 = "cat", s2 = "apple", s3 = "zoo";
std::string c = TripleMin(s1, s2, s3);

  • The compiler looks at the function arguments.

  • Then it chooses a concrete type for T.

What Does the Compiler Do with T?

TripleMin(10, 5, 7);
Read argument types
→
Determine T = int
→
Create TripleMin<int>

This is the one key process to remember: determine the type, then instantiate a concrete version.

Instantiation: The Concrete Function

Instantiation means the compiler generates a real version for a specific type.

//template
template <typename T>
T TripleMin(T a, T b, T c) {
  T minVal = a;
  if (b < minVal) minVal = b;
  if (c < minVal) minVal = c;
  return minVal;
}
// approximate generated version
int TripleMin(int a, int b, int c) {
  int minVal = a;
  if (b < minVal) minVal = b;
  if (c < minVal) minVal = c;
  return minVal;
}

This is a compile-time process, not a runtime template engine.

Template Vocabulary

template <typename T>
T TripleMin(T a, T b, T c);

TripleMin<double>(3, 2.5, 1);

  • T: template parameter, the placeholder type.

  • double: template argument, the type used for T.

  • 3, 2.5, 1: ordinary function arguments.

Template Argument Deduction

When the type is not written explicitly, the compiler tries to infer it.

TripleMin(3, 2, 1);        // T is int
TripleMin(3.0, 2.0, 1.0);  // T is double
TripleMin('z', 'a', 'm');  // T is char

  • This inference is called template argument deduction.

  • For this version of TripleMin, all three arguments must match the same T.

Common Mistake: Mixed Types

This call gives the compiler conflicting clues.

auto x = TripleMin(1, 2.5, 3);

  • 1 and 3 are int.

  • 2.5 is double.

  • The template has only one T, so deduction cannot choose both types.

Fix: Write the Template Argument Explicitly

We can tell the compiler which type to use.

auto x = TripleMin<double>(1, 2.5, 3);

  • Now T is explicitly set to double.

  • The integer arguments can be converted to double.

  • Use this when deduction does not choose what you want.

Practice: Will It Compile?

Assume TripleMin is the single-T template.

TripleMin(3, 2, 1);
TripleMin(3, 2.0, 1);
TripleMin<double>(3, 2.0, 1);

  • Which calls allow the compiler to choose one clear T?

  • Which call gives mixed type clues?

Practice: Answer

  • TripleMin(3, 2, 1): compiles, all arguments are int.

  • TripleMin(3, 2.0, 1): fails deduction, the arguments suggest both int and double.

  • TripleMin<double>(3, 2.0, 1): compiles, T is explicitly double.

Requirements on T

Can T Be Any Type?

Not exactly. The type must support the operations used inside the template.

if (item2 < minVal) minVal = item2;

  • This line uses the < operator.

  • So T must support comparison with <.

  • If not, the compiler reports an error when that template version is instantiated.

Example: Custom Type Needs <

If we want TripleMin to work for our own type, define an ordering.

struct Point {
  int x, y;
};

bool operator<(const Point& a, const Point& b) {
  if (a.x != b.x) return a.x < b.x;
  return a.y < b.y;
}

  • Now the compiler knows how to compare two Point values.

  • So TripleMin(point1, point2, point3) can compile.

Class Templates

Same Idea, Now for Classes

  • A function template generates functions such as TripleMin<int>.

  • A class template generates classes such as Box<int>.

  • Both use a placeholder type such as T.

The mechanism is the same. Only the kind of code being generated changes.

A Small Class Template: Box<T>

template <typename T>
class Box {
  public:
    Box(T value) : value(value) {}

    T getValue() const {
      return value;
    }

  private:
    T value;
};

  • T is the type of the stored value.

  • Different T values generate different class versions.

Using Box<T>

Use int

Box<int> a(10);
int x = a.getValue();

Use std::string

Box<std::string> b("hello");
std::string y = b.getValue();

  • Box<int> stores an int.

  • Box<std::string> stores a std::string.

  • The class design is shared, but the stored type changes.

STL Uses This Idea Everywhere

You have already seen class templates in the STL.

std::vector<int> numbers;
std::vector<std::string> names;
std::stack<char> chars;
std::map<std::string, int> counts;

  • The type inside < > tells the template what concrete type to generate.

  • For containers, that type usually describes what the container stores.

A Larger Example: TripleItem<T>

After the simple Box, the same idea works for a class with more behavior.

template <typename T>
class TripleItem {
  public:
    TripleItem(T v1, T v2, T v3)
      : item1(v1), item2(v2), item3(v3) {}

    T MinItem() const {
      T minVal = item1;
      if (item2 < minVal) minVal = item2;
      if (item3 < minVal) minVal = item3;
      return minVal;
    }

  private:
    T item1, item2, item3;
};

Requirement: T must support < because MinItem uses comparison.

Using TripleItem<T>

TripleItem<int> triInts(9999, 5555, 6666);
std::cout << triInts.MinItem() << "\n";

TripleItem<std::string> triStr("cat", "apple", "zoo");
std::cout << triStr.MinItem() << "\n";

  • TripleItem<int> compares integers.

  • TripleItem<std::string> compares strings.

Multiple Template Parameters

Why Have More Than One Type?

Some structures store different types in different roles.

  • A key/value pair has a key type and a value type.

  • The key might be a std::string.

  • The value might be an int.

  • So one placeholder type is not enough.

Simple Key/Value Class Template

template <typename Key, typename Value>
class Entry {
  public:
    Entry(const Key& k, const Value& v) : key(k), value(v) {}

    const Key& getKey() const { return key; }
    const Value& getValue() const { return value; }

  private:
    Key key;
    Value value;
};

  • Key and Value are both template parameters.

  • They can be different types.

Using Multiple Template Parameters

Entry<std::string, int> score("Alice", 95);

std::cout << score.getKey() << ": "
          << score.getValue() << "\n";

  • Key = std::string

  • Value = int

  • The two template arguments can represent different roles and different types.

Template Organization

Why Is Template Code Usually in the Header?

The compiler must see the full template definition when it instantiates a concrete version.

Normal class pattern

.hpp: declarations
.cpp: definitions

Common template pattern

.hpp: declarations + definitions

  • If the definition is hidden in a separate .cpp, another file may not be able to instantiate the needed type.

  • That often causes linker errors.

Common Ways to Organize Template Code

  • Simple option: put the declaration and definition together in the .hpp file.

  • Larger template: put definitions in a .tpp file and include it at the bottom of the header.

  • Either way, the template definition must be visible when the compiler needs to instantiate it.

Common Template Errors

How to Read Common Errors

  • no matching function: check whether template argument deduction failed, especially because of mixed types.

  • invalid operands to operator<: check whether T supports the operation used by the template.

  • undefined reference: check whether the template definition is visible from the header.

Review

Summary

  • Templates let us write one pattern that works for many types.

  • T is a placeholder type chosen at compile time.

  • Instantiation creates concrete functions or classes from the template.

  • The type used with a template must support the operations used by the template.

  • Template definitions are usually kept in headers so the compiler can see them.
