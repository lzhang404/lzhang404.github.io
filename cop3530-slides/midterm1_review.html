Modular Programs and Testing

Header, source, and driver roles

  • A header declares the interface: classes, fields, constructors, and methods.

  • A source file contains non-inline method and function definitions.

  • A driver contains main() and uses one or more modules.

  • A driver such as main.cpp or test.cpp does not need a paired header.

  • Focused files are easier to reuse, test, compile, and maintain than one large file.

Related course slide: 02_module.html

Header guards

#ifndef SCORE_HPP
#define SCORE_HPP

class Score {
  // declarations
};

#endif

  • #ifndef checks whether the guard name is not defined.

  • #define marks the header as included.

  • #endif closes the conditional block.

  • The guard prevents duplicate declarations when several files include the same header.

Compile first, then link

g++ -c main.cpp -o main.o
g++ -c score.cpp -o score.o
g++ -o app main.o score.o

  • -c compiles one source file into an object file without linking.

  • The linker combines object files into an executable.

  • Link object files when they have already been compiled.

Read a Makefile rule

app: main.o score.o
	g++ -o app main.o score.o

clean:
	rm -f app *.o

  • Target: the output or action before :

  • Dependencies: files needed to build the target

  • Recipe: the tab-indented command

  • make builds the first target; make app and make clean name targets directly.

Unit tests

#include "score.hpp"
#include <cassert>

int main() {
  Score s(7);
  assert(s.value() == 7);
}

  • A unit test checks one small function or class behavior.

  • Tests provide quick, repeatable checks after code changes.

  • Tests do not change an algorithm's runtime or replace implementation code.

Infer an interface from usage

#include "book.hpp"

int main() {
  Book text("Algorithms", 320);
  return text.pages() > 0 ? 0 : 1;
}

  • The include requires a file named book.hpp.

  • The type name requires a class named Book.

  • The construction requires a matching two-parameter constructor.

  • The call requires a member named pages with a usable return value.

  • Do not invent copy or cleanup methods unless ownership evidence requires them.

Memory and Resource Ownership

Stack and heap

  • Each active function call has a stack frame.

  • A stack frame stores parameters, local variables, and a return location.

  • The heap stores objects and arrays created with new or new[].

  • Unbounded function calls can exhaust stack space.

Related course slides: 03_memory.html and 05_recursion.html

Match allocation and deallocation

int* value = new int;
int* values = new int[20];

delete value;
delete[] values;

value = nullptr;
values = nullptr;

  • Use delete for one object created with new.

  • Use delete[] for an array created with new[].

  • A memory leak occurs when owned heap memory is no longer reachable and was not released.

When the Rule of Three is needed

  • A class that owns a raw resource usually needs custom copying and cleanup.

  • The three methods are the destructor, copy constructor, and copy-assignment operator.

  • A class with ordinary value members and no owned resource usually can use compiler-generated methods.

  • Getters, setters, and debug flags do not replace ownership operations.

Non-inline Rule of Three syntax

Buffer::Buffer(const Buffer& other) {
  /* construct a deep copy */
}

Buffer& Buffer::operator=(const Buffer& other) {
  /* replace existing state safely */
  return *this;
}

Buffer::~Buffer() { delete[] data; }

  • A destructor has no return type.

  • Outside the class, use ClassName::methodName.

  • Copy assignment returns the current object by reference.

Deep-copy checklist

  • Copy constructor: allocate new storage, copy size/state, then copy elements.

  • Copy assignment: handle self-assignment and preserve a valid owned resource.

  • Destructor: release the resource exactly once.

  • A shallow pointer copy makes two objects refer to the same allocation and risks double deletion.

allocate replacement -> copy elements -> release old memory
-> store replacement -> copy size -> return *this

Algorithm Analysis

Time, space, and the cost model

  • Time complexity describes how executed work grows with input size.

  • Space complexity describes how memory use grows with input size.

  • An exact count starts by deciding which statements or expressions count as one step.

  • State the input size and assumptions before counting.

Related course slide: 04_algorithm_analysis.html

Count a loop carefully

int matches = 0;
for (int i = 0; i < n; ++i) {
  if (data[i] > 10) {
    ++matches;
  }
}

  • Initialization runs once.

  • The loop condition runs n + 1 times.

  • The update and if condition run n times.

  • The conditional body runs only as often as its condition is true.

  • An exact T(n) may require a stated input assumption.

Sequential, nested, and conditional work

  • Sequential blocks: add their costs.

  • Nested loops: multiply iterations when the inner loop runs for each outer iteration.

  • If/else: one branch runs per condition evaluation; do not count both on the same pass.

  • If every outer iteration runs one linear branch, the total can still be quadratic.

two sequential linear loops:  n + 3n -> Θ(n)
n iterations × one n-step branch: n × n -> Θ(n²)

Growth bounds and dominant terms

  • Big-O: an asymptotic upper bound

  • Big-Omega: an asymptotic lower bound

  • Big-Theta: a tight asymptotic bound

  • Drop constant factors and lower-order terms when simplifying a tight bound.

6n² + n log n + 4n + 9 -> Θ(n²)

Recognize common growth patterns

  • A fixed number of statements: Θ(1)

  • One full pass through n values: Θ(n)

  • A full n-step loop inside another: Θ(n²)

  • Repeatedly halve the remaining problem: Θ(log n)

  • Changing the numeric value of n does not make fixed straight-line code linear.

Recursion

Three questions for every recursive function

  1. Base case: when can the function answer directly?

  2. Progress: how does each call move toward the base case?

  3. Combination: how is the current work combined with the recursive result?

  • Each recursive call creates its own stack frame.

  • Frames remain active until deeper calls return and the stack unwinds.

Related course slide: 05_recursion.html

The base case must be reachable

int steps(int n) {
  if (n == 0) return 0;
  return 1 + steps(n - 3);
}

  • A call such as steps(8) follows 8, 5, 2, -1, ....

  • The code has a base case, but that input never reaches it.

  • Missing or unreachable base cases can cause stack overflow.

  • Trace parameter values to verify progress.

Helpers are optional

  • A function may call itself directly without another function.

  • Use a helper when recursion needs state that should not appear in the public interface.

  • An index, remaining size, or pair of bounds can record progress.

  • The helper and wrapper must agree on the first subproblem.

Recursive array pattern

This parallel example counts positive values instead of computing a sum.

int countPositive(const int values[], int size) {
  if (size == 0) return 0;

  int current = values[size - 1] > 0 ? 1 : 0;
  return current + countPositive(values, size - 1);
}

  • Base case: an empty prefix contributes zero.

  • Progress: each call reduces size by one.

  • Combination: current contribution plus the smaller result.

One recursive call on half the input

n -> n/2 -> n/4 -> n/8 -> ... -> 1

  • Binary search checks one middle value and continues in one half.

  • Constant work per level with about log₂ n levels gives Θ(log n) time.

  • One recursive subproblem is different from two recursive subproblems.

  • The recursive version also uses one stack frame per active level.
