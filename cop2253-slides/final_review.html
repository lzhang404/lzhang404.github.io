Objects and Classes

Class vs. Object

  • A class is a type definition or blueprint.

  • An object is one instance created from that class.

  • The class describes the fields and methods.

  • The object stores actual values while the program runs.

Ticket ticket1 = new Ticket("A12", 25.00);
Ticket ticket2 = new Ticket("B07", 30.00);

  • Ticket is the class.

  • ticket1 and ticket2 are reference variables.

  • new Ticket(...) creates objects.

Basic Class Pattern

A beginner class usually has private fields and public methods.

public class Ticket {
    private String seat;
    private double price;

    public Ticket(String seat, double price) {
        this.seat = seat;
        this.price = price;
    }

    public String getSeat() {
        return seat;
    }

    public double getPrice() {
        return price;
    }
}

  • Fields store object data.

  • The constructor initializes a new object.

  • Getters return field values.

Private Fields and Public Methods

Private fields protect object data from direct outside changes.

public class Ticket {
    private double price;

    public void setPrice(double price) {
        this.price = price;
    }
}

  • private: only code inside the same class can directly use the field.

  • public: other code can call the method.

  • A setter gives the class control over how a field changes.

  • Usually keep fields private and expose safe behavior through methods.

Constructor Rules

  • A constructor has the same name as the class.

  • A constructor has no return type, not even void.

  • A constructor runs when an object is created with new.

  • A constructor usually initializes fields.

public class Song {
    private String title;

    public Song(String title) {
        this.title = title;
    }
}

The this Keyword

this refers to the current object.

private String name;

public void setName(String name) {
    this.name = name;
}

  • this.name means the object field.

  • name by itself means the parameter.

  • This is common when the parameter and field use the same name.

Reference Variables and Aliasing

A reference variable stores a way to find an object. It does not store the object itself.

Counter a = new Counter();
a.value = 10;

Counter b = a;
b.value = 15;

System.out.println(a.value);

  • a and b refer to the same object.

  • Changing the object through b changes what a sees.

  • This is called aliasing.

  • The printed value is 15.

Inheritance and Polymorphism

Is-a vs. Has-a

Before using inheritance, check the relationship.

RelationshipUseExample
Is-aInheritanceCat is a Pet
Has-aField or collectionTeam has players

  • Use extends only when the subclass is a more specific version of the base class.

  • Use fields or ArrayList when one object contains other objects.

Inheritance Syntax

A subclass uses extends to inherit from a base class.

class Vehicle {
    public String move() {
        return "moving";
    }
}

class Bicycle extends Vehicle {
    public int getWheelCount() {
        return 2;
    }
}

  • Bicycle inherits public behavior from Vehicle.

  • Bicycle can also add new behavior.

Calling a Base-Class Constructor

A subclass constructor can call the base-class constructor with super(...).

class Vehicle {
    private String model;

    public Vehicle(String model) {
        this.model = model;
    }
}

class Bicycle extends Vehicle {
    public Bicycle(String model) {
        super(model);
    }
}

  • super(model) calls the constructor in the direct parent class.

Private Fields Stay Private

Inheritance does not remove encapsulation.

class Vehicle {
    private String model;

    public String getModel() {
        return model;
    }
}

class Bicycle extends Vehicle {
    public void printModel() {
        System.out.println(getModel());
    }
}

  • The subclass object contains inherited data.

  • The subclass code should not directly access private base-class fields.

  • Use inherited public methods when needed.

Overriding

Overriding means the subclass provides its own version of an inherited method.

class Vehicle {
    public String move() {
        return "Vehicle moves";
    }
}

class Bicycle extends Vehicle {
    @Override
    public String move() {
        return "Bicycle pedals";
    }
}

  • Same method name.

  • Same parameter list.

  • Compatible return type.

The @Override Annotation

@Override tells the compiler that the method should replace inherited behavior.

@Override
public String toString() {
    return "Bicycle";
}

  • It is not required to run the program.

  • It helps catch spelling or parameter mistakes.

  • Use it before methods that override parent-class or interface methods.

Overloading vs. Overriding

ConceptMeaningExample
OverloadingSame method name, different parameter listprint(int) and print(String)
OverridingSubclass replaces inherited method behaviorBicycle.move() replaces Vehicle.move()

Overloading is about parameters. Overriding is about inheritance.

Polymorphism

Polymorphism lets a general reference point to a specific object.

Vehicle item = new Bicycle("Trail Rider");

System.out.println(item.move());

  • Reference type: Vehicle

  • Object type: Bicycle

  • The object type decides which overridden method runs.

Two-Step Rule for Polymorphic Calls

When Java sees a method call on a polymorphic reference, two checks happen.

Vehicle item = new Bicycle("Trail Rider");
item.move();

  • The compiler asks whether Vehicle has a move() method.

  • At runtime, Java asks what object is actually there.

  • If the object is a Bicycle, the Bicycle version runs.

  • Careable is an interface.

  • Pet is an abstract class.

  • Dog and Cat are concrete subclasses.

  • An ArrayList<Pet> can store dogs and cats together.

Subclass Checklist

When writing a pet subclass, check each required part.

  • Use extends Pet.

  • Write a constructor that calls super(name).

  • Implement every abstract method from Pet.

  • Implement every required method from the interface.

  • Use @Override before methods that replace required behavior.

Polymorphism in the Shelter

The manager code should not decide every pet's sound manually.

ArrayList<Pet> pets = new ArrayList<Pet>();

pets.add(new Dog("Buddy"));
pets.add(new Cat("Luna"));

for (Pet pet : pets) {
    System.out.println(pet.makeSound());
}

  • The loop uses the general type Pet.

  • The object decides which makeSound() version runs.

Abstract Classes and Interfaces

Abstract Classes

An abstract class describes a common idea but is not complete enough to instantiate directly.

abstract class Account {
    private String owner;

    public Account(String owner) {
        this.owner = owner;
    }

    public String getOwner() {
        return owner;
    }

    public abstract double monthlyFee();
}

  • It can store shared fields.

  • It can provide shared methods.

  • It can require abstract methods.

Concrete Subclasses

A concrete subclass must finish inherited abstract methods.

class CheckingAccount extends Account {
    public CheckingAccount(String owner) {
        super(owner);
    }

    @Override
    public double monthlyFee() {
        return 5.00;
    }
}

  • Account is abstract.

  • CheckingAccount is concrete because it implements monthlyFee().

Abstract Methods

An abstract method has a header but no body.

public abstract double monthlyFee();

  • It ends with a semicolon.

  • It does not use braces.

  • A concrete subclass must provide the body.

Interfaces

An interface is a contract of required methods.

interface Printable {
    void printReport();
}

class Receipt implements Printable {
    @Override
    public void printReport() {
        System.out.println("Receipt report");
    }
}

  • A class uses implements to follow an interface.

  • A concrete class must implement the required methods.

Abstract Class vs. Interface

Use thisWhen you need...Example
Abstract classShared fields, shared methods, and required methodsPet, Account
InterfaceA method contract that different classes can followCareable, Printable

  • A class can extend one class.

  • A class can implement multiple interfaces.

File I/O and Exceptions

File Input Pattern

To read a file, open a stream and connect a scanner to it.

FileInputStream fileStream =
        new FileInputStream("data.txt");

Scanner fileScanner = new Scanner(fileStream);

while (fileScanner.hasNextLine()) {
    String line = fileScanner.nextLine();
    System.out.println(line);
}

fileScanner.close();
fileStream.close();

  • FileInputStream opens the file.

  • Scanner reads tokens or lines from the stream.

Reading Tokens vs. Reading Lines

Scanner methodUse when...
hasNextLine()You want to process each full line.
nextLine()You want to read one full line.
hasNext()You want to check for another token.
next()You want to read one token.
hasNextInt()You want to check whether the next token is an integer.

File Output Pattern

To write to a file, open an output stream and connect a writer to it.

FileOutputStream outputStream =
        new FileOutputStream("summary.txt");

PrintWriter writer = new PrintWriter(outputStream);

writer.println("Summary Report");
writer.printf("Average: %.2f%n", average);

writer.close();
outputStream.close();

  • PrintWriter gives print(), println(), and printf().

  • Close the writer when finished.

Common Exception Types

ExceptionCommon cause
IOExceptionA file or stream operation has a problem.
FileNotFoundExceptionA file cannot be opened.
InputMismatchExceptionScanner expected one type but found another.
NumberFormatExceptionA string cannot be converted to a number.
NullPointerExceptionCode tries to use an object through null.

try and catch

A try block contains code that may fail. A catch block handles the exception.

try {
    int rating = scnr.nextInt();
    System.out.println("Rating: " + rating);
}
catch (InputMismatchException excpt) {
    System.out.println("Please enter a whole number.");
    scnr.next();
}

  • If the read succeeds, the program continues normally.

  • If the read fails, the matching catch block runs.

Checked vs. Unchecked Exceptions

KindBeginner meaningExamples
Checked exceptionJava requires the code to catch it or declare it.IOException, FileNotFoundException
Unchecked exceptionUsually caused by a programming or runtime input problem.InputMismatchException, NullPointerException

  • File operations commonly involve checked exceptions.

Try-With-Resources

Try-with-resources closes declared resources automatically.

try (Scanner input =
         new Scanner(new FileInputStream("data.txt"));
     PrintWriter output =
         new PrintWriter(new FileOutputStream("summary.txt"))) {

    while (input.hasNextLine()) {
        String line = input.nextLine();
        output.println(line);
    }
}
catch (IOException excpt) {
    System.out.println("File problem.");
}

Recursion Basics

A recursive method calls itself to solve a smaller version of the same problem.

public static int sumTo(int n) {
    if (n <= 0) {
        return 0;
    }

    return n + sumTo(n - 1);
}

  • Base case: n <= 0

  • Recursive case: n + sumTo(n - 1)

  • The value moves closer to the base case each time.

Text Fields and Button Clicks

A GUI program often reads text, calculates, then displays text.

calculateButton.addActionListener(event -> {
    String inputText = wageField.getText();
    double wage = Double.parseDouble(inputText);

    double salary = wage * 40 * 50;
    salaryField.setText(String.format("%.2f", salary));
});

  • getText() reads text from a field.

  • setText() displays text in a field.

  • The listener code runs after the button is clicked.

Summary

Read Code in This Order

  1. What classes are defined?

  2. Which class extends another class?

  3. Which methods are overridden?

  4. What is the reference type?

  5. What object is actually created with new?

  6. Which method version runs?

This order is especially useful for polymorphism questions.

Common Mistakes to Avoid

  • Writing void in a constructor.

  • Forgetting super(...) when the parent constructor requires arguments.

  • Using extends for an interface instead of implements.

  • Forgetting to implement an abstract or interface method.

  • Confusing overloading with overriding.

  • Reading from System.in when the task says to read from a file stream.

  • Forgetting to increment a counter inside a loop.

Key Takeaways

  • Use classes to group data and behavior.

  • Use inheritance only for real is-a relationships.

  • Use abstract classes and interfaces to require behavior.

  • Use polymorphism to process related objects through a shared type.

  • Use file streams, scanners, writers, and exceptions to handle input and output safely.
