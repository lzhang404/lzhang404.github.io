ADTs and Templates

ADT and implementation

AbstractionDefinesExamples
ADTAvailable operations and their behaviorList, stack, queue, deque, map, set
ImplementationHow data and state are storedArray, singly-linked list, doubly-linked list, hash table

  • A linked list exposes nodes and pointers, so it describes an implementation.

  • The same linked structure can implement several ADTs.

  • An ADT class declaration can list public operations without exposing private storage.

Stack, queue, and deque behavior

ADTInsertRemoveOrdering rule
StackTopTopLIFO
QueueRearFrontFIFO
DequeEither endEither endChosen by the operation

  • A deque supports all queue operations and additional operations at the other end.

  • A linked list can implement a queue, but the linked list itself does not define FIFO behavior.

Practice: declare an ADT interface

Declare a generic queue interface with four public operations. Do not expose its storage.

template <typename T>
class Queue {
public:
  void enqueue(T value);
  T dequeue();
  T peek();
  bool isEmpty();
};

  • The methods describe queue behavior.

  • No array, node, head, or rear field appears in the public interface.

  • A different implementation can keep the same interface.

Function and class templates

template <typename T>
T larger(T a, T b) {
  return a < b ? b : a;
}

template <typename T>
class Box {
  T value;
};

  • T is a placeholder for a type chosen when the template is used.

  • Templates reuse one algorithm or class design for several compatible types.

  • The chosen type must support every operation used by the template.

  • Templates complement function overloading; they do not replace every overload.

Pass by reference

template <typename T>
void exchange(T& first, T& second) {
  T saved = first;
  first = second;
  second = saved;
}

  • C++ passes ordinary parameters by value unless the parameter type contains &.

  • References let the function modify the caller's variables.

  • Both parameters need reference types for a swap-like function.

Practice: generic first match

template <typename T>
int firstMatch(const T values[], int size, T target) {
  for (int i = 0; i < size; ++i) {
    if (values[i] == target) return i;
  }
  return -1;
}

  • The array element type and target type use the same template parameter.

  • The function requires T to support ==.

  • The search checks at most n elements, so its worst-case time is O(n).

Template definitions must be visible

  • The compiler generates a concrete function or class when a template is instantiated.

  • It must see the full template definition at that point.

  • For this course, place a template's declaration and definition in one header file.

  • A larger project may include a .tpp file from the bottom of the header.

Linked Lists and Queues

Singly-linked list invariants

class Node {
public:
  int value;
  Node* next;
};

Node* head;
Node* tail;

  • An empty list has head == nullptr and tail == nullptr.

  • In a non-empty list, head points to the first node and tail points to the last.

  • The last node satisfies tail->next == nullptr.

  • Save a pointer before overwriting the only route to a node.

Prepend a node

void prepend(int value) {
  Node* node = new Node{value, nullptr};
  if (head == nullptr) {
    head = node;
    tail = node;
  } else {
    node->next = head;
    head = node;
  }
}

  • Empty case: both pointers identify the one new node.

  • Non-empty case: connect the new node before moving head.

  • tail does not change when the old list was non-empty.

Linked queue state

class TicketQueue {
  int size;
  Node* head;  // front
  Node* tail;  // rear
public:
  TicketQueue() : size(0), head(nullptr), tail(nullptr) {}
};

  • Enqueue at the tail and dequeue at the head.

  • The head stores the oldest item; the tail stores the newest item.

  • An empty queue has size 0 and both pointers equal to nullptr.

  • Keeping both pointers makes enqueue and dequeue O(1).

Linked queue: enqueue

void enqueue(int value) {
  Node* node = new Node{value, nullptr};
  if (head == nullptr)
    head = node;
  else
    tail->next = node;
  tail = node;
  ++size;
}

  • When the queue is empty, the new node becomes both front and rear.

  • Otherwise, connect the old tail before moving tail.

  • The old head does not move.

Linked queue: dequeue

int dequeue() {
  if (head == nullptr) return -1;
  Node* old = head;
  int result = old->value;
  head = head->next;
  if (head == nullptr) tail = nullptr;
  delete old;
  --size;
  return result;
}

  • Save the value and next pointer before deleting the node.

  • Removing the final node must clear both head and tail.

  • Peek returns head->value without changing any pointer or the size.

Read tests as a contract

TicketQueue q;
q.enqueue(4);
q.enqueue(9);
CHECK(q.length() == 2);
CHECK(q.dequeue() == 4);
CHECK(q.peek() == 9);
CHECK(q.length() == 1);

  • The tests require FIFO order, a non-removing peek, and an accurate length.

  • Implement the public behavior the tests use, including the specified empty result.

  • A destructor can repeatedly remove the head until no nodes remain.

~TicketQueue() {
  while (head != nullptr) dequeue();
}

Extra storage and stability

AlgorithmExtra arrays or bucketsStable?

QuicksortNone for partitionNo for the class partition

  • In place: rearranges the original data without an auxiliary array proportional to n.

  • Stable: equal keys keep their original relative order.

Radix sort rounds

For decimal LSD radix sort, the largest number determines the number of digit passes.

values: 8, 63, 407, 1205

ones -> tens -> hundreds -> thousands

  • The largest value, 1205, has four decimal digits.

  • The algorithm performs four bucket-and-collection rounds.

  • A missing digit counts as 0, so every value participates in every round.

  • Preserve arrival order inside each bucket.

Hoare partition from class

int partition(int arr[], int low, int high) {
  int pivot = arr[low + (high - low) / 2];
  int i = low, j = high;
  while (i <= j) {
    while (arr[i] < pivot) ++i;
    while (arr[j] > pivot) --j;
    if (i >= j) break;
    std::swap(arr[i], arr[j]);
    ++i;
    --j;
  }
  return j;
}

  • Save the middle element's value as the pivot.

  • Move i past values smaller than the pivot and j past values larger than it.

  • Complete the entire function call. One swap is not one partition round.

  • The returned index is a split boundary; it need not be the pivot's final position.

Order common growth rates

expected hash-table lookup: O(1)
linear search:             O(n)
merge sort:               O(n log n)
selection sort:           O(n²)

From least to greatest asymptotic growth:

O(1) < O(n) < O(n log n) < O(n²)

  • Expected, best-case, average-case, and worst-case bounds are different claims.

  • A lower growth rate does not mean an algorithm is always faster for every small input.

Hash Tables

Key, hash code, and index

  1. Key: k

  2. Hash code: h(k)

  3. Table index: h(k) % m

  4. Bucket check: compare actual keys.

  • Different keys may share an index.

  • Keep both entries and resolve the collision.

Collision methods and capacity

MethodWhere colliding entries goCapacity fact
ChainingSame bucket's linked structureStored entries may exceed the bucket count
Open addressingOther buckets in the same arrayAt most one live entry per bucket

  • Linear, quadratic, and double hashing are open-addressing probe rules.

  • A full open-addressed table cannot accept another entry without resizing or reusing a deleted slot.

Hash-table lookup cost

ConditionLookup timeReason
Suitable hashing and controlled loadO(1) expectedShort bucket or probe sequence
Many collisions or poor distributionCan reach O(n)Many keys must be examined
Sorted array with binary searchO(log n) worst caseDiscard half of the range per comparison

“Expected O(1)” does not mean “always faster.” Compare the same case, assumptions, and input size.
