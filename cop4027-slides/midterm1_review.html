1. Java Projects, Maven, and Modules

Course Project Mental Model

  • Build: Maven and pom.xml compile, test, package, and download libraries.

  • Project layout: Maven directories separate source, resources, tests, and generated output.

  • Organization: Packages group related classes and provide namespaces.

  • Strong boundary: module-info.java declares required modules and exposed packages.

Maven Layout and Resource Flow

project/
├── pom.xml
├── src/main/java/       Java source
├── src/main/resources/  packaged files
├── src/test/java/       test source
└── target/              generated output

  • Maven copies resources to the runtime classpath under target/classes.

  • target is generated. Edit files under src.

Dependencies and Module Boundaries

  • Maven dependencies

    • A direct dependency is declared in pom.xml.

    • A transitive dependency is required by another dependency.

    • The local repository is the .m2 cache for downloaded artifacts.

  • Module boundaries

    • requires names a module this module needs.

    • exports exposes a package to other modules.

A public class must also be inside an exported package for cross-module access.

2. Reflection and Annotations

Direct Calls and Runtime Discovery

  • Direct construction and calls: Use them when the class and method are known while writing the code. The compiler checks names and types.

  • Reflection behind a loader: Use it when a class name comes from configuration and the program chooses the class at runtime.

  • Annotations plus reflection: A framework can discover marked methods and use metadata to identify allowed elements.

Class Metadata and Member Lookup

Class<?> a = Report.class;
Class<?> b = report.getClass();
Class<?> c = Class.forName(className);

Method m = c.getMethod("run", String.class);

  • getMethods() returns public methods, including inherited methods.

  • getDeclaredMethods() returns methods declared directly in the class.

Create and Invoke at Runtime

Class<?> rawType = Class.forName(className);
Class<? extends ReportTask> type =
    rawType.asSubclass(ReportTask.class);
ReportTask task = type.getDeclaredConstructor()
                      .newInstance();
Method method = type.getMethod(
    "run", String.class);
Object result = method.invoke(task, "weekly");

  • Lookup fails when the class, constructor, or method does not exist.

  • InvocationTargetException wraps an exception thrown by the invoked method.

Runtime Annotations

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Command {
    String value();
}

  • RUNTIME makes the annotation visible to reflection.

  • METHOD limits where the annotation may appear.

  • The runner discovers marked methods, validates them, and invokes accepted methods.

3. Data and Configuration Formats

External Text to Validated Java

try (InputStream in = App.class
        .getResourceAsStream("/app.properties")) {
    Properties p = new Properties();
    p.load(in);
    String text = p.getProperty("server.port");
    int port = Integer.parseInt(text);
}

  • A classpath resource travels with the application.

  • Properties stores keys and values as strings.

  • Convert the text, then validate the application rules.

Choosing a Text Format

JSON Structure and Java Representations

{
  "name": "Harbor Store",
  "open": true,
  "items": [
    { "sku": "A17", "price": 12.5 }
  ]
}

  • Use object mapping for a stable shape.

  • Use JsonNode for a flexible shape or selected fields.

YAML Structure

store:
  name: "Harbor Store"
  open: true
  tags:
    - local
    - "open late"

  • Indentation expresses nesting.

  • A dash starts a list item.

  • Quotes protect text that may be interpreted as another type.

Reading an XSD

<xs:element name="book">
  <xs:complexType>
    <xs:sequence>
      <xs:element name="title" type="xs:string"/>
      <xs:element name="pages" type="xs:positiveInteger"/>
    </xs:sequence>
    <xs:attribute name="id" type="xs:string" use="required"/>
  </xs:complexType>
</xs:element>

  • The root element is book.

  • title comes before a positive pages value.

  • The id attribute is required.

Valid XML Instance

<book id="B7">
  <title>Clean Code</title>
  <pages>464</pages>
</book>

  • Well-formed XML follows XML syntax.

  • Schema-valid XML also follows the required structure, types, and attributes.

4. JavaFX

JavaFX Runtime Mental Model

  • Stage: the top-level window.

  • Scene: the content area placed in the window.

  • VBox: a layout node that arranges children vertically.

  • Button: a control that can fire an action event.

The scene graph is a tree of layouts, controls, and other nodes.

Controls, Layouts, and Events

  • Controls define what appears, such as Label, TextField, and Button.

  • Layouts determine where nodes go, such as VBox, HBox, and GridPane.

  • Event handlers define what happens after a user action.

saveButton.setOnAction(event -> {
    String name = nameField.getText();
    if (name.isBlank()) {
        messageLabel.setText("Name required");
        return;
    }
    save(name);
});

FXML, Controllers, and CSS

<VBox fx:controller="app.EditorController">
  <TextArea fx:id="editor" id="mainEditor"/>
  <Button text="Save" onAction="#save"/>
</VBox>

  • FXMLLoader builds the object graph from FXML.

  • fx:id connects an object to an @FXML controller field.

  • id supports a CSS #mainEditor selector.

  • onAction="#save" connects an event to an @FXML method.

Properties, Listeners, and Binding

  • Event handler: React to a discrete user action, such as a button click.

  • Listener: React to a value changing, such as marking a document dirty when its text changes.

  • Binding: Keep one value derived from another, such as disabling Save while the document is unchanged.

saveButton.disableProperty().bind(dirty.not());

editor.textProperty().addListener(
    (observable, oldText, newText) -> dirty.set(true));

Files and Application State

File file = chooser.showOpenDialog(stage);
if (file != null) {
    String text = Files.readString(file.toPath());
    editor.setText(text);
    currentFile = file.toPath();
    dirty.set(false);
}

  • A file chooser returns null when the user cancels.

  • Track the current file and whether edits are unsaved.

  • File operations can fail and need a useful message.

Responsive JavaFX Applications

Task<Report> task = new Task<>() {
    @Override
    protected Report call() throws Exception {
        return buildReport();
    }
};

progress.progressProperty().bind(task.progressProperty());
task.setOnSucceeded(e -> showReport(task.getValue()));
new Thread(task).start();

  • Task.call() performs slow work away from the JavaFX Application Thread.

  • Task properties report state. Completion handlers update the interface.

5. Generics

Generic Types, Methods, and Bounds

Box<String> name = new Box<>();

static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

  • The compiler checks the selected type and removes many casts.

  • A bound states which operations are safe for T.

Generic Invariance

List<Integer> integers = new ArrayList<>();
// List<Number> numbers = integers;  // compile-time error

  • Integer is a subtype of Number.

  • List<Integer> is not a subtype of List<Number>.

  • Otherwise, code could add a Double to a list of integers.

Wildcard Read and Write Rules

ParameterSafe ReadSafe WriteBest Fit
List<? extends Number>Read as NumberCannot add a specific numberThe method mainly reads values
List<? super Integer>Read only as ObjectMay add an IntegerThe method writes integer values

Reading needs a safe upper type. Writing needs a destination known to accept the value.

Copying Between Related Lists

static <T> void copy(
        List<? super T> destination,
        List<? extends T> source) {
    for (T value : source) {
        destination.add(value);
    }
}

The source supplies T values. The destination accepts T values.

Type Erasure and Runtime Limits

  • Erasure

    • Unbounded T erases to Object.

    • T extends Number erases to Number.

  • Runtime limits

    • new T() and new T[] are not allowed.

    • instanceof List<String> is not allowed.

    • instanceof List<?> is allowed because it checks only the list type.

Five Mental Models

  • Projects: Source and resources flow through Maven into generated output.

  • Reflection: Discover at runtime, validate the contract, then return to normal Java types.

  • Formats: Parse syntax, represent the data, convert values, then validate meaning.

  • JavaFX: User events change state and UI while slow work stays off the UI thread.

  • Generics: Type relationships determine what can be read, written, and known at runtime.
