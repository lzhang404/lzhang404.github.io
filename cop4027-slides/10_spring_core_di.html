Dependency Injection in Plain Java

What Is a Dependency?

A dependency is another object that a class needs to do its work.

public final class TaskModel {
    private final TaskRepository repository;

    public TaskModel(TaskRepository repository) {
        this.repository = repository;
        reload();
    }
}

  • TaskModel performs task operations.

  • It needs a TaskRepository to save and load tasks.

  • Therefore, the Repository is a dependency of the Model.

Creating the Dependency Inside the Class

A class can create the object it needs by itself.

public TaskModel() throws IOException {
    DatabaseConfig config =
            DatabaseConfig.load("/database.properties");
    repository = new JdbcTaskRepository(config);
}

  • TaskModel decides that persistence must use JDBC.

  • TaskModel also loads the database configuration.

  • Task operations and dependency construction become coupled.

Receiving the Dependency from Outside

A class can receive the object it needs from another part of the application.

public TaskModel(TaskRepository repository) {
    this.repository = repository;
    reload();
}

  • TaskModel only declares that it needs a Repository.

  • Something outside the Model chooses which Repository to provide.

  • The Model stays focused on task operations.

What Is Dependency Injection?

Dependency injection means giving an object the dependencies it needs from outside instead of having the object create them itself.

  • The class declares what it needs.

  • Another part of the application creates the dependency.

  • That dependency is supplied to the class.

TaskModel needs a TaskRepository, but it does not need to decide whether that Repository uses JDBC, memory, JPA, or another storage system.

Injection Styles

  • Constructor injection: passes required dependencies during construction.

  • Setter injection: supplies a dependency through a setter after construction.

  • Field injection: writes directly to a field.

This course uses constructor injection.

Why Constructor Injection?

  • The constructor shows every required dependency.

  • The object starts with complete state.

  • Dependency fields can remain final.

  • Tests can pass small replacement objects.

  • The class stays independent of Spring.

Who Performs the Injection?

Dependency injection does not require a framework.

Ordinary Java code can create and connect the objects.

DatabaseConfig config = DatabaseConfig.load("/database.properties");
TaskRepository repository = new JdbcTaskRepository(config);

TaskModel model = new TaskModel(repository);
TaskView view = new TaskView(model);
TaskController controller = new TaskController(model, view);

  • The startup code chooses the implementations.

  • The constructors receive the dependencies.

  • This is dependency injection in plain Java.

Dependency Injection and Inversion of Control

  • Dependency injection: dependencies are supplied from outside the object.

  • Inversion of control: the object no longer controls how those dependencies are created.

For TaskModel:

  • The Model declares that it needs a TaskRepository.

  • Another part of the application chooses and creates that Repository.

  • Spring can take over this construction and wiring work.

From Manual Wiring to Spring

The dependencies do not change. What changes is who creates and connects the objects.

  • Plain Java: startup code creates the Repository, Model, View, and Controller.

  • Spring: configuration describes those objects, and the container creates them.

  • The application classes can keep ordinary Java constructors.

Manual wiring:
startup code -> creates objects -> connects dependencies

Spring wiring:
configuration -> Spring container -> creates and connects objects

The Spring Core Container

Spring Core Vocabulary

  • Bean: an object managed by Spring.

  • Container: creates and connects beans.

  • Application context: the Spring container that manages the application's beans.

  • Configuration: describes the beans to create.

  • Injection: supplies one bean to another.

Spring Core with Maven

The project needs Spring Core libraries before it can create a Spring application context.

<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-context</artifactId>
    <version>${spring.version}</version>
</dependency>

  • spring-context provides the application context.

  • It includes the Core container dependencies.

  • Maven downloads the required Spring libraries.

Annotations at Runtime

  • Spring inspects annotations and configuration metadata during startup.

  • Reflection lets Spring inspect classes and methods.

  • @Configuration marks bean configuration.

  • @Bean marks an object-creation method.

  • The annotation supplies metadata to the container.

This reuses Java reflection and annotation concepts.

Database and Repository Beans

A configuration class can describe how Spring should create infrastructure and data-access objects.

@Configuration //marks a configuration class
public class TaskConfiguration {
    @Bean // marks an object-creation method
    DatabaseConfig databaseConfig() throws IOException {
        return DatabaseConfig.load("/database.properties");
    }

    @Bean
    TaskRepository taskRepository(DatabaseConfig config) {
        return new JdbcTaskRepository(config);
    }
}

  • Spring supplies the DatabaseConfig parameter.

Beans Form a Dependency Graph

Bean method parameters tell Spring which other objects are required.

@Bean
TaskModel taskModel(TaskRepository repository) {
    return new TaskModel(repository);
}

@Bean
TaskController taskController(TaskModel model, TaskView view) {
    return new TaskController(model, view);
}

  • TaskModel requires a TaskRepository.

  • TaskController requires a Model and View.

  • Spring finds matching beans and supplies those arguments.

The Application Context

The application context starts the container and gives the application access to managed objects.

context = new AnnotationConfigApplicationContext(
        TaskConfiguration.class);

TaskController controller =
        context.getBean(TaskController.class);

controller.connectHandlers();

  • The context reads TaskConfiguration.

  • Spring creates the required beans and connects their dependencies.

  • getBean(...) retrieves an object managed by Spring.

How Spring Resolves the Beans

  1. TaskController requires a Model and View.

  2. TaskView requires the Model.

  3. TaskModel requires a Repository.

  4. JdbcTaskRepository requires database configuration.

  5. Spring creates the required beans and supplies constructor or method arguments.

The constructors remain ordinary Java constructors.

Choosing a Bean by Type

  • Spring normally matches a dependency by its Java type.

  • One matching bean gives Spring a clear choice.

  • No matching bean causes application startup to fail.

  • Several matching beans require Spring to know which one to use.

  • @Primary or @Qualifier can resolve that choice.

Component Scanning

Spring can also discover annotated classes instead of using only explicit @Bean methods.

  • Explicit @Bean methods show each construction step.

  • Component scanning finds annotated classes in selected packages.

  • @Component marks a general Spring-managed class.

  • @ComponentScan selects packages to scan.

Spring Stereotype Roles

Stereotype annotations mark Spring-managed classes and describe their role in the application.

  • @Component: general Spring-managed class.

  • @Service: application or service logic.

  • @Repository: data-access class.

  • @Controller: web controller in Spring Web MVC.

  • @RestController: web controller that returns response data.

The annotation helps Spring discover the class; it does not automatically design the application for us.

Constructor Injection with Scanned Classes

In many Spring applications, application operations are placed in a service class.

When Spring discovers a class, it can still use ordinary constructor injection.

@Service
public class TaskService {
    private final TaskRepository repository;

    public TaskService(TaskRepository repository) {
        this.repository = repository;
    }
}

  • Spring discovers TaskService during component scanning.

  • The constructor declares a required TaskRepository.

  • Spring finds a matching Repository bean and injects it.

JavaFX and Spring Work Together

JavaFX manages the application window while Spring manages the application objects.

public void start(Stage stage) {
    context = new AnnotationConfigApplicationContext(
            TaskConfiguration.class);

    TaskView view = context.getBean(TaskView.class);
    TaskController controller =
            context.getBean(TaskController.class);

    controller.connectHandlers();

    stage.setScene(new Scene(view));
    stage.show();
}

  • JavaFX creates the application and Stage.

  • Spring creates and connects the Task List objects.

  • The Controller connects the JavaFX event handlers.

  • The two frameworks have different responsibilities.

Replacing Dependencies

A Different Repository Bean

Because the Model depends on the interface, Spring can provide another implementation.

@Bean
TaskRepository taskRepository() {
    return new InMemoryTaskRepository();
}

  • TaskModel still receives a TaskRepository.

  • The Model code does not change.

  • Tests can use a small in-memory implementation.

  • A later lesson can supply a Spring Data JPA implementation.

Testing Without the Container

Constructor injection lets unit tests create only the objects they need.

TaskRepository repository = new InMemoryTaskRepository();
TaskModel model = new TaskModel(repository);

model.addTask("Review dependency injection");

assertEquals(1, model.getTasks().size());

  • A Model unit test does not need Spring.

  • A separate context test can check bean wiring.

  • Constructor injection supports both test styles.

Practice

Read the Bean Definition

@Bean
TaskController taskController(TaskModel model, TaskView view) {
    return new TaskController(model, view);
}

  1. Which object becomes a bean?

  2. Which objects are its dependencies?

  3. Who supplies the method arguments?

  4. Who calls the constructor?

Practice Answers

  • The returned TaskController becomes a bean.

  • TaskModel and TaskView are its dependencies.

  • Spring supplies both method arguments.

  • The bean method calls the constructor.

Summary

Key Takeaways

  • A dependency is an object another object needs.

  • Constructor injection supplies dependencies from outside.

  • Spring Core manages objects in a container.

  • A Spring-managed object is a bean.

  • @Configuration, @Bean, and component scanning define the object graph.

  • Stereotype annotations mark common roles such as service, repository, and web controller.

  • The three-tier responsibilities stay the same.
