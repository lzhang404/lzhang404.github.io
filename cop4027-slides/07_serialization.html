Serializable Task List

public final class TaskList implements Serializable { ... }
public final class Task implements Serializable { ... }

TaskList week = new TaskList("Week 6");
week.add(new Task("Read"));
week.add(new Task("Practice"));

  • Serializable is a marker interface.

  • It has no methods to implement.

  • A TaskList reaches its Task objects.

Java Object Serialization

Object Streams and Graphs

  • The root is the object passed to writeObject.

  • Java follows reachable fields.

  • Nested and shared references are preserved.

  • Each reached object must be serializable.

  • Unsupported values cause NotSerializableException.

Shared References Stay Shared

Task sharedTask = new Task("Read");
TaskList original = new TaskList("Week 6");
original.add(sharedTask);
original.add(sharedTask);

// After save and load:
restored.tasks().get(0) == restored.tasks().get(1)  // true

  • One object may have several references.

  • The restored graph keeps that identity.

Writing an Object Stream

TaskList original = new TaskList("Week 6");
original.add(new Task("Read"));

try (ObjectOutputStream out = new ObjectOutputStream(
        Files.newOutputStream(file))) {
    out.writeObject(original);
}

  • original is the graph root.

  • The stream follows its saved fields.

  • try-with-resources closes the stream.

Reading and Round Trip

TaskList restored;
try (ObjectInputStream in = new ObjectInputStream(
        Files.newInputStream(file))) {
    Object value = in.readObject();
    if (!(value instanceof TaskList taskList)) {
        throw new InvalidObjectException("Expected TaskList");
    }
    restored = taskList;
}

  • Check the Object returned by readObject().

  • Matching classes must be available.

  • A round trip restores state in a new object graph.

What Gets Saved?

public final class TaskList implements Serializable {
    private static final long serialVersionUID = 1L;
    private final String name;              // saved
    private final List<Task> tasks = new ArrayList<>(); // followed
    private transient Path sourceFile;      // excluded
    private transient int completedCount;   // excluded
}

public final class Task implements Serializable {
    private static int nextId = 1000;       // not saved
    private final int id;                   // saved
    private final String title;             // saved
    private boolean done;                   // saved
}

  • Instance fields are saved by default.

  • static fields belong to the class.

  • transient fields are excluded.

Restored-State Validation

private void readObject(ObjectInputStream in)
        throws IOException, ClassNotFoundException {
    in.defaultReadObject();

    if (name == null || name.isBlank()) {
        throw new InvalidObjectException(
                "Task list name must not be blank");
    }
    if (tasks == null || tasks.contains(null)) {
        throw new InvalidObjectException("Task collection is invalid");
    }

    // Rebuild completedCount from tasks.
}

  • Normal loading skips constructor checks.

  • defaultReadObject() restores saved fields.

  • Then validate fields and rebuild transient state.

Versioning and Safety

Version Compatibility

private static final long serialVersionUID = 1L;

  • Saved files may outlive current code.

  • The stream stores this class version.

  • A mismatch causes InvalidClassException.

  • The value does not migrate changed data.

Common Compatibility Changes

Change What to think about Safer approach
Add a field Old data will not have it Make it optional or provide a default
Rename a field Old names may no longer map Accept old and new names during migration
Remove a field Old data may still contain it Ignore it intentionally or migrate the data
Change meaning Syntax may still parse but logic may be wrong Use a version field and explicit migration

Testing Old Files

  • A current round trip tests only current code.

  • Keep small files from supported versions.

  • Load them with current code.

  • Check defaults and rebuilt fields.

  • Reject unsupported versions clearly.

Deserialization Risks

  • Input may request unexpected classes.

  • Large graphs can exhaust resources.

  • Loading hooks may run.

  • Never deserialize unknown network input.

Deserialization Filter

ObjectInputFilter filter = ObjectInputFilter.Config.createFilter(
    "maxdepth=20;maxrefs=10000;maxbytes=1000000;" +
    "cop4027.serialization.TaskList;" +
    "java.base/*;!*");

try (ObjectInputStream in = new ObjectInputStream(
        Files.newInputStream(file))) {
    in.setObjectInputFilter(filter);
    in.readObject();
}

  • The filter omits Task.

  • The incomplete allowlist rejects the graph.

  • A complete filter lists every expected graph class.

  • Example: FilteredDeserializationExample.java

Serialization Checklist

  • Private Java snapshot: filtered object stream

  • Public boundary: JSON or XML

  • Every reached class implements Serializable.

  • transient excludes runtime state.

  • Loading validates fields and rebuilds derived state.

  • Supported old files remain in compatibility tests.
