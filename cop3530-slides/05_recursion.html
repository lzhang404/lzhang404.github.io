What is recursion?

Recursion is a technique where a function solves a problem by calling itself on smaller inputs until it reaches a base case.

  • Base case: stops recursion and returns an answer directly

  • Recursive case: reduces the problem and calls itself

  • Progress: each call must move toward the base case

Function Calls and the Call Stack

Stack frames

  • Each function call creates a stack frame

  • A stack frame stores parameters, local variables, and return information

  • When a function returns, its stack frame is removed

  • The call stack is LIFO: last call returns first

Stack snapshot example

Top of stack
┌─────────────────────────┐
│ Frame: f(0)             │
├─────────────────────────┤
│ Frame: f(1)             │
├─────────────────────────┤

├─────────────────────────┤

Bottom of stack

  • Recursion creates many frames of the same function

  • Deep recursion means many frames (risk: stack overflow)

Practice: call order

What is the call order and return order?

int A() { return 1; }
int B() { int x = A(); return x + 1; }
int C() { int y = B(); return y + 1; }
int main() { int z = C(); }

  • Call order: main → C → B → A

  • Return order: A → B → C → main

Recursion Template

Three parts of a recursive solution

  • Base case: handle the simplest input

  • Progress: reduce input size so base case is reachable

  • Combine: build final answer from recursive result

Generic recursion template

ReturnType f(Input x) {
  if (isBase(x)) {
    return baseAnswer(x);
  }
  Input smaller = makeSmaller(x);
  ReturnType sub = f(smaller);
  return combine(x, sub);
}

Example: factorial

Definition:

  • 0! = 1

  • n! = n × (n−1)! for n > 0

#include <stdexcept>
long long factorial(int n) {
  if (n < 0) throw std::invalid_argument("n must be >= 0");
  if (n == 0) return 1;
  return 1LL * n * factorial(n - 1);
}

Tracing factorial(4)

factorial(4)
= 4 * factorial(3)
= 4 * 3 * factorial(2)
= 4 * 3 * 2 * factorial(1)
= 4 * 3 * 2 * 1 * factorial(0)
= 24

Tracing Recursion

Call tree vs call stack

  • Call tree: conceptual picture of recursive calls

  • Call stack: actual runtime memory frames

Call tree (concept)
f(3)
└─ f(2)
   └─ f(1)
      └─ f(0)
Call stack (runtime)
top:    [f(0)]
        [f(1)]
        [f(2)]
bottom: [f(3)]

Work before vs work after recursion

Where you place work changes output order.

// work before (prints 3 2 1)
void down(int n) {
  if (n == 0) return;
  cout << n << " ";
  down(n - 1);
}

// work after (prints 1 2 3)
void up(int n) {
  if (n == 0) return;
  up(n - 1);
  cout << n << " ";
}

Writing Recursive Functions

Common pattern: helper function

  • Public function has a clean interface

  • Helper carries extra state (index, bounds, depth)

int sumHelper(const int a[], int n, int i) {
  if (i == n) return 0;
  return a[i] + sumHelper(a, n, i + 1);
}

int sumAll(const int a[], int n) {
  return sumHelper(a, n, 0);
}

Practice: power function

Implement x^n for n ≥ 0

long long powInt(long long x, int n) {
  if (n == 0) return 1;
  return x * powInt(x, n - 1);
}

Faster power (divide by 2)

long long powFast(long long x, int n) {
  if (n == 0) return 1;
  if (n == 1) return x;
  long long half = powFast(x, n / 2);
  if (n % 2 == 0) return half * half;
  return half * half * x;
}

Recursive Search: Binary Search

Binary search idea

  • Only works on a sorted array

  • Check the middle element

  • Eliminate half the search space each step

  • Progress: range shrinks each recursive call

Binary search (recursive code)

int binSearch(const int a[], int left, int right, int target) {
  if (left > right) return -1;

  int mid = left + (right - left) / 2;

  if (a[mid] == target) return mid;
  if (target < a[mid]) return binSearch(a, left, mid - 1, target);
  return binSearch(a, mid + 1, right, target);
}

Print tracing with indentation

#include <iostream>
#include <string>
using namespace std;

void indent(int depth) {
  for (int i = 0; i < depth; i++) cout << "  ";
}

int sumDbg(const int a[], int n, int i, int depth) {
  indent(depth); cout << "sum(i=" << i << ")\n";
  if (i == n) {
    indent(depth); cout << "base return 0\n";
    return 0;
  }
  int ans = a[i] + sumDbg(a, n, i + 1, depth + 1);
  indent(depth); cout << "return " << ans << "\n";
  return ans;
}

What to check when recursion breaks

  • Is there a base case?

  • Is the base case reachable?

  • Does input shrink every call?

  • Are you shrinking the correct direction?

  • Are you using valid indices/bounds?

Stack Overflow

What causes stack overflow?

  • Too many recursive calls → too many stack frames

  • Most common reasons:

    • Missing base case

    • Base case unreachable (no progress)

    • Progress goes in the wrong direction

Bug example: progress is wrong

int bad(int n) {
  if (n == 0) return 0;
  return bad(n + 1);
}

  • n increases forever

  • base case is never reached

How to avoid recursion crashes

  • Make progress obvious (n decreases, index increases, range shrinks)

  • Validate inputs (negative values, empty ranges)

  • Prefer shallow recursion when possible (divide by 2)

  • If depth can be huge, use iteration or an explicit stack

Review

Recursion checklist

  • Write the base case first

  • Ensure each call makes progress toward base case

  • Trace a small input by hand (0, 1, 2, 3)

  • If buggy, print the parameter each call (with indentation)

  • If slow, look for repeated work (memoization)

  • If too deep, consider iteration
