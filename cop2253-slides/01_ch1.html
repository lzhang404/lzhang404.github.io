Why Programming?

Why Learn Programming?

Programming is a way to give a computer exact instructions.

  • Computers are fast, but they do not guess what we meant

  • Programs are precise: small differences can change the result

  • Programming is problem solving: understand, plan, implement, test, improve

  • Java is general purpose: apps, tools, backend systems, Android, and education

Human Instructions vs Program Instructions

A human can fill in missing details. A computer needs every detail stated clearly.

Human instructionComputer needs
"Print the name nicely"Exact words, spaces, punctuation, and newline
"If the value is high"The exact cutoff for "high"
"Repeat until done"The exact condition that means done
"Read a number"Where the number comes from and what type it is

In programming, vague ideas must become exact steps.

Problem Solving Before Coding

Do not start with Java syntax. Start with the problem.

  • Input: What information is provided?

  • Output: What exactly should be printed?

  • Hand example: What should happen for one sample input?

  • Algorithm: What steps solve the problem?

  • Java code: Translate the steps after the plan is clear

Computers and Programs

What Is a Program?

A program is a sequence of instructions that a computer can run.

  • Source code: code written by humans in a .java file

  • Compiler: checks source code and translates it

  • Bytecode: .class output produced by the Java compiler

  • Java Virtual Machine: runs the bytecode on your computer

Java's Two-Step Translation Model

Java uses a source-code → bytecode → run model.

StepToolResult
1javacChecks .java source code and produces .class bytecode
2javaAsks the JVM to run the compiled class
3Program executionStatements inside main run and output appears

This model matters because the compiler can catch many mistakes before the program runs.

Java Workflow From File to Output

  • Write source code in a .java file

  • Compile the file

  • Fix syntax errors if compilation fails

  • Run the compiled class

  • Compare actual output with expected output

Braces Define Blocks

Braces group statements together.

BraceMeaning
{Start a block
}End a block
Class blockContains the program's methods
Method blockContains statements that run

If a brace is missing, the compiler may complain later than you expect.

Semicolons End Statements

public class SemicolonDemo {
    public static void main(String[] args) {
        System.out.println("This statement ends with a semicolon.");
        System.out.println("So does this one.");
    }
}

  • Most Java statements end with a semicolon

  • Missing semicolons are one of the first syntax errors students see

  • Class headers and method headers do not end with semicolons

Basic Input

Reading Keyboard Input With Scanner

import java.util.Scanner;

public class ReadOneNumber {
    public static void main(String[] args) {
        Scanner scnr = new Scanner(System.in);
        int value = scnr.nextInt();
        System.out.println(value);
    }
}

  • Scanner lets a program read keyboard input

  • new Scanner(System.in) connects the scanner to standard input

  • nextInt() reads the next integer token

  • example: ReadOneNumber.java

Scanner Reads Tokens

A token is a chunk of input separated by whitespace.

InputFirst tokenSecond tokenThird token
Pat Morgan LeePatMorganLee
42 17 942179
Hello WorldHelloWorld

next() reads one string token. nextInt() reads one integer token.

Input + Output Example: Married-Couple Names

import java.util.Scanner;

public class MarriedCoupleNames {
    public static void main(String[] args) {
        Scanner scnr = new Scanner(System.in);

        String firstName1 = scnr.next();
        String firstName2 = scnr.next();
        String lastName = scnr.next();

        System.out.println(firstName1 + " and " + firstName2 + " " + lastName);
    }
}

  • The three next() calls read three tokens

  • The last line builds the exact output text

  • example: MarriedCoupleNames.java

Comments and Whitespace

Comments Explain Code to Humans

public class CommentDemo {
    public static void main(String[] args) {
        // This line prints one message.
        System.out.println("Comments are ignored by Java.");
    }
}

  • A line comment starts with //

  • Java ignores comments when the program runs

  • Good comments explain purpose, not every obvious detail

Whitespace in Source Code

Java usually ignores extra spaces in source code, but people do not.

public class GoodStyle {
    public static void main(String[] args) {
        System.out.println("Readable");
    }
}
public class HardToRead {
    public static void main(String[] args) { System.out.println("Works, but hard to read"); }
}

Readable formatting helps you find mistakes faster.

Whitespace in Output

public class WhitespaceDemo {
    public static void main(String[] args) {
        System.out.println("Hello World");
        System.out.println("Hello  World");
        System.out.print("Hello");
        System.out.println("World");
    }
}

  • Spaces inside quotes are printed

  • print and println change line breaks

  • Whitespace in output can decide whether an answer is accepted

  • example: WhitespaceDemo.java

Errors and Debugging

Four Common Problem Types

Problem typeWhen foundExample
Syntax errorCompilerMissing semicolon, missing brace, misspelled keyword
Runtime errorWhile program is runningProgram crashes because input is not what the program expected
Logic errorProgram runs but behavior is wrongStatements are in the wrong order
Output-format errorWhen comparing outputExtra prompt, missing newline, wrong capitalization

Different error types require different debugging strategies.

Syntax Error Example

public class BaseballBroken {
    public static void main(String[] args) {
        int runs = 7
        System.out.println("Runs: " + runs);
    }
}

  • This program is missing a semicolon after 7

  • The compiler may point near the next line because it was still reading the statement

  • Fix the first compiler error first

  • example: BaseballBroken.java

Logic Error Example

public class LogicErrorDemo {
    public static void main(String[] args) {
        System.out.println("Step 2: Mix ingredients");
        System.out.println("Step 1: Add water");
    }
}

  • This program compiles and runs

  • The output is still wrong because the steps are in the wrong order

  • The compiler checks syntax, not whether your instructions make sense

A Practical Debugging Loop

StepQuestion to ask
1. CompileWhat is the first compiler error?
2. Run one simple inputDid the program crash?
3. Compare outputWhat is different from expected output?
4. Trace the stepsWhat statement runs first, second, third?
5. Change one thingDid this specific change improve the result?

Do not randomly change code. Use evidence from errors and output.

Summary

Key Takeaways

  • Programming means turning an idea into exact steps

  • A Java application starts in main

  • The compiler checks source code before the JVM runs bytecode

  • print stays on the same line; println moves to a new line

  • Scanner can read simple input tokens

  • Comments and formatting help humans read code

  • Syntax errors, runtime errors, logic errors, and output-format errors are different problems
