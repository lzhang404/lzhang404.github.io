Why Generics

The Problem Without Generics

Before generics, collections stored values as Object.

  • The collection did not remember what type it was supposed to contain.

  • Different types could accidentally be placed in the same collection.

  • Values had to be cast when they were retrieved.

  • A wrong type might not fail until runtime.

Generics allow Java to catch many of these mistakes during compilation.

Raw Type Problem

A raw collection does not protect the type of its contents.

List accounts = new ArrayList();

accounts.add(new BankAccount());
accounts.add("my savings");   // Allowed by the compiler.

BankAccount b =
    (BankAccount) accounts.get(1);

The cast compiles, but the program fails at runtime because the object is actually a String.

Parameterized Collections

A parameterized collection states what type it should contain.

List<BankAccount> accounts = new ArrayList<>();

accounts.add(new BankAccount());

accounts.add("my savings");   // Compile-time error.

BankAccount b = accounts.get(0);

  • The compiler knows that accounts should contain BankAccount objects.

  • An invalid insertion is rejected immediately.

  • No cast is needed when retrieving an element.

  • Example: RawVsGeneric.java

Generics Move Errors Earlier

The main benefit is compile-time type checking.

Without Generics With Generics
Values treated as Object Expected type is known
Manual casts required Usually no cast needed
Wrong type may fail at runtime Wrong type usually fails at compile time
Less readable intent Type is visible in the declaration

Key idea: generics make reusable code safer without giving up type checking.

Type Parameters

Reading Type Parameters

The name inside angle brackets is a placeholder for a type.

Symbol Common Meaning Example
E Element ArrayList<E>
T Type Box<T>
K Key Map<K, V>
V Value Map<K, V>

List<String> means a list whose element type is String.

Using Generic Types

A concrete type replaces the type parameter when the generic type is used.

ArrayList<BankAccount> accounts =
    new ArrayList<>();

HashMap<String, Integer> scores =
    new HashMap<>();

  • For ArrayList<BankAccount>, the element type is BankAccount.

  • For HashMap<String, Integer>, keys are String and values are Integer.

  • The diamond <> lets the compiler infer the type on the right side.

Reference Types Only

Generic type arguments must be reference types.

List<Integer> numbers = new ArrayList<>();
List<Double> prices = new ArrayList<>();

// Not allowed:
// List<int> values = new ArrayList<>();

Use wrapper classes such as Integer, Double, and Boolean instead of primitive types.

Generic Classes and Methods

Generic Class

A generic class can work with different types without rewriting the class.

public class Pair<T, U> {
    private T first;
    private U second;

    public Pair(T first, U second) {
        this.first = first;
        this.second = second;
    }

    public T getFirst() {
        return first;
    }

    public U getSecond() {
        return second;
    }
}

Using a Generic Class

The type parameters become concrete types when an object is declared.

Pair<String, BankAccount> result =
    new Pair<>("Harry", harrysChecking);

String name = result.getFirst();

BankAccount account = result.getSecond();

  • T becomes String.

  • U becomes BankAccount.

  • The compiler checks both types.

  • Example: Pair.java

Generic Method

A method can declare its own type parameter.

public static <T> void printArray(T[] values) {
    for (T value : values) {
        System.out.println(value);
    }
}

The <T> before the return type declares the method's type parameter.

Calling a Generic Method

The compiler usually infers the type from the argument.

String[] names = {"Alice", "Bob"};

Integer[] scores = {90, 85};

printArray(names);   // T = String

printArray(scores);  // T = Integer

The same method works safely with different reference types.

  • Example: GenericMethodDemo.java

Bounds and Wildcards

Type Bounds

A bound restricts which types can replace a type parameter.

public class Box<T extends Number> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public double asDouble() {
        return value.doubleValue();
    }
}

T extends Number means that T must be Number or one of its subclasses.

Why Use a Bound?

A bound tells the compiler what operations are safe for the type parameter.

Box<Integer> count = new Box<>(10);

Box<Double> price = new Box<>(12.5);

// Not allowed:
// Box<String> name = new Box<>("Alice");

Because every allowed type is a Number, the class can safely call methods such as doubleValue().

  • Example: Box.java

Wildcards

A wildcard means that the exact generic type is not specified here.

Class<?> clazz = String.class;

List<? extends Number> numbers =
    List.of(1, 2, 3);

Number n = numbers.get(0);

  • ? means an unknown type.

  • ? extends Number means some type that is Number or a subtype of Number.

  • You will often see wildcards when reading framework and reflection APIs.

  • Example: Box.java

Type Erasure

Compile Time vs Runtime

Most generic type checking happens during compilation.

  • The compiler uses generic information to check types.

  • At runtime, much of the type-parameter information is erased.

  • An unbounded type variable such as T is generally erased to Object.

  • A bounded type variable is erased to its bound.

Type Erasure Example

An unbounded type variable is replaced by Object after erasure.

class Box<T> {
    T value;
}

Conceptually, the runtime representation is similar to:

class Box {
    Object value;
}

The compiler still uses the original generic declaration to enforce type safety in your source code.

Erasure With a Bound

If a type variable has a bound, the bound is used during erasure.

class Box<T extends Number> {
    T value;
}

Conceptually, the erased field is similar to:

class Box {
    Number value;
}

This is one reason generic type information behaves differently at runtime than normal class information.

Runtime Type Checking

Because the element type is erased, Java cannot normally test it directly at runtime.

if (obj instanceof List<?> list) {
    System.out.println("This object is a List.");
}

// Not allowed:
// obj instanceof List<String>

At runtime, Java can determine that the object is a List, but not reliably that it is specifically a List<String>.

  • Example: TypeErasureDemo.java

Raw Types

What Is a Raw Type?

A raw type uses a generic class without specifying its type parameter.

List list = new ArrayList();              // Raw type

List<String> names = new ArrayList<>();  // Parameterized type

Raw types mainly exist for compatibility with Java code written before generics were introduced.

Why Raw Types Are Dangerous

Raw types remove much of the compile-time type checking provided by generics.

List<String> names = new ArrayList<>();

List raw = names;

raw.add(123);   // Warning, but allowed.

String first = names.get(0);

The collection was intended to contain strings, but using the raw reference allowed another type to enter it.

  • Example: RawVsGeneric.java

Best Practice

// Preferred
List<String> names = new ArrayList<>();

Map<String, Integer> scores = new HashMap<>();

// Avoid
List names2 = new ArrayList();

Map scores2 = new HashMap();

Rule: use parameterized types unless you are working with legacy code that requires a raw type.

Generics in This Course

You Have Already Seen Generics

Generics appear throughout Java libraries and frameworks.

List<String> words;

ObservableList<PieChart.Data> pieData;

EventHandler<ActionEvent> handler;

Class<?> clazz;

The angle brackets are not special syntax for one library. They all use the same Java generics system.

Generics in the Course

Topic Examples
Reflection Class<?>
Spring / REST List<Product>, ResponseEntity<Product>
Persistence List<Entity>, repository result types
Concurrency Callable<T>, Future<T>

The important skill is being able to read what the type parameter represents.

Reading a Generic API

When you encounter an unfamiliar generic class, first identify what each type parameter represents.

Future<String> result;

Callable<Integer> task;

Map<String, List<Student>> courses;

  • Future<String>: the future result will be a String.

  • Callable<Integer>: the task produces an Integer.

  • Map<String, List<Student>>: each string key maps to a list of students.

Summary

Key Takeaways

  • Generics provide compile-time type safety for reusable classes and methods.

  • Type parameters such as T, E, K, and V stand for types supplied later.

  • A generic class defines type parameters for the class; a generic method can define its own.

  • Bounds restrict which types are allowed.

  • Type erasure means much of the generic type information is not available directly at runtime.

  • Avoid raw types because they remove useful compiler checks.
