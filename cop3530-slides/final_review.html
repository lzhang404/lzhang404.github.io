Modular Development

Drivers vs modules

  • Driver: has main; produces an executable; one per program or per test

  • Module: reusable code with no main; consists of a header (.hpp) and implementation (.cpp)

  • Header: declares the interface (class declarations, function prototypes)

  • Source: defines the implementation and #includes its own header

  • Templates are header-only: declaration and definition both in .hpp; no separate .cpp

  • When reading a test file, identify the exact header filename to #include, the exact class name (case-sensitive), and every method called on objects of that class

Header guards

  • Prevent a header from being included more than once in the same translation unit

  • Without them, multiple #includes cause redefinition errors

  • Three-keyword pattern: #ifndef, #define, and #endif

#ifndef MY_HPP    // if the macro is not yet defined ...
#define MY_HPP    // define it now

// class declarations, templates, function prototypes

#endif            // end of guard

  • Know which keyword goes where: #ifndef first (the "if not defined" check), #define second, #endif last

C++ build pipeline and testing

  • Preprocessing: expands macros and #include directives; produces one translation unit

  • Compiling: translates to an object file (.o); flag: -c

  • Linking: combines object files, resolves references, produces the executable

  • assert: halts with an error message if the condition is false

  • Framework style (Catch2-like): uses REQUIRE / CHECK; test run continues after a failure

Memory Management

Memory regions

  • Code (text): compiled instructions; read-only at runtime

  • Global / static: global and static variables; allocated at program start

  • Stack: local variables and function frames; managed automatically; limited size

  • Heap: objects allocated with new; managed manually; large but can fragment

  • Stack grows toward the heap; when they meet you get a stack overflow (e.g., infinite recursion with no base case)

Dynamic allocation: new and delete

// single object
MyClass* p = new MyClass();
delete p;            // correct

// array
int* a = new int[10];
delete[] a;          // correct: brackets required

// WRONG: delete a;  // undefined behavior: missing []

  • Always match form to form: new[] must be released with delete[]; omitting the brackets compiles silently but is undefined behavior

Rule of Three

  • Any class that owns a raw pointer member needs all three of:

    • Destructor: release the resource when the object is destroyed

    • Copy constructor: deep-copy when initializing from another object

    • Copy assignment operator: deep-copy on =

  • Without these, compiler-generated defaults do shallow copies: two objects share the same pointer, causing double-free or use-after-free

  • Rule of Five adds: move constructor and move assignment operator (C++11)

  • If a class has a raw pointer member but only a constructor, the missing pieces are: destructor, copy constructor, and copy assignment operator

Algorithm Analysis

T(N): counting basic steps

  • T(N) counts the number of basic operations as a function of input size N

  • A for (int i = 0; i < N; i++) loop: init runs once, condition runs N+1 times, update runs N times, body runs N times

int positives = 0;             // 1 step
for (int i = 0; i < n; i++)   // condition: n+1, update: n
    if (array[i] > 0)          // n comparisons
        positives += 1;        // 0 to n increments (depends on data)

  • Whether the if-body runs on every iteration determines best vs worst case; rewrite to a while loop if it helps you count more clearly

Big-O, Big-Omega, Big-Theta

  • O(f(n)): upper bound; runs at most this fast

  • Omega(f(n)): lower bound; takes at least this long

  • Theta(f(n)): tight bound; both upper and lower match; the most precise characterization

  • Rules: drop constants, drop lower-order terms, keep the dominant term

  • For T(n) = 3.5n + n² + 1, the dominant term is n²: Theta(n²) is the tightest bound; O(n²) is a valid upper bound; O(n) alone is not a valid bound because n² grows faster than n

Recursion tree analysis

  • The recursion tree visualizes how work is distributed across recursive calls

  • Total cost = (work per level) × (number of levels)

  • Key: identify the depth and the total work done across all nodes at each level

  • A tree with log₂(N) levels and N total work per level costs Theta(N log N); this is the recursion tree for merge sort

Templates

Function templates

  • Purpose: code reuse for different data types without duplicating the algorithm

  • The compiler instantiates a concrete version for each type used at a call site

  • Templates exist for code reuse across different data types, not to reduce the number of unit tests or to avoid compiler errors in general

template <typename T>
T tripleMin(T a, T b, T c) {
    T m = a;
    if (b < m) m = b;
    if (c < m) m = c;
    return m;
}

tripleMin(3, 1, 2);        // T = int
tripleMin(3.0, 1.5, 2.7);  // T = double

List ADT and Linked Lists

ADT vs implementation

  • An ADT defines what operations exist and what they mean, without specifying storage

  • A linked list is one concrete implementation of the List ADT using nodes and pointers

  • Common operations: Append, Prepend, InsertAfter, RemoveAfter, Remove(value), Contains

  • A hash table is a data structure, not an ADT: it specifies concrete storage details (array, hash function, collision resolution) and is not abstract

Singly-linked list: complexities

OperationComplexityNote
PrependO(1)Update head pointer
AppendO(1) with tailO(n) without tail pointer
InsertAfter (given node)O(1)Already have the position
RemoveAfter (given node)O(1)Already have the position
Search / ContainsO(n)Must scan from head
Remove(value)O(n)Must find the node first

  • A tail pointer enables O(1) append and is also the key addition that makes O(1) enqueue possible when implementing a queue on a linked list

Stack, Queue, and Deque

Stack ADT: LIFO

  • Insertion and removal both happen at the same end (the top)

  • LIFO: Last-In, First-Out

  • Core operations: push(x), pop(), peek(), isEmpty()

  • Applications: function call stack, undo/redo, iterative DFS, expression evaluation

  • A class that provides push_back, pop_back, and back can implement a Stack, because all three operations act on the same end

Queue ADT: FIFO

  • Insert at the rear; remove from the front: add and remove at different ends

  • FIFO: First-In, First-Out

  • Core operations: enqueue(x), dequeue(), peek(), isEmpty()

  • Applications: BFS traversal, CPU scheduling, print queues

  • To convert a singly-linked Stack (head pointer only) into a Queue efficiently, add a Node* tail pointer; without it, enqueue must traverse the entire list to reach the end

Array-based vs linked-list implementation

Quicksort: Hoare's partition scheme

  • Pick the middle element as the pivot value

  • Set cursors i = low and j = high (both ends of the range)

  • Move i right while arr[i] < pivot; move j left while arr[j] > pivot

  • If i <= j: swap arr[i] and arr[j], then advance both cursors

  • Repeat until i > j; return j as the partition boundary

Merge sort and linked lists

  • Merge sort: divide in half, sort each half recursively, merge. Always Theta(n log n)

  • Merge sort is the preferred sort for linked lists: splitting and merging work naturally on links; no random access is needed

  • For arrays, quicksort or a hybrid typically wins due to better cache behavior

CaseArrayLinked list
Small inputInsertion sortInsertion sort
Large inputQuicksort > Merge sortMerge sort (preferred)

Radix sort

  • Not comparison-based; sorts by digit position using a stable sort at each pass

  • LSD: process from the rightmost digit to the leftmost

  • Complexity: Theta(nk), where n is the number of elements and k is the number of digit positions

  • The number of rounds (collection passes) equals the number of digits in the maximum value; a 4-digit maximum means exactly 4 rounds regardless of how many elements there are

Hashing

Map ADT and hash tables

  • A map associates each unique key with a value

  • Core operations: insert(key, value), get(key), remove(key), contains(key)

  • A hash table is a concrete data structure implementing the map (or set) ADT

  • Pipeline: key → hash function → hash code → compression → table index

  • Average-case operations: O(1)

  • A hash table is not an ADT: it specifies concrete storage (array + hash function + collision resolution) and therefore has implementation details baked in

Collision handling: chaining

  • Each table slot holds a linked list of all items that hash to that index

  • Easy to represent; the table never becomes "full"

  • Degrades to O(n) if one bucket grows very long

Binary Search Tree (BST)

BST property and search

  • BST property: for every node, all values in its left subtree are smaller; all in its right subtree are larger

  • Search: compare key with current node; go left if smaller, right if larger; stop when found or null

  • BST search runs in O(h); the height is not always log n: it is O(log n) only for a balanced tree, and O(n) for a skewed tree

Node* search(Node* root, int key) {
    if (root == NULL || root->data == key)
        return root;
    if (key < root->data)
        return search(root->left, key);
    else
        return search(root->right, key);
}

BST insertion

Node* insert(Node* root, int key) {
    if (root == NULL) return new Node(key);
    if (key < root->data)
        root->left = insert(root->left, key);
    else if (key > root->data)
        root->right = insert(root->right, key);
    return root;
}

  • When tracing an insert, list every node visited from root to insertion point; at each node compare and go left or right; when the child is null, that is where the new node goes

BST deletion

  • No child: remove node directly

  • One child: bypass node, connect parent directly to that child

  • Two children: replace with the inorder successor (smallest value in the right subtree), then delete the successor

BST traversals

  • Inorder (left, root, right): visits nodes in ascending sorted order

  • Preorder (root, left, right): useful for copying or serializing the structure

  • Postorder (left, right, root): useful for freeing or deleting all nodes

  • Level order: breadth-first; uses a queue; visits level by level

void inorder(Node* root) {
    if (root == NULL) return;
    inorder(root->left);
    visit(root);        // middle
    inorder(root->right);
}
void preorder(Node* root) {
    if (root == NULL) return;
    visit(root);        // first
    preorder(root->left);
    preorder(root->right);
}

BST height and efficiency

  • All BST operations: O(h), where h is the height

  • Balanced: h = O(log n), so O(log n) per operation

  • Skewed: h = O(n), so O(n) per operation

  • Solutions: AVL, Red-Black, B-tree maintain balance automatically

Heaps

Heap properties and storage

  • Logically a complete binary tree: all levels full except possibly the last, filled left to right

  • Max-heap: every parent ≥ its children; root holds the maximum

  • Physically stored as a flat array; navigation by arithmetic, not pointers

  • Index formulas (0-based): left child = 2i+1, right child = 2i+2, parent = floor((i-1)/2)

  • A common misconception: the heap is a complete binary tree logically, but is physically stored as a flat array; there are no pointer fields, only index arithmetic

Heap insert and remove

  • Insert: add new value at the next open leaf; sift up (swap with parent) until heap property is restored

  • Remove (max/min): save root value; move last leaf to root; sift down (swap with larger child) until restored

  • Both cost at most one swap per level: O(log N)

  • Insert is O(log N) because a complete binary tree with N nodes always has height exactly floor(log₂N); the complete-tree shape guarantees this, unlike a BST

Heapify and heapsort

  • Heapify: convert an unsorted array into a valid heap in-place

    • Skip leaf nodes (indices floor(N/2) through N-1); they are already valid

    • Sift-down every internal node from index floor(N/2)-1 (the last internal node) down to 0

    • Tip: draw the tree from the array, locate where the heap property is violated, and fix bottom-up

    • Total cost: O(N), cheaper than N separate inserts

  • Heapsort: heapify (O(N)) + N-1 extract-max steps (O(N log N)) = O(N log N) total, in-place, not stable

Graphs

Graph terminology and types

  • Vertex: an entity; Edge: a connection; Degree: number of edges at a vertex

  • Trees are a special case of graphs: connected, undirected, and acyclic

  • Graph properties are independent; a single graph can be directed AND weighted AND cyclic simultaneously; check each property independently and select all that apply:

    • Directed or Undirected

    • Weighted or Unweighted

    • Cyclic or Acyclic

Adjacency list vs adjacency matrix

AspectAdjacency listAdjacency matrix
SpaceO(V + E)O(V²)
Check edge (u, v)O(degree of u)O(1)
List neighbors of uO(degree of u)O(V)
Best forSparse graphsDense graphs

  • For sparse graphs, the adjacency list has better time and space complexity: the matrix stores O(V²) entries even when most edges are absent, while the list uses only O(V+E)

BFS: breadth-first search

  • Uses a queue (FIFO): process closer vertices before farther ones

  • Mark vertices visited when enqueued, not when dequeued, to prevent a vertex from being pushed multiple times

void bfs(const Graph& g, int start) {
    queue<int> q;
    vector<bool> visited(g.size(), false);
    visited[start] = true;   // mark on enqueue
    q.push(start);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : g.adj[u])
            if (!visited[v]) {
                visited[v] = true;  // mark on enqueue
                q.push(v);
            }
    }
}

  • Time complexity: O(V + E)

DFS: depth-first search

  • Uses a stack (LIFO): dive deep along one path before backtracking

  • Can also be implemented recursively, using the call stack implicitly

  • The best-fit ADT for iterative DFS is a Stack; when tracing with lexical order, push unvisited neighbors in reverse alphabetical order so the smallest letter pops first

void dfs(const Graph& g, int u, vector<bool>& visited) {
    visited[u] = true;
    for (int v : g.adj[u])
        if (!visited[v])
            dfs(g, v, visited);
}

Dijkstra's algorithm

  • Finds shortest path distances from a source in a weighted graph with non-negative weights

  • Uses a min-heap priority queue storing (distance, vertex) pairs

  • Steps: init all distances to infinity except source = 0; repeatedly EXTRACT-MIN; relax neighbors; push updated pairs

  • Vertices are extracted in order of their final shortest distance

  • When answering a trace question, track two things separately: (1) the vertex extract-min order, and (2) the relaxed distance values after each extraction

Common misconceptions to watch out for

  • BST search is NOT always O(log n): only O(log n) for balanced trees; O(n) for skewed

  • Heap is NOT physically a tree: logically a complete binary tree, physically a flat array

  • Hash table is NOT an ADT: it is a concrete data structure implementing the Map/Set ADT

  • Binary search requires a sorted array: it does not work on an unsorted array

  • BFS marks visited on enqueue, not dequeue: marking on dequeue causes a vertex to be pushed multiple times

  • delete vs delete[]: using delete without brackets on an array is undefined behavior

  • Trees are special graphs: connected, undirected, and acyclic

  • Templates are header-only: no separate .cpp

Which ADT / data structure for what purpose?

  • BFS traversal: Queue (FIFO, level-by-level)

  • DFS traversal (iterative): Stack (LIFO, deep-path)

  • Always retrieve min or max efficiently: Heap / Priority Queue

  • O(1) average key-value lookup: Hash table

  • Sorted access and range queries: Balanced BST

  • Sorting a linked list: Merge sort (no random access needed)

  • Class with push_back / pop_back / back: which ADT?: Stack (add and remove at the same end)

  • Stack to Queue conversion: what to add?: A tail pointer for O(1) access to both ends
