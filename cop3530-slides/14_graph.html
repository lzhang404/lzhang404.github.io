Graph Basics

What is a graph?

A graph G = (V, E) consists of two sets.

  • Vertices (V) represent entities.

    • The Library and Cafe are vertices.

  • Edges (E) represent relationships between vertices.

    • The walkway between the Library and Cafe is an edge.

Graphs can model friendships or computer links.

Vertices, edges, and paths

  • Adjacent vertices share an edge.

    • The Library and Cafe are adjacent.

  • A path follows edges in sequence.

    • In an unweighted graph, path length counts edges.

    • Library → Cafe → Union has length 2.

  • A cycle returns to its starting vertex.

    • Only the starting vertex repeats.

    • No edge repeats.

    • Library → Cafe → Gym → Library is a cycle.

Directed and undirected edges

  • An undirected edge can be followed in either direction.

    • On the first map, Library–Cafe goes both ways.

  • Follow a directed edge in the arrow’s direction.

    • On this map, Library → Cafe is one-way.

    • To return, follow Cafe → Gym → Library.

  • Web links and course prerequisites are directed edges.

Degree of a vertex

  • In an undirected graph, degree counts the edges at a vertex.

    • Four orange edges meet at the Cafe.

    • The Cafe has degree 4.

  • In a directed graph, count incoming and outgoing edges separately.

    • In-degree counts arriving edges.

    • Out-degree counts departing edges.

    • Total degree is in-degree plus out-degree.

  • Maximum degree is the largest vertex degree.

Graph Properties and Types

Weighted graphs

  • A weight is a value on an edge.

    • A weight can represent distance, travel time, or cost.

  • A path’s total cost is the sum of its edge weights.

    • Union → Cafe → Gym costs 7 + 5 = 12.

    • Union → Dorm → Gym costs 2 + 2 = 4.

    • Both routes use two edges.

  • Direction and weight are independent.

    • This graph is both directed and weighted.

Cyclic and acyclic graphs

  • A cyclic graph contains at least one cycle.

    • Orange arrows trace Library → Cafe → Gym → Library.

    • Purple arrows trace Cafe → Bldg 4 → Union → Cafe.

  • An acyclic graph contains no cycles.

    • On the left, following arrows leads to Bldg 1.

Connectivity and edge density

  • Connected (undirected)

    • Every pair of vertices has a path.

  • Strongly connected (directed)

    • Every vertex can reach every other.

    • Follow the arrows.

  • Weakly connected (directed)

    • Every pair has a path with arrows ignored.

    • Strong connectivity implies weak connectivity.

  • Edge density

    • Fraction of possible edges present.

    • Sparse graphs have few edges.

    • Dense graphs have nearly all possible edges.

Graph Representation

Storing a graph in memory

  • An adjacency list stores each vertex’s neighbors.

  • An adjacency matrix uses a grid indexed by vertices.

  • Both examples use the same undirected graph.

    • Edges are A–B, A–C, B–C, and C–D.

    • Find A’s neighbors, B and C, in both representations.

Adjacency list

  • Store each undirected edge in both endpoint lists.

    • C lists D, and D lists C.

  • Space is O(V + E).

  • Scanning the list for u takes O(degree(u)).

    • An edge check may scan the entire unsorted list.

B: [A, C]
C: [A, B, D]
D: [C]

Adjacency matrix

  • Read row u, column v.

    • 1 means there is an edge.

    • 0 means there is no edge.

  • An undirected edge appears in two cells.

    • The matrix is symmetric.

  • An edge check takes O(1).

  • A weighted matrix stores edge weights.

Graph Traversals

Why traverse a graph?

  • Visit every vertex reachable from the start.

    • Can A reach B?

    • How many edges are in the shortest unweighted route?

  • Track visited vertices.

    • Process each vertex once.

    • Cycles can lead back to a vertex you already visited.

    • Several routes can reach the same vertex.

  • Restart at an unvisited vertex to continue the traversal.

Breadth-first search

  • BFS explores in layers.

    • Start at distance 0.

    • Visit vertices one edge away next.

    • Continue to distance 2 and beyond.

  • A FIFO queue processes earlier discoveries first.

  • The first discovery gives the minimum edge count.

    • Record the predecessor to recover a shortest path.

BFS steps

  1. Enqueue the start vertex.

    • Mark it discovered as it enters the queue.

  2. Dequeue the front vertex.

    • Process that vertex.

  3. Enqueue each undiscovered neighbor.

    • Mark each one as it enters the queue.

  4. Repeat until the queue is empty.

Marking on enqueue prevents duplicates.

BFS from A

  • Start at A.

  • Enqueue unseen neighbors in A–Z order.

  • The front of the queue is on the left.

BFS implementation

Mark each neighbor when it enters the queue.

void bfs(const Graph& g, int start) {
    queue<int> q;
    vector<bool> seen(g.size(), false);
    seen[start] = true;
    q.push(start);
    while (!q.empty()) {
        int u = q.front();
        q.pop();  // Process u here.
        for (int v : g.adj[u]) {
            if (seen[v]) continue;
            seen[v] = true;
            q.push(v);
        }
    }
}

Depth-first search

  • DFS follows a branch as far as possible.

    • Backtrack when there is no unvisited neighbor.

  • A LIFO stack takes the most recent entry first.

    • If you push B then C, C comes off first.

  • Recursive DFS backtracks by returning to the previous call.

Iterative DFS steps

  1. Push the start vertex.

  2. Pop the top entry.

    • Skip the entry if its vertex was already visited.

  3. Mark the vertex visited.

    • Process that vertex.

  4. Push each unvisited neighbor.

  5. Repeat until the stack is empty.

A vertex can be pending more than once.

Iterative DFS from A

  • Start at A.

  • Push unvisited neighbors alphabetically.

    • The last neighbor pushed is on top.

  • The top of the stack is on the right.

Iterative DFS implementation

Check for repeat visits when popping an entry.

void dfs(const Graph& g, int start) {
    stack<int> pending;
    vector<bool> visited(g.size(), false);
    pending.push(start);
    while (!pending.empty()) {
        int u = pending.top();
        pending.pop();
        if (visited[u]) continue;
        visited[u] = true;
        // Process u.
        for (int v : g.adj[u]) {
            if (!visited[v]) pending.push(v);
        }
    }
}

Recursive DFS implementation

Each call explores one unvisited neighbor at a time.

void dfsHelper(const Graph& g, int u,
               vector<bool>& visited) {
    visited[u] = true;
    // Process u.
    for (int v : g.adj[u]) {
        if (!visited[v]) dfsHelper(g, v, visited);
    }
}

void dfs(const Graph& g, int start) {
    vector<bool> visited(g.size(), false);
    dfsHelper(g, start, visited);
}

  • Returning from a call backtracks.

  • With alphabetical neighbors, recursion visits B before C.

  • The stack example visits C before B.

Dijkstra’s Shortest Path Algorithm

Fewest edges and lowest cost

  • Compare two routes from A to D.

    • A → B → D uses 2 edges.

      • Total cost is 4 + 10 = 14.

    • A → C → E → D uses 3 edges.

      • Total cost is 2 + 3 + 4 = 9.

  • BFS minimizes the number of edges.

  • Dijkstra’s algorithm minimizes total cost.

    • Start from one source.

    • Use non-negative edge weights.

Tentative distances and relaxation

  • A tentative distance is the best cost found so far.

  • Relax u → v to test a route to v through u.

    • Compute distance to u plus the edge weight.

    • Use the smaller distance if the route improves.

    • Record u as v’s predecessor when the distance improves.

  • A min-priority queue selects the smallest tentative distance.

    • Popping the smallest current entry finalizes its distance.

    • A competing route must first reach an unfinished vertex.

    • We already checked exits from finalized vertices.

    • Non-negative edges cannot lower a route’s cost.

Dijkstra’s algorithm steps

  1. Initialize the distances.

    • Set the source to 0.

    • Set all other distances to ∞.

    • Push (0, source).

  2. Pop the smallest entry (d, u).

    • Skip a stale entry if d differs from the current distance to u.

  3. Finalize u.

    • Relax each outgoing edge.

    • Save each better distance.

    • Update its predecessor.

    • Push the new entry.

  4. Repeat until the queue is empty.

    • Unreachable vertices keep distance ∞.

Dijkstra implementation

  • The min-heap stores (distance, vertex) pairs.

  • The function returns distances.

  • It records predecessors in prev.

vector<long long> dijkstra(const WeightedGraph& g,
                           int start, vector<int>& prev) {
    vector<long long> dist(g.size(), LLONG_MAX);
    prev.assign(g.size(), -1);

    using Entry = pair<long long, int>;
    priority_queue<Entry, vector<Entry>,
                   greater<Entry>> pq;

    dist[start] = 0;
    pq.push({0, start});

    while (!pq.empty()) {
        long long d = pq.top().first;
        int u = pq.top().second;
        pq.pop();
        if (d != dist[u]) continue;  // Stale entry.

        for (const auto& edge : g.adj[u]) {
            int v = edge.first;
            long long candidate = d + edge.second;
            if (candidate >= dist[v]) continue;

            dist[v] = candidate;
            prev[v] = u;
            pq.push({candidate, v});
        }
    }
    return dist;
}

Dijkstra time complexity

  • An adjacency list lets us scan each outgoing edge once.

  • A binary min-heap holds tentative entries.

    • Relaxations add at most O(E) entries.

    • On a simple graph, each heap operation costs O(log V).

  • Adjacency lists plus a min-heap take O((V + E) log V).

  • Scanning an array for the next vertex takes O(V²) overall.

When Dijkstra applies

  • Dijkstra requires non-negative weights.

    • A negative edge can improve an already finalized distance.

  • Bellman–Ford supports negative edges.

    • It can detect a reachable negative cycle.

  • A reachable negative cycle lets a route keep getting cheaper.

    • Destinations reachable from that cycle have no finite minimum cost.

Wrap-up

Choosing a graph algorithm

  • An adjacency list makes neighbor scans efficient.

  • An adjacency matrix gives constant-time edge checks.

  • BFS finds a route with the fewest edges.

    • A queue explores by layers.

    • Record a predecessor on first discovery.

  • DFS explores branches and backtracks.

    • Use a stack or recursion.

  • Dijkstra finds minimum cost with non-negative weights.

    • A min-priority queue selects the smallest tentative distance.

    • Record a predecessor when a distance improves.
