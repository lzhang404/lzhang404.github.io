Method Definitions

Method Vocabulary

A method is a named block of code that performs one clear task.

  • method definition: the complete method, including the header and the body.

  • method header: the first line of the method definition. It gives the access, static keyword if used, return type, method name, and parameter list.

  • method call: a statement or expression that runs the method.

  • parameter: a variable in the method header that receives a value when the method is called.

  • argument: the actual value sent into the method call.

  • return type: the type of value the method sends back, or void if it sends back nothing.

  • method body: the statements inside the braces that tell the method what to do.

Method Header Syntax

The method header is the first line of a method definition.

public static double circleArea(double radius)

  • public: other code is allowed to call this method.

  • static: this method belongs to the class. In this chapter, that lets main call it directly.

  • double: this method returns a double value.

  • circleArea: this is the method name.

  • double radius: this method receives one double value.

Reading Method Headers

public static void printHeader(String title)
public static double circleArea(double radius)
public static boolean isValidScore(double score)
private static double weeklySalary(double hourlyRate, double hours)

  • printHeader performs an action and returns nothing.

  • circleArea receives one number and returns one number.

  • isValidScore returns true or false.

  • weeklySalary receives two numbers and returns one number.

  • private means this method is intended for use inside the same class.

Method Definition vs. Method Call

The definition creates the method. The call runs it.

public static void printCourseName(String courseName){...}

printCourseName("COP 2253");

  • The first line is a method header from a method definition.

  • String courseName is the parameter.

  • The second line is a method call.

  • "COP 2253" is the argument sent into the parameter.

  • The argument type must match the parameter type.

Example: Simple Method Calls

This example uses two small helper methods and one main method.

public class MethodBasics {
    public static void printGreeting() {
        System.out.println("Welcome to Java methods.");
    }

    public static void printCourseName(String courseName) {
        System.out.println("Course: " + courseName);
    }

    public static void main(String[] args) {
        printGreeting();
        printCourseName("COP 2253");
        printGreeting();
    }
}

  • printGreeting() has no parameters.

  • printCourseName(...) receives one String.

  • main calls both helper methods.

  • example: MethodBasics.java

Void Methods and Value-Returning Methods

Void Methods Perform Actions

A void method performs an action but does not send a value back.

public static void printLine()
public static void printHeader(String title)
public static void printReceipt(double total)

  • The return type is void.

  • The method may print output or update something.

  • The method call is usually written as its own statement.

  • A void method cannot be used where a value is needed.

  • example: PrintMethods.java

Value-Returning Methods Produce One Result

A value-returning method computes a result and sends it back with return.

public static double circleArea(double radius)
public static int maxOfThree(int first, int second, int third)
public static boolean isVowel(char ch)

  • The return type is not void.

  • The method must return a compatible value.

  • The caller can store the returned value in a variable.

  • The caller can use the returned value inside a larger expression.

Return Statement

The return statement finishes the method and sends one value back.

public static double circleArea(double radius) {
    return Math.PI * radius * radius;
}

double area = circleArea(3.0);

  • The expression after return must match the method return type.

  • Here the returned value is a double.

  • The variable area receives the result.

  • example: MathMethods.java

Incorrect Method Example: Missing Return

This method promises to return a double, but it ends without returning one.

public class MissingReturnBroken {
    public static double celsiusToFahrenheit(double celsius) {
        double fahrenheit = (9.0 / 5.0) * celsius + 32.0;
    }

    public static void main(String[] args) {
        System.out.println(celsiusToFahrenheit(50.0));
    }
}

  • The header says the method returns double.

  • The calculation creates a local variable named fahrenheit.

  • The method needs return fahrenheit; before it ends.

  • example: MissingReturnBroken.java

Corrected Method Example

The corrected version sends the computed value back to the caller.

public static double celsiusToFahrenheit(double celsius) {
    double fahrenheit = (9.0 / 5.0) * celsius + 32.0;
    return fahrenheit;
}

  • The return type is double.

  • The returned expression is a double value.

  • The caller can print, store, or use the returned value.

  • example: CelsiusConversion.java

Method Calls and Parameters

Arguments and Parameters

The caller sends arguments. The method receives those values in parameters.

printCourseName("COP 2253");

public static void printCourseName(String courseName)

  • "COP 2253" is the argument.

  • courseName is the parameter.

  • The parameter is a local variable inside the method.

  • The argument type must match the parameter type.

Method Call Flow

When Java reaches a method call, execution temporarily jumps to that method.

  • Java evaluates the arguments in the method call.

  • Java copies the argument values into the parameters.

  • The method body runs from top to bottom.

  • For a value-returning method, return sends one value back.

  • Execution continues after the original method call.

Primitive Parameters Are Copies

When an int, double, char, or boolean is passed to a method, the method receives a copy.

public static void swap(int first, int second)

  • first and second are local copies inside the method.

  • Changing the copies does not change the original variables in main.

  • This is why a basic swap method does not swap two int variables in the caller.

  • example: SwapAttempt.java

Methods with Decisions, Loops, and Input

Methods with Branches

A method can contain an if statement when the task includes a decision.

public static double calculateShipping(double orderTotal)

  • The method receives the order total.

  • The method decides which shipping cost applies.

  • The method returns one shipping cost.

  • The branch belongs in the method because the decision is part of the shipping calculation.

  • example: ShippingCost.java

Methods with Loops

A method can contain a loop when the task must repeat.

public static int countVowels(String text)

  • The method receives a String.

  • The loop visits each character in the string.

  • The method counts characters that are vowels.

  • The method returns the final count.

  • example: CountVowels.java

Parameter Error Checking

A method should check parameter values before doing risky work.

public static double averageScore(int totalPoints, int numberOfScores)
public static boolean isValidPercentage(double percentage)

  • averageScore should not divide by zero.

  • isValidPercentage checks whether a score is between 0 and 100.

  • Put simple error checks near the beginning of the method.

  • example: ParameterCheck.java

Using Scanner in Methods

Use one Scanner for System.in, then pass that Scanner to helper methods.

public static int readPositiveInt(Scanner scnr, String prompt)

  • The caller creates the Scanner.

  • The method receives the Scanner as a parameter.

  • The method can read one valid value and return it.

  • Avoid creating many Scanners for System.in in one program.

  • example: ScannerMethod.java

Scope, Access, and Static Members

Variable Scope

Scope means where a name can be used in a program.

  • A local variable is declared inside a method or block.

  • A parameter is local to the method that receives it.

  • A class-level variable is declared inside the class but outside any method.

  • A local variable stops existing when its method or block finishes.

  • Use the smallest reasonable scope so the program is easier to read.

Method Definition Scope

In this course, method definitions belong inside the class, not inside another method.

public class MethodLayout {
    public static void main(String[] args) {
        helperMethod();
    }

    public static void helperMethod() {
        System.out.println("Helper method");
    }
}

  • main is one method.

  • helperMethod is another method in the same class.

  • Do not define one method inside another method.

  • Both method definitions are class members.

public and private

public and private control access.

  • public means other code is allowed to call the method.

  • private means only code inside the same class is allowed to call the method.

  • A helper method is often private because it supports the class internally.

  • A method that the outside program needs to use is usually public.

  • Access control keeps the program organized and protects implementation details.

static Members

static means the member belongs to the class itself.

  • A static method can be called through the class, without creating an object.

  • A static field is shared by all objects of the class.

  • Anything declared static is class-level, not object-level.

Scope Example

This example uses a class constant, parameters, and a local variable.

public class ScopeExample {
    public static final int INCHES_PER_FOOT = 12;

    public static double heightToCentimeters(int feet, int inches) {
        int totalInches = feet * INCHES_PER_FOOT + inches;
        return totalInches * 2.54;
    }
}

  • INCHES_PER_FOOT is a class-level constant.

  • feet and inches are parameters.

  • totalInches is a local variable inside the method.

  • example: ScopeExample.java

Overloading, Documentation, and Testing

Method Overloading

Overloading means using the same method name with different parameter lists.

public static int square(int value)
public static double square(double value)
public static int square(int value, int times)

  • The method name is the same.

  • The parameter lists are different.

  • Java chooses the method by matching the arguments in the call.

  • Use overloading only when the methods represent the same basic idea.

  • example: OverloadMethods.java

Java Documentation for Methods

A method comment explains the method from the caller's point of view.

/**
 * Returns the largest of three integer values.
 * @param first the first value
 * @param second the second value
 * @param third the third value
 * @return the largest value
 */
public static int maxOfThree(int first, int second, int third)

  • @param explains each parameter.

  • @return explains the value sent back.

  • The comment should describe behavior, not just repeat the code.

Unit Testing Methods

Unit testing means checking one method with small, specific test cases.

  • Test normal cases first.

  • Then test edge cases, such as zero, negative numbers, or equal values.

  • A value-returning method is easy to test because the result can be compared to an expected value.

  • When the method changes, run the tests again.

  • example: UnitTesting.java

Common Method Errors

Method errors often come from a mismatch between the header, the body, and the call.

  • Wrong number of arguments.

  • Wrong argument type.

  • Using a void method as if it returned a value.

  • Forgetting to return a value from a value-returning method.

  • Returning a value whose type does not match the method header.

Summary

Key Takeaways

  • A method is a named block of code that performs one task.

  • A method header tells Java how the method can be called.

  • Arguments are sent by the caller; parameters receive those values inside the method.

  • A void method does not return a value.

  • A value-returning method must return a compatible value.

  • Scope controls where names can be used.

  • public and private control access.

  • static means the member belongs to the class, not one individual object.

  • Testing small methods makes larger programs easier to debug.
