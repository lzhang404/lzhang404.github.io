Example Program and Memory Regions

This example uses static memory, the stack, and the heap.

public class MemoryRegionEx {
    public static int myStaticField = 33;

    public static void myMethod() {
        int myLocal;
        myLocal = 999;
        System.out.print(" " + myLocal);
    }

    public static void main(String[] args) {
        int myInt;
        Integer myInteger = null;

        myInt = 555;
        myInteger = new Integer(222);

        System.out.print(myInteger.intValue()
                + " " + myInt);

        myInteger = null;
        myMethod();
    }
}

Where the important values go:

Static memory
myStaticField = 33
Stack
main(): myInt = 555
main(): myInteger →
myMethod(): myLocal = 999
Heap
Integer object: 222

  • myInteger is a reference variable.

  • new Integer(222) creates the heap object.

The Stack

The Stack Stores Local Variables

The stack stores local variables while a method is running.

public static void myMethod() {
    int myLocal;
    myLocal = 999;
    System.out.print(" " + myLocal);
}
Stack while myMethod() is running
myMethod(): myLocal = 999
main(): myInt = 555
main(): myInteger

  • myLocal exists while myMethod() is running.

  • When myMethod() returns, myLocal is removed.

Method Calls Add and Remove Stack Frames

A method call adds local variables to the stack. A method return removes them.

main() starts
→
myMethod() called
→
myLocal added
→
myMethod() returns
→
myLocal removed

  • This is automatic memory management.

  • The programmer does not manually remove local variables.

  • The local variables disappear when the method returns.

The Heap

new Creates an Object on the Heap

The heap stores objects created with new.

Integer myInteger = null;

myInteger = new Integer(222);

  • myInteger is a local reference variable.

  • The reference variable is on the stack.

  • The Integer object is on the heap.

Stack
myInteger →
Heap
Integer object: 222

Reference Variable Versus Object

A reference variable is not the object itself.

myInteger
reference variable
→
Integer object
222

  • The reference variable stores a way to find the object.

  • The object stores the actual data.

  • Changing the reference variable does not directly erase the object.

null Means No Object

A reference variable can store null.

Integer myInteger = null;

  • null means the variable does not currently refer to an object.

  • If code tries to use an object through null, Java can throw NullPointerException.

References and Garbage Collection

Two References Can Point to One Object

Assigning one reference variable to another copies the reference, not the object.

Integer myInt = null;
Integer myOtherInt = null;

myInt = new Integer(10);
myOtherInt = myInt;
myInt
↘
Integer object

↙
myOtherInt

  • There is one heap object.

  • Two reference variables can reach it.

Setting One Reference to null

The object is still reachable if another reference points to it.

myInt = null;

  • myInt no longer refers to the object.

  • myOtherInt still refers to the object.

When No Reference Remains

An object becomes unreachable when no live reference can reach it.

myOtherInt = null;

  • Now myInt is null.

  • Now myOtherInt is also null.

  • No reference can reach the object.

What Is Garbage Collection?

Garbage collection is Java's automatic process for cleaning up heap objects that are no longer reachable.

Object is created
→
References point to it
→
No references remain
→
Object is eligible for cleanup

  • Java programmers usually do not manually free heap objects.

  • The Java Virtual Machine decides when garbage collection runs.

  • An unreachable object is not always removed immediately.

Scope and Memory

Local Variables Go Out of Scope

A local variable only exists while its method is running.

  • When a method starts, its local variables are created.

  • When a method returns, its local variables are removed.

  • If a local reference was the only way to reach an object, that object becomes unreachable.

Setting a local reference to null is not always necessary. Returning from the method can remove the reference automatically.

Local Reference in a Method

The method creates a local reference variable named binaryStr.

public class BitCounter {
    public static int countBits(int inNum) {
        int countInt;
        String binaryStr;

        binaryStr = Integer.toBinaryString(inNum);
        countInt = binaryStr.length();

        return countInt;
    }

    public static void main(String[] args) {
        int numBits;
        numBits = countBits(7);
    }
}

While countBits(7) is running:

Stack
countBits(): inNum = 7
countBits(): countInt = 3
countBits(): binaryStr →
main(): numBits
Heap
String object: "111"

  • binaryStr refers to the string object.

  • numBits will receive the returned value.

After the Method Returns

When countBits() returns, its local variables are removed from the stack.

  • numBits receives the returned value 3.

  • binaryStr goes out of scope.

  • If no other reference points to "111", the string object becomes unreachable.

Stack after return
main(): numBits = 3
countBits() frame removed
binaryStr is gone
Heap
String object may be unreachable

Summary

Key Takeaways

  • Code memory stores program instructions.

  • Static memory stores static fields.

  • The stack stores active method calls and local variables.

  • The heap stores objects created with new.

  • A reference variable is not the object itself.

  • null means a reference variable does not refer to an object.

  • An object becomes unreachable when no live reference can reach it.

  • Garbage collection can reclaim unreachable objects.

  • When a method returns, its local variables go out of scope.
