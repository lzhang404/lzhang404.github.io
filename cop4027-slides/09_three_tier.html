Separating the Two Jobs

Adding a task includes application work that can move out of the button handler.

  • The Controller reads the field and updates the screen.

  • The Model checks the title, asks the Repository to save, and reloads the task list.

  • The Repository continues to handle JDBC and SQL.

The Controller asks the Model to perform the operation with model.addTask(title).

The Refactored Code

Presentation: TaskController

The Controller delegates the operation and displays its outcome.

public void addClicked() {
    try {
        model.addTask(view.getEnteredTitle());
        view.showTasks(model.getTasks());
        view.clearEnteredTitle();
        view.setStatus("Task saved");
    } catch (IllegalArgumentException
             | RepositoryException exception) {
        view.setStatus(exception.getMessage());
    }
}

The Controller has no Repository field.

Example: three-tier/TaskController.java

Application: TaskModel

The Model checks the title, saves the task, and reloads its state.

public void addTask(String title) {
    if (title == null || title.isBlank()) {
        throw new IllegalArgumentException("Title required");
    }

    repository.add(title.trim());
    reload();
}

Every caller of addTask goes through the same title check.

Example: three-tier/TaskModel.java

Data: TaskRepository

The Model uses task storage operations through an interface.

public interface TaskRepository {
    List<TaskItem> findAll();
    void add(String title);
    void setDone(long id, boolean done);
    void delete(long id);
}

JdbcTaskRepository implements these methods with JDBC and SQL. JDBC objects stay inside that implementation.

Example: three-tier/TaskRepository.java and JdbcTaskRepository.java

Object Construction at Startup

The application creates the objects and passes each dependency through a constructor.

DatabaseConfig config =
        DatabaseConfig.load("/database.properties");
TaskRepository repository = new JdbcTaskRepository(config);

TaskModel model = new TaskModel(repository);
TaskView view = new TaskView();
TaskController controller = new TaskController(model, view);
controller.connectHandlers();

The Controller receives the Model and View. The Model receives the Repository. The View has no Model dependency.

Saving and Reloading the Task

  1. The Controller reads the field and calls model.addTask(title).

  2. The Model checks the title and calls repository.add(title.trim()).

  3. JdbcTaskRepository inserts the database row.

  4. The Model calls reload(), which reads tasks back through the Repository.

// TaskModel
private void reload() {
    tasks = List.copyOf(repository.findAll());
}

The Model now holds the saved tasks, including database-generated IDs.

Refreshing the Screen

After model.addTask returns successfully, the Controller passes the updated task list to the View.

// TaskController
view.showTasks(model.getTasks());

// TaskView
public void showTasks(List<TaskItem> tasks) {
    taskList.getItems().setAll(tasks);
}

The View displays the supplied tasks. The Controller then clears the field and displays Task saved.

Testing the Rule Without the Screen

The test defines an in-memory Repository and calls the Model directly.

TaskModel model = new TaskModel(new InMemoryTaskRepository());

assertThrows(IllegalArgumentException.class,
        () -> model.addTask("   "));

model.addTask("  Practice three-tier  ");
assertEquals("Practice three-tier",
        model.getTasks().getFirst().title());

This checks the title rule and saved state without JavaFX or a database.

Where Does Each Responsibility Belong?

Choose presentation, application, or data.

  2. Handle the Add button event.

  3. Reject a blank task title.

  4. Reload Model state after a change.

  5. Execute an INSERT statement.

Responsibility Check

  • Presentation: display the message and handle the button event.

  • Application: reject a blank title and coordinate reloading Model state.

  • Data: execute the SQL and map each row to a task.

TaskModel. The Controller displays the outcome, and the Repository performs storage operations.

Key Takeaways

  • The Controller handles user interaction and supplies display data to the View.

  • The Model owns task rules and coordinates persistence.

  • The Repository implementation owns JDBC and SQL.

  • Moving the operation into the Model makes it available to other callers and direct tests.
