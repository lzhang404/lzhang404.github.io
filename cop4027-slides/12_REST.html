From Button Clicks to HTTP Requests

Same Service, New Input

The Task List already has a Service. Today, a web request becomes a second way to call it.

JavaFX: button click → TaskController → TaskModel → TaskService
Web:    HTTP request → TaskApiController ─────────→ TaskService

  • The Service, Repository, and entity do not change.

  • Only the presentation tier gains a new entry point.

Clients and Servers

On the web, a client sends a request, and a server sends back a response.

client                       server
(browser, curl, an app)      (our Spring app)
        ── request  ──→
        ←── response ──

  • HTTP defines the format of these messages.

  • The server waits and only answers requests.

  • HTTP travels over TCP connections; the networking lecture covers that layer.

An HTTP Request

A request says what the client wants, where, and with what data.

POST /api/tasks HTTP/1.1
Host: localhost:8080
Content-Type: application/json

{"title": "Review REST"}

  • Request line: the method, the path, and the HTTP version.

  • Headers: extra details; Content-Type says the body is JSON.

  • Body: the data, if any. A GET request usually has none.

An HTTP Response

A response says what happened and carries the result.

HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/tasks/4

{"id": 4, "title": "Review REST", "done": false}

  • Status line: a status code and a short reason.

  • Headers: details such as the body format and the new task's URL.

  • Body: the result, here the created task.

Designing a REST API

What Makes an API RESTful?

An API is the set of requests a program accepts. REST is a style for designing web APIs around resources.

  • Resource: a thing the API manages, such as a task.

  • URL: names the resource, such as /api/tasks/4.

  • Method: says what to do with it.

  • Representation: the resource's data, usually JSON.

  • Stateless: each request carries everything the server needs.

URLs Name Things; Methods Name Actions

A REST URL is a noun. The HTTP method supplies the verb.

AvoidPrefer

POST /api/createTask

POST /api/tasks

GET /api/getTask?id=4

GET /api/tasks/4

POST /api/deleteTask?id=4

DELETE /api/tasks/4

Collections use plural nouns: /api/tasks is all tasks; /api/tasks/4 is one.

JSON Represents a Resource

The server sends a representation of the task: its data as JSON, not the Java object itself.

{
  "id": 4,
  "title": "Review REST",
  "done": false
}

  • Spring converts Java objects to JSON and back with Jackson, from the data formats lecture.

  • Each record component or getter becomes a JSON key.

A First Spring Web Controller

Spring Web Adds an HTTP Server

Adding the web starter turns the Boot app from the JPA lecture into a web server.

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

  • Boot starts an embedded Tomcat server on port 8080.

  • Jackson, for JSON, comes with the starter.

  • The TaskService and TaskRepository beans are still there.

How a Request Reaches a Method

Spring's DispatcherServlet receives every request and sends it to the matching controller method.

HTTP request
  → Tomcat
  → DispatcherServlet      finds the method by HTTP method + URL
  → TaskApiController.findAll()
  → return value → Jackson → JSON response

  • We write the controller method; Spring does the routing and the JSON conversion.

  • This part of Spring is Spring Web MVC.

@Controller vs. @RestController

Spring MVC applies the MVC idea from the desktop lecture to web requests. The two annotations differ in what the client gets back.

@Controller@RestController

Returns

A view name: an HTML page template

Data, written as JSON

Used for

Web pages rendered on the server

APIs for other programs

@RestController is @Controller plus @ResponseBody on every method. We build APIs, so we use @RestController.

The Web Controller

The web controller is a new presentation-tier class. It uses the same TaskService as the JavaFX side.

@RestController
@RequestMapping("/api/tasks")
public class TaskApiController {
    private final TaskService service;

    public TaskApiController(TaskService service) {
        this.service = service;
    }
}

  • @RequestMapping sets the base URL for every method in the class.

  • The name differs from the JavaFX TaskController, so both can exist.

  • Spring injects the Service through the constructor, as before.

Return Records, Not Entities

The API returns a response record instead of the entity, so the database design and the JSON can change separately.

public record TaskItemResponse(Long id, String title, boolean done) {
    public static TaskItemResponse from(TaskItem item) {
        return new TaskItemResponse(item.getId(), item.getTitle(), item.isDone());
    }
}

  • TaskItem could not be a record; request and response types can.

  • The record decides exactly which fields the client sees.

GET All Tasks

A @GetMapping method returns data. Spring turns the return value into JSON with status 200 OK.

@GetMapping
public List<TaskItemResponse> findAll() {
    return service.findAllTaskItems().stream()
            .map(TaskItemResponse::from)
            .toList();
}
curl http://localhost:8080/api/tasks
[{"id":1,"title":"Review REST","done":false}]

  • A list becomes a JSON array.

  • Opening the URL in a browser also sends a GET.

Takeaways: HTTP, REST, and a First Endpoint

  • A request has a method, a URL, headers, and an optional body; a response has a status code.

  • REST URLs name resources, and HTTP methods name the actions.

  • Spring Web MVC routes each request to a controller method and converts the result to JSON.

  • The web controller calls the same TaskService as the JavaFX side.

Reading Request Data

Recall

Answer from memory before we continue.

  1. Which method creates a resource? POST.

  2. What does 404 mean? The resource was not found.

  3. What turns a returned record into JSON? Jackson, called by Spring.

Path Variables: One Task

Part of the URL can be a value. @PathVariable copies it into a method parameter.

@GetMapping("/{id}")
public TaskItemResponse findOne(@PathVariable Long id) {
    return TaskItemResponse.from(service.getTaskItem(id));
}

  • GET /api/tasks/4 calls findOne(4L).

  • Spring converts the text "4" to a Long.

  • If task 4 does not exist, the Service throws an exception. We turn it into 404 later today.

Query Parameters: Filter Tasks

Optional settings go after ? in the URL. @RequestParam reads them.

@GetMapping
public List<TaskItemResponse> findAll(@RequestParam(required = false) Boolean done) {
    List<TaskItem> items = (done == null)
            ? service.findAllTaskItems()
            : service.findTaskItemsByDone(done);
    return items.stream().map(TaskItemResponse::from).toList();
}

  • GET /api/tasks?done=false lists unfinished tasks.

  • GET /api/tasks still lists every task, because done is optional.

  • Path variables name which resource; query parameters filter or sort.

Request Body: Create a Task

A POST sends the new task as JSON in the body. @RequestBody turns that JSON into a record.

public record CreateTaskRequest(String title) { }
@PostMapping
public TaskItemResponse create(@RequestBody CreateTaskRequest request) {
    return TaskItemResponse.from(service.addTaskItem(request.title()));
}

  • Jackson matches the JSON key title to the record component title.

  • This works, but it answers 200 OK. A create should answer 201 Created.

201 Created and Location

ResponseEntity lets a method choose the status code and headers, not just the body.

@PostMapping
public ResponseEntity<TaskItemResponse> create(@RequestBody CreateTaskRequest request) {
    TaskItem saved = service.addTaskItem(request.title());
    URI location = URI.create("/api/tasks/" + saved.getId());
    return ResponseEntity.created(location).body(TaskItemResponse.from(saved));
}

  • created(location) sets status 201 and the Location header.

  • The client learns the new task's URL without guessing its id.

PATCH: Mark a Task Done

PATCH changes part of a task. When there is nothing useful to send back, answer 204 No Content.

public record UpdateTaskRequest(boolean done) { }
@PatchMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void update(@PathVariable Long id, @RequestBody UpdateTaskRequest request) {
    service.setDone(id, request.done());
}

  • @ResponseStatus sets the success status for a void method.

  • The Service's @Transactional setDone from the JPA lecture does the work.

DELETE: Remove a Task

A delete needs only the id from the URL. It has no request body and no response body.

@DeleteMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)
public void delete(@PathVariable Long id) {
    service.deleteTaskItem(id);
}

  • Each controller method is a few lines: read the request, call the Service, shape the response.

  • Task rules stay in the Service. It gains small methods for these endpoints: getTaskItem, findTaskItemsByDone, and deleteTaskItem.

Validation and Errors

Validate the Request Body

Constraints on the request record reject bad input before the controller method runs.

public record CreateTaskRequest(
        @NotBlank @Size(max = 100) String title) { }
@PostMapping
public ResponseEntity<TaskItemResponse> create(
        @Valid @RequestBody CreateTaskRequest request) { ... }

  • @Valid checks the constraints; a failure answers 400 Bad Request.

  • @Size with max = 100 matches the length = 100 column from the JPA lecture.

  • The Service keeps its own title check, because the JavaFX side calls it too.

  • Validation needs the spring-boot-starter-validation dependency.

Exceptions Carry Meaning

A specific exception type lets the web layer choose the right status code.

public class TaskNotFoundException extends RuntimeException {
    public TaskNotFoundException(Long id) {
        super("Task item " + id + " not found");
    }
}
@Transactional(readOnly = true)
public TaskItem getTaskItem(Long id) {
    return repository.findById(id).orElseThrow(() -> new TaskNotFoundException(id));
}

  • A missing task becomes TaskNotFoundException, which should be 404.

  • A blank title is still IllegalArgumentException, which should be 400.

  • setDone and deleteTaskItem throw TaskNotFoundException too.

Handle Errors in One Place

@RestControllerAdvice maps exceptions to responses for every controller at once.

@RestControllerAdvice
public class ApiExceptionHandler {
    @ExceptionHandler(TaskNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    ApiError notFound(TaskNotFoundException exception) {
        return new ApiError(404, exception.getMessage());
    }

    @ExceptionHandler(IllegalArgumentException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    ApiError badRequest(IllegalArgumentException exception) {
        return new ApiError(400, exception.getMessage());
    }
}

  • Controller methods stay short: no try/catch in each one.

  • An exception with no handler becomes 500 Internal Server Error.

The Error Response

Clients get a small, predictable JSON body for every handled error.

public record ApiError(int status, String message) { }
HTTP/1.1 404 Not Found
Content-Type: application/json

{"status": 404, "message": "Task item 42 not found"}

  • The status code is for programs; the message is for people.

  • Validation failures use Spring Boot's default 400 body unless we add a handler for them.

Testing the API

Try the API with curl

curl sends any HTTP request from the terminal, so we can test methods a browser cannot send.

curl -i -X POST http://localhost:8080/api/tasks \
     -H "Content-Type: application/json" \
     -d '{"title": "Review REST"}'

curl "http://localhost:8080/api/tasks?done=false"

curl -i -X PATCH http://localhost:8080/api/tasks/1 \
     -H "Content-Type: application/json" -d '{"done": true}'

curl -i -X DELETE http://localhost:8080/api/tasks/1

  • -X sets the method, -H adds a header, and -d sends a body.

  • -i shows the status line and headers.

Test the Web Layer with MockMvc

A web-layer test sends a fake request to the controller and checks the response, without starting a server.

@WebMvcTest(TaskApiController.class)
class TaskApiControllerTest {
    @Autowired
    MockMvc mockMvc;

    @MockitoBean
    TaskService service;

    @Test
    void rejectsBlankTitle() throws Exception {
        mockMvc.perform(post("/api/tasks")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("{\"title\": \"   \"}"))
                .andExpect(status().isBadRequest());
    }
}

  • @WebMvcTest starts only the web layer: no Tomcat and no database.

  • @MockitoBean supplies a stand-in TaskService.

  • This test checks the API contract: a blank title must answer 400.

Summary

Common Mistakes

  • Putting verbs in URLs, such as /api/createTask.

  • Answering 200 OK for everything, including errors.

  • Returning JPA entities directly as JSON.

  • Putting task rules in the controller instead of the Service.

  • Forgetting @RequestBody, so the JSON body is ignored.

  • Forgetting @Valid, so the constraints are never checked.

  • Building without the -parameters compiler flag, so Spring cannot match {id} to the id parameter. spring-boot-starter-parent turns it on.

Key Takeaways

  • HTTP requests carry a method, a URL, headers, and a body; responses carry a status code.

  • REST URLs name resources, methods name actions, and JSON carries the data.

  • @PathVariable, @RequestParam, and @RequestBody read request data.

  • @RestControllerAdvice turns exceptions into the right status codes.

  • The web controller and the JavaFX controller share one TaskService.
