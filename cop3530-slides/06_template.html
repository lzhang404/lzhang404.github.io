Big idea (generic programming)

Templates let you write algorithms and data structures that are type-independent.

  • You provide the algorithm once

  • The compiler generates type-specific versions as needed

  • This is how the STL works: vector<T>, stack<T>, map<K,V>, …

Important: templates are a compile-time feature, not a runtime feature.

Motivation

Problem: same logic, many types

Suppose we want a function that returns the minimum of three items.

  • Works for int, double, char, string, etc.

  • But the logic is always: compare and keep the smallest

Without templates, you end up writing many almost-identical functions.

Redundant code (two versions)

Same algorithm, copied for different types:

// min of 3 ints
int TripleMinInt(int item1, int item2, int item3) {
  int minVal = item1;
  if (item2 < minVal) minVal = item2;
  if (item3 < minVal) minVal = item3;
  return minVal;
}

// min of 3 chars
char TripleMinChar(char item1, char item2, char item3) {
  char minVal = item1;
  if (item2 < minVal) minVal = item2;
  if (item3 < minVal) minVal = item3;
  return minVal;
}

  • Maintenance issue: fix a bug in one → must fix it everywhere

  • More code = more chances for mistakes

Template solution

  • Write the algorithm once

  • Replace the type (int, char, …) with a placeholder type T

  • The compiler “fills in” the type later when you call it

You can think of templates as “recipes” for generating real code.

Quick check

In the two functions above, what is the only real difference?

  • A) The algorithm is different

  • B) The return type and parameter types are different

  • C) The number of comparisons is different

Quick check: answer

  • B: only the types differ; the algorithm is the same.

Function Templates

Function template syntax

General pattern:

template <typename T>
T name(T p1, T p2 /* ... */) {
  // uses T like a normal type
}

  • template <typename T> introduces a template parameter named T

  • T can be used as a type in parameters, locals, return type

  • When called, the compiler picks a concrete type for T

TripleMin as a template

This version works for any T that supports < comparison.

template <typename T>
T TripleMin(T item1, T item2, T item3) {
  T minVal = item1;
  if (item2 < minVal) minVal = item2;
  if (item3 < minVal) minVal = item3;
  return minVal;
}

If you try a type that does not define operator<, the compiler will error.

Calling a function template

In most cases, you just call it like a normal function:

int a = TripleMin(10, 5, 7);         // T deduced as int
char b = TripleMin('z', 'a', 'm');   // T deduced as char

std::string s1 = "cat", s2 = "apple", s3 = "zoo";
std::string c = TripleMin(s1, s2, s3); // T deduced as std::string

  • This is called template argument deduction

  • The compiler looks at the argument types and decides what T is

What the compiler generates (instantiation)

When you call TripleMin for different types, the compiler generates different functions:

  • TripleMin<int>(int,int,int)

  • TripleMin<char>(char,char,char)

  • TripleMin<std::string>(std::string, std::string, std::string)

This happens at compile time; there is no runtime “template engine.”

Common gotcha: mixed types

This template expects all parameters to be the same type T:

// Won't compile in many cases:
auto x = TripleMin(1, 2.5, 3);

  • Why? Arguments are int, double, int

  • Compiler can’t pick ONE T that matches exactly (without conversions)

Fix 1: explicit template argument

Force a specific type:

auto x = TripleMin<double>(1, 2.5, 3);

  • Now all arguments are converted to double

  • So T = double

Fix 2: multiple template parameters

If you really want mixed types, define multiple placeholders:

template <typename T1, typename T2, typename T3>
auto TripleMinMixed(T1 a, T2 b, T3 c) {
  auto minVal = a;
  if (b < minVal) minVal = b;
  if (c < minVal) minVal = c;
  return minVal;
}

But now you must think carefully about the return type and conversions.

Practice: will it compile?

Assume TripleMin is the single-T template.

  • 1) TripleMin(3, 2, 1)

  • 2) TripleMin(3, 2.0, 1)

  • 3) TripleMin<double>(3, 2.0, 1)

Practice: answer

  • 1) Yes: all int → T=int

  • 2) Usually no: mixed int/double makes deduction fail

  • 3) Yes: you explicitly set T=double, so ints convert to double

Template Constraints

Templates require operations

Templates don’t magically work for every type — the type must support the operations used inside the template.

  • In TripleMin, we use < to compare

  • So the type must define a meaningful operator<

If the operation doesn’t exist, the error appears during instantiation (when the template is used).

Example: custom type needs <

If you want TripleMin to work for your own class, define ordering:

struct Point {
  int x, y;
};

// define an ordering (example: compare x then y)
bool operator<(const Point& a, const Point& b) {
  if (a.x != b.x) return a.x < b.x;
  return a.y < b.y;
}

// Now TripleMin(Point, Point, Point) can compile.

Class Templates

Class template concept

A class template is a blueprint for generating classes with different internal types.

  • Example: std::vector<int> vs std::vector<std::string>

  • Same class design; different element type

TripleItem class template

Stores three values of the same type and can compute the minimum.

template <typename T>
class TripleItem {
public:
  TripleItem(T v1, T v2, T v3)
    : item1(v1), item2(v2), item3(v3) {}

  void PrintAll() const {
    std::cout << "(" << item1 << ", " << item2 << ", " << item3 << ")\\n";
  }

  T MinItem() const {
    T minVal = item1;
    if (item2 < minVal) minVal = item2;
    if (item3 < minVal) minVal = item3;
    return minVal;
  }

private:
  T item1, item2, item3;
};

Requirement: T must support < and also printing if you call PrintAll().

Using TripleItem

TripleItem<int> triInts(9999, 5555, 6666);
triInts.PrintAll();
std::cout << "min = " << triInts.MinItem() << "\\n";

TripleItem<std::string> triStr("cat", "apple", "zoo");
std::cout << triStr.MinItem() << "\\n";

Quick check

What happens if T does NOT support printing with <<?

  • A) The class won’t compile at all

  • B) It compiles unless you call PrintAll()

  • C) It prints garbage at runtime

Quick check: answer

  • B: templates compile the parts you use. If you never call PrintAll(), that code may never be instantiated.

Multiple Template Parameters

Why have more than one type?

Some structures naturally store different types in different roles.

  • Example: key/value pairs (like a dictionary)

  • Key might be a string, value might be an int

  • Or key might be an int, value might be a custom object

Simple key/value class template

template <typename Key, typename Value>
class Entry {
public:
  Entry(const Key& k, const Value& v) : key(k), value(v) {}
  const Key& getKey() const { return key; }
  const Value& getValue() const { return value; }
private:
  Key key;
  Value value;
};

This is the idea behind many STL components (pairs, maps, unordered_maps).

Template Organization

Why templates are usually “header-only”

The compiler must see the full template definition when it instantiates it.

  • If method bodies are hidden in a .cpp, other files can’t instantiate new template types.

  • This leads to linker errors (undefined references) or missing symbols.

Common patterns

  • All in header: declarations + definitions in .hpp

  • Header + .tpp: declare in .hpp, define in .tpp and include it

  • Explicit instantiation: define in .cpp, then explicitly instantiate supported types

In most CS courses, the “header-only” approach is simplest.

Example: .hpp includes implementation

// TripleItem.hpp
#pragma once
#include <iostream>

template <typename T>
class TripleItem {
  // declarations...
};
/*
template definition
*
// OR include implementation at the bottom
#include "TripleItem.tpp"

This keeps headers cleaner while still letting the compiler see definitions.

Common Template Errors

1) “no matching function”

  • Often caused by template argument deduction failing

  • Common reason: mixed argument types for a single-T template

  • Fix: cast, or specify <T> explicitly, or redesign template

2) “invalid operands to operator<”

  • The type doesn’t support the operation your template uses

  • Fix: define the operator for your custom type, or change the template to use a comparator

3) Linker errors for templates

  • Template definitions are not visible when instantiated

  • Fix: move definitions to header (or include .tpp), or explicitly instantiate

Review

Summary

  • Templates let you write code that works for many types (generic programming)

  • Function templates reduce repeated algorithm code

  • Class templates generalize data structures (STL style)

  • Types used with templates must support the required operations

  • Template definitions usually live in headers so the compiler can instantiate them

Review questions

  • What does “instantiation” mean for templates?

  • Why might TripleMin(1, 2.0, 3) fail to compile?

  • What operations must T support for TripleMin to work?

  • Why are templates commonly implemented in header files?

Review answers

  • Instantiation is when the compiler generates a concrete function/class for a specific type.

  • Deduction may fail because the arguments have different types for a single-T template.

  • T must support < comparison (and printing if you print values).

  • The compiler must see the full template definition when generating code for specific types.
