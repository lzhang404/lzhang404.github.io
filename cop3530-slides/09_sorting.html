Sorting Overview

What is Sorting

  • Definition: Reordering a collection (list/array) so items appear in a chosen order

  • Why it matters:

    • Makes searching faster (binary search needs sorted data)

    • Helps with data cleaning and reporting

    • Used inside many other algorithms

  • Everyday examples:

    • Sorting your photo by date

    • Contacts A->Z

Time Complexity

  • Comparison-based sorting algorithms (Array)

    • Bubble sort Θ(n²)

    • Selection sort Θ(n²)

    • Insertion sort Θ(n²)

    • Merge sort Θ(n log n)

    • Quick sort Θ(n log n) (average), Θ(n²) (worst)

    • Heap sort Θ(n log n)

  • Non-comparison-based sorting algorithms (Array)

    • k is a constant value depending on algorithms

    • Radix sort Θ(nk)

    • Counting sort Θ(n + k)

    • Bucket sort Θ(n + k)

  • Linked list

    • Merge sort Θ(n log n)

    • Insertion sort Θ(n²)

Space Complexity (Array)

  • In-place sorting algorithms (swap based) Θ(1)

    • Θ(1) for swapping

    • Θ(log n) to Θ(n) for recursion stack

    • Iterative: swapping only

    • Recursive: swapping + recursion stack

  • Out-of-place sorting algorithms Θ(n)

    • Θ(n) for a new array

    • Θ(log n) to Θ(n) for recursion stack

Insertion Sort

Insertion Sort

  • Big idea:

    • Build the final sorted list one item at a time.

    • For each new item, insert it into the right spot among the items already sorted to its left.

  • Analogy

    • Sorting playing cards in your hand

    • Pick the next card and insert it into the proper position

  • Good for

    • Small lists

    • Lists that are already almost sorted

  • Visualization: https://lzhang404.github.io/sorting/insertionsort/

Key Characteristics

  • Comparison-based sorting

  • Iterative (not recursive)

  • In-place (no extra memory required)

  • Stable (preserves order of equal elements)

  • Adaptive (very fast on nearly sorted data)

  • Simple implementation

  • Poor performance on large, random data (O(n²))

Complexity & Properties

  • Best case (already sorted): O(n) just one check per item

  • Average: O(n²)

  • Worst case: O(n²) when the array is reverse sorted

  • Space: O(1) extra (in-place)

Pros & Cons

  • Pros

    • Very simple to implement

    • Great when the input is almost sorted

    • Works in-place; stable

  • Cons

    • Gets slow as n grows large (quadratic time)

  • When to use

    • Sorting small number of items < 30 ~ 50

    • As a cleanup step after a bigger algorithm mostly sorted the list

    • In practice: often used inside faster sorts (e.g., switch to insertion sort for tiny subarrays)

Implementation (Insertion Sort)

  • Before each iteration:

    • arr[0..i-1] is sorted

    • arr[i..n] is unsorted

  • Inserting the current element (key) requires finding the correct spot within that sorted region

  • Therefore, we move leftward to find where it fits

  • Core idea:

    • Take the key element at index i

    • Compare with elements to its left

    • Shift all larger elements right to make space

    • Insert key in the correct position

void insertionSort(int arr[], int n) {
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j = j - 1;
        }
        arr[j + 1] = key;
    }
}

Quicksort

Key Characteristics

  • Comparison-based sorting

  • Recursive (divide and conquer)

  • In-place (needs only stack space Θ(log n))

  • Not stable (standard implementation does not preserve equal order)

  • Fast average performance (Θ(n log n))

  • Worst case Θ(n²) if partitions are unbalanced

  • Performance depends on pivot selection (random/median-of-three improves)

Quick Partition Algorithm

  • The core of quick sort

  • Steps:

    • Pick an element, called pivot, from the list

    • Use the pivot to partition the list into two sublists

  • Maintain indices i and j:

    • All elements ≤ pivot are left of i

    • All elements ≥ pivot are right of j

    • Elements between i and j are unknown

  • The loop shrinks the unknown retion until pointers cross

  • Return the location of the partition

Quick Partition Algorithm (Hoare's scheme)

  • Select the pivot:

    • use the middle element as the pivot

  • Initialize cursors:

    • set i = low and j = high

  • Move the left cursor i:

    • move i to the right while arr[i] < pivot

  • Move the right cursor j:

    • move j to the left while arr[j] > pivot

  • Check for completion:

    • if i >= j, the partition is complete. Return j as the split index

  • Swap misplaced elements

    • If the cursors have no crossed, swap arr[i] and arr[j]

  • Advance both cursors

    • Increment i and decrement j

  • Repeat from step 3 until the loop ends

Implementation (Quicksort partition)

  • Low = 0, high = 4, pivot = 8

  • i

  • j

int partition(int arr[], int low, int high) {
    int midpoint = low + (high - low) / 2;
    int pivot = arr[midpoint];
    int i = low, j = high;
    while (i <= j) {
        while (arr[i] < pivot)
            i += 1;
        while (arr[j] > pivot)
            j -= 1;
        if (i >= j) break;
        std::swap(arr[i], arr[j]);
        i += 1;
        j -= 1;
    }
    return j;
}

Time Complexity

  • Time Complexity

  • Depends on whether the pivot splits the list into two roughly equal parts

  • Average case: Θ(n log n)

  • Worst case: Θ(n²), when partitioning is extremely unbalanced

  • Space Complexity

  • Θ(log n) to Θ(n), depending on recursion depth and partition behavior

  • Improvement Attempts

    • Pivot selection

    • Randomized quicksort

    • Median of three

    • Shuffling the list before sorting

  • Visualization: https://lzhang404.github.io/sorting/quicksort/

Merge Sort

Key Characteristics

  • Comparison-based sorting

  • Recursive

  • Out-of-place (requires extra memory)

  • Stable (preserves order of equal elements)

  • Parallelable (easy to split work)

Algorithm Overview (Top-Down)

  • Divide the array into two halves

  • Conquer recursively by sorting each half

  • Combine by merging the two sorted halves

  • Zybook 9.4

  • Visualization: https://lzhang404.github.io/sorting/mergesort/

Time & Space Complexity (Merge Sort)

  • Time: Θ(n log n) in best/average/worst (always splits in half, always merges n items)

  • Space: Θ(n) extra array for merging (array-based); recursion depth Θ(log n)

  • Stability: stable if merge step keeps equal keys in original order

Recurrence (top-down):
T(n) = 2T(n/2) + Θ(n)
→ Θ(n log n)

Variations

  • Top-down merge sort (recursive)

  • Bottom-up merge sort (iterative)

  • Natural merge sort (uses pre-existing order)

  • Visualization: https://lzhang404.github.io/sorting/mergesort/

Radix Sort (LSD)

Radix Sort

  • Radix sort is for integers/strings with fixed length

  • It's a form of bucket sort

  • Bucket: a group of numbers sharing the same digit value for a chosen place

  • Example:

Base K (Radix)

  • What is base (k)?

  • Number of buckets (symbols) processed per pass.

  • Examples:

    • base 10: digits 0–9;

    • base 2: bits 0–1;

    • base 256: bytes 0–255.

  • Why it matters

    • Higher k: fewer passes, more memory per pass.

    • Lower k: more passes, less memory per pass.

  • Total time ≈ d · (n + k) where d is number of digit-positions in base k.

LSD Radix Sort

  • For each digit from least to most significant:

  • Scatter: place each value into a bucket based on the current digit

  • Gatter: copy buckets back to the array from bucket 0 → 9 (stable order) After the last digit, the array is sorted

Characteristic

  • Non-comparison-based sorting algorithm

  • Only works with integers, and strings whose length is finite

  • Digit/character-based

  • Stable

  • Out-of-place

  • Time: O(d·(n + k)), with base k (e.g., 10) and d = digits

  • Space: O(n + k) for buckets and auxiliary arrays

  • Stable: if per-digit gather is stable

  • Works best when keys have bounded length (e.g., up to 3 digits → d = 3)

Wrap-up

  • Comparison-based sorts: rely on comparisons (insertion/quick/merge)

  • Radix sort: uses digits/characters + stable passes (no comparisons)

  • Pick based on data structure and constraints (arrays vs lists, memory, stability)

  • Always consider edge cases: empty, one element, duplicates, already sorted
