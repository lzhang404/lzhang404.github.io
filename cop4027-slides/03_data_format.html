Data and Configuration Formats

Advanced Programming

Overview

Learning Goals

After this topic, you should be able to:

  • Explain why programs keep configuration and data outside source code.

  • Recognize the basic syntax of properties, JSON, YAML, and XML.

  • Choose an appropriate Java reading strategy: key-value, object mapping, tree model, or streaming.

  • Convert parsed text values into useful Java types and validate them.

  • Describe how schemas, namespaces, and application rules help keep external data safe and predictable.

External Formats

External Configuration

Hardcoded values are simple but fragile:

String databaseUrl = "jdbc:mysql://localhost/store";
int port = 8080;
boolean debug = true;
String dataFile = "products.json";

  • Changing settings requires changing and rebuilding code.

  • Different machines may need different values.

  • Passwords and tokens must not be stored in source code.

Common workflow:

External text
  -> locate the source
  -> open it safely
  -> parse the syntax
  -> represent it in Java
  -> validate the meaning
  -> use it or write it back

This topic prepares us for JavaFX FXML, Spring Boot, REST APIs, databases, and containers.

Config vs Data

Configuration

  • Controls how the program behaves.

  • Usually small and read near startup.

  • Edited by developers, administrators, or deployment tools.

app.name=Inventory Manager
server.port=8080
debug=false
data.file=products.json

Application Data

  • Information the program processes.

  • May grow or change while the program runs.

  • Created by users, services, APIs, or databases.

{
  "id": 1,
  "name": "Keyboard",
  "price": 49.99,
  "available": true
}

Data Sources

External text can come from several places:

  • Classpath resources: files packaged with the application, commonly under src/main/resources.

  • External files: files stored outside the application, such as a config folder on the machine.

  • Runtime settings: environment variables and command-line arguments.

  • Remote or persistent sources: API responses, network requests, and databases.

The source tells Java where the text comes from. The format tells Java how to parse it.

//external file path
Path path = Path.of("config", "application.properties");

// Classpath resource
InputStream input = PropertiesExample.class.getResourceAsStream(
        "/data/application.properties"
    );

Choosing a Format

  • Use properties for a few simple Java settings.

  • Use JSON for REST API requests, responses, and structured application data.

  • Use YAML for readable nested configuration, especially deployment and Spring-style config.

  • Use XML when the document needs elements, attributes, namespaces, or schema validation.

The best format depends on the data shape, who edits it, and how strictly it must be validated.

Properties Files

Properties Syntax

# comments can start with #
! comments can also start with !
app.name=Inventory Manager
server.port=8080
debug=false
data.file=products.json
categories=Books,Electronics
long.message = first line \
               second line

  • Each line stores one key-value pair.

  • = and : are commonly used as separators.

  • Values are read as strings.

  • The file is flat: there are no real nested objects or arrays.

Reading Properties

Properties properties = new Properties();

// A leading slash starts at src/main/resources.
InputStream resource = PropertiesExample.class.getResourceAsStream(
    "/data/application.properties"
);
if (resource == null) {
    throw new IOException("Resource not found");
}

try (InputStream input = resource) {
    // load(...) reads key-value pairs from the stream.
    properties.load(input);
}

String appName = properties.getProperty(
    "app.name", "My Application"
);

  • Use try-with-resources when opening files or resources.

  • getProperty returns a string and can provide a default value.

  • Example: examples/data-formats/src/main/java/cop4027/data/PropertiesExample.java

Property Validation

int port = Integer.parseInt(
    properties.getProperty("server.port", "8080")
);

boolean debug = Boolean.parseBoolean(
    properties.getProperty("debug", "false")
);

List<String> categories = Arrays.stream(
        properties.getProperty("categories", "").split(","))
    .map(String::trim)
    .filter(value -> !value.isEmpty())
    .toList();

public ServerSettings {
    if (port < 1 || port > 65535) {
        throw new IllegalArgumentException(
            "server.port must be between 1 and 65535"
        );
    }
}

Properties Tradeoffs

Problem examples:

server.port=eighty
debug=yes
categories=Books,, Electronics

  • server.port cannot convert to int.

  • debug=yes becomes false with Boolean.parseBoolean.

  • Strengths: simple syntax, built into Java and easy to edit
  • Limits: flat structure, no native ojects or arrays, values need conversion

JSON

JSON Objects

{
  "stringValue": "hello",
  "numberValue": 42,
  "decimalValue": 3.14,
  "booleanValue": true,
  "nullValue": null,
  "objectValue": { "x": 1 },
  "arrayValue": [1, 2, 3]
}

  • Objects use curly braces: { }

  • Keys and strings use double quotes.

  • Common value types: string, number, boolean, null, object, array.

  • JSON has no comments, dates, classes, or methods by itself.

Nested JSON

{
  "id": 1,
  "name": "Keyboard",
  "tags": ["input", "wired"],
  "manufacturer": {
    "name": "Acme",
    "country": "US"
  }
}

  • Object values can be arrays or nested objects.

  • Field order should not be treated as meaningful application logic.

  • If order matters, use an array.

JSON Arrays

Valid mixed array:

[
  42,
  "Keyboard",
  true,
  null,
  { "id": 1, "name": "Mouse" },
  ["nested", "array"]
]

Common application array:

[
  { "id": 1, "name": "Keyboard", "price": 49.99 },
  { "id": 2, "name": "Mouse", "price": 24.99 },
  { "id": 3, "name": "Monitor", "price": 159.99 }
]

  • JSON allows mixed arrays, but strongly typed Java code is easier with consistent element shapes.

Object Mapping and Tree Model

Object mapping

  • The file is converted into a Java class or record.

  • Field names in the text usually match field names in Java.

  • Best when the structure is known and stable.

Product product = mapper.readValue(input, Product.class);

Tree model

  • The file is converted into generic nodes.

  • The code chooses which nodes to inspect.

  • Best when the structure is flexible or only a few fields are needed.

JsonNode root = mapper.readTree(input);
String name = root.path("name").asText();

Java Records

public record Product(
    int id,
    String name,
    double price,
    boolean available
) {
}

  • Each record component matches a JSON field.

  • A record is compact for data with a known shape.

  • A regular class is still useful when objects need setters, inheritance, or complex behavior.

  • Example: examples/data-formats/src/main/java/cop4027/data/Product.java

Lists of Objects

// ObjectMapper is Jackson's main JSON reader and writer.
ObjectMapper mapper = new ObjectMapper();

InputStream resource = JsonExample.class.getResourceAsStream(
    "/data/products.json"
);
if (resource == null) {
    throw new IOException("Resource not found");
}

try (InputStream input = resource) {

    // TypeReference keeps the information that this is a List of Product,
    // not just a raw List.
    List<Product> products = mapper.readValue(
        input,
        new TypeReference<List<Product>>() {}
    );
}

  • Object mapping is best when the JSON shape is known and stable.

  • The rest of the program works with normal Java data, not raw JSON.

Tree Model

ObjectMapper mapper = new ObjectMapper();

InputStream resource = JsonExample.class.getResourceAsStream(
    "/data/products.json"
);
if (resource == null) {
    throw new IOException("Resource not found");
}

try (InputStream input = resource) {

    // Parse JSON into a generic tree instead of a Product class.
    JsonNode root = mapper.readTree(input);

    // The root is an array, so get(0) selects the first item.
    // path("name") selects the field without returning null.
    // asText("(missing)") converts it to text with a fallback.
    String name = root.get(0)
        .path("name")
        .asText("(missing)");
}

  • Use the tree model when the JSON structure is flexible or only a few fields are needed.

Choosing Mapping or Tree

  • Choose object mapping when

    • the file has a stable shape
    • and the rest of the program wants normal Java objects

  • Choose tree model when

    • the file shape may vary
    • fields are optional
    • the program only needs part of the data

  • Both approaches still need validation. Parsing does not prove that the values make sense for the application.

Known shape      -> Product or List<Product>
Flexible shape   -> JsonNode tree
Very large input -> streaming parser

JSON I/O

Serialization converts Java objects to JSON text. Deserialization converts JSON text to Java objects.

String json =
    mapper.writerWithDefaultPrettyPrinter()
          .writeValueAsString(products);

List<Product> copy = mapper.readValue(
    json,
    new TypeReference<List<Product>>() {}
);
Java object  --serialization-->    JSON text
JSON text    --deserialization-->  Java object

JSON Error Types

Syntax error: Syntax fails before mapping. 

{
  "name": "Keyboard",
  "price": 49.99,
}

Wrong type: Wrong type fails during mapping.

{
  "id": 1,
  "name": "Keyboard",
  "price": "forty-nine"
}

Invalid value: Invalid value fails during application validation

{
  "id": 1,
  "name": "",
  "price": -25.00
}

JSON Error Handling

try {
    List<Product> products = loadProducts();
} catch (JsonProcessingException exception) {
    System.err.println(
        "Invalid JSON: " + exception.getOriginalMessage()
    );
} catch (IOException exception) {
    System.err.println(
        "Unable to read products: " + exception.getMessage()
    );
}

  • Parsing errors and resource errors communicate different problems.

  • Example: examples/data-formats/src/main/java/cop4027/data/JsonExample.java

YAML

YAML Basics

app:
  name: Inventory Manager
server:                 # map
  port: 8080
debug: false            # scalar
dataFile: products.json # scalar
categories:             # list
  - Books
  - Electronics

  • Indentation creates hierarchy.

  • A scalar is a single value; a map stores key-value pairs; a list stores ordered items.

YAML Types

Mixed lists are possible:

mixedValues:
  - 42
  - Keyboard
  - true
  - null
  - id: 1
    name: Mouse
  - [nested, list]

Quote values that must stay text:

debug: false
port: 8080
version: "1.0"
code: "00123"
message: "false should stay text here"

  • Consistent list items are easier to map into Java types.

  • Unquoted values may be interpreted as booleans, numbers, or null.

YAML in Java

  • Java does not include a built-in YAML parser.

  • Jackson can read YAML when the project adds the YAML module.

  • For known configuration, map YAML into a record such as ApplicationConfig.

  • For flexible configuration, read YAML into a Map or tree-like structure.

The same idea from JSON applies: choose object mapping when the shape is stable, and choose a map or tree when the shape is flexible.

YAML Records

public record ApplicationConfig(
    AppSettings app,
    ServerSettings server,
    boolean debug,
    String dataFile,
    List<String> categories
) {
    public record AppSettings(String name) {}
    public record ServerSettings(int port) {}
}

// YAMLFactory tells Jackson to read YAML syntax instead of JSON syntax.
ObjectMapper yamlMapper = new ObjectMapper(new YAMLFactory());

InputStream resource = YamlExample.class.getResourceAsStream(
    "/data/application.yaml"
);
if (resource == null) {
    throw new IOException("Resource not found");
}

try (InputStream input = resource) {
    ApplicationConfig config = yamlMapper.readValue(
        input,
        ApplicationConfig.class
    );
}

  • The nested Java records match the nested YAML structure.

  • Example: examples/data-formats/src/main/java/cop4027/data/YamlExample.java

  • Supporting record: examples/data-formats/src/main/java/cop4027/data/ApplicationConfig.java

YAML Error Types

Malformed syntax: Indentation and colons affect syntax. 

server:
 port: 8080
  host: localhost

Wrong shape: Java mapping checks shape. 

server:
  port: eight thousand
categories: Books,Electronics

Invalid values: Application validation checks meaning.

app:
  name: ""
server:
  port: 70000
categories: []

YAML Tradeoffs

  • Strength:

    • for nested configuration.
    • supports maps, lists, and hierarchy without many braces.

  • Limit:

    • indentation errors are common and can change meaning.
    • unquoted values may be interpreted as other data types.

XML

XML Building Blocks

<product id="1" category="input">
  <name>Keyboard</name>
  <price currency="USD">49.99</price>
  <tag>wired</tag>
  <tag>mechanical</tag>
</product>

  • Elements hold data: product, name, price.

  • Attributes describe elements: id, category, currency.

  • Repeated elements can represent a list.

  • Each XML document needs exactly one root element.

Escaping Special Characters

<!-- Invalid: < and & have special meaning -->
<message>A < B & C</message>

<!-- Valid: use entity references -->
<message>A &lt; B &amp; C</message>

  • &lt; means <.

  • &gt; means >.

  • &amp; means &.

  • &quot; and &apos; are useful inside attributes.

CDATA

<script><![CDATA[
if (a < b && c > d) {
    System.out.println("ok");
}
]]></script>

  • CDATA treats text as literal text.

  • Markup is not parsed inside the CDATA block.

  • Useful when the text contains many < or & characters.

XML Namespaces

<order xmlns:store="https://example.com/store"
       xmlns:ship="https://example.com/shipping">
  <store:address>Store 101</store:address>
  <ship:address>123 Main St</ship:address>
</order>

  • xmlns:store="..." declares the store namespace prefix.

  • store and ship are author-chosen prefix names.

  • The URI identifies the namespace; it does not need to be a real web page.

  • store:address and ship:address are different XML names.

  • FXML also uses namespaces, such as xmlns:fx="http://javafx.com/fxml".

XML Rule Levels

XML text
  -> well-formed check
  -> schema validation
  -> parse into Java
  -> application validation

  • Well-formed: correct XML syntax.

  • Schema-valid: follows DTD or XSD rules.

  • Application-valid: makes sense for the program.

Well-Formed XML

Well-formed:

<book>
  <title>XML Basics</title>
  <price>39.99</price>
</book>

Malformed:

<book>
  <title>XML Basics
  <price>39.99</price>
</book>

  • Tags must match.

  • Elements must be properly nested.

  • The document needs one root element.

DTD and XSD

DTD

  • Older XML validation mechanism.

  • Defines elements and order.

  • Uses its own syntax.

<!ELEMENT product (name, price)>
<!ELEMENT name (#PCDATA)>
<!ELEMENT price (#PCDATA)>

XSD

  • More powerful schema language.

  • Written using XML syntax.

  • Checks structure and data types.

<xs:element
    name="price"
    type="xs:decimal"/>

XML Schema Definition

<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="product">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="name" type="xs:string"/>
        <xs:element name="price" type="xs:decimal"/>
        <xs:element name="available" type="xs:boolean"/>
      </xs:sequence>
      <xs:attribute name="id" type="xs:int" use="required"/>
    </xs:complexType>
  </xs:element>
</xs:schema>

  • xs is the namespace prefix for XML Schema.

  • xs:sequence requires child elements in this order.

  • XSD can check types, required fields, ranges, and patterns.

XSD Validation

Valid:

<product id="1">
  <name>Keyboard</name>
  <price>49.99</price>
  <available>true</available>
</product>

Schema-invalid:

<product id="abc">
  <name>Keyboard</name>
  <price>forty-nine</price>
  <available>yes</available>
</product>

  • The second document has legal XML syntax, but its values do not match the XSD types.

Validating XML in Java

SchemaFactory schemaFactory = SchemaFactory.newInstance(
    XMLConstants.W3C_XML_SCHEMA_NS_URI
);

Schema schema = schemaFactory.newSchema(xsdInputStream);

Validator validator = schema.newValidator();
validator.validate(new StreamSource(xmlInputStream));

  • SchemaFactory loads the XSD rules.

  • Validator checks the XML document.

  • Handle validation errors before trusting the data.

  • Example: XsdValidationExample.java

XML Parsing Approaches

  • DOM: loads the whole XML document as a tree.

  • SAX: parser pushes events to handler methods.

  • StAX: code pulls the next event from the parser.

DOM  = whole tree in memory
SAX  = push model: parser calls your code
StAX = pull model: your code calls next()

DOM Parsing

DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();

factory.setNamespaceAware(true);
factory.setFeature(XMLConstants.FEATURE_SECURE_PROCESSING, true);
factory.setAttribute(XMLConstants.ACCESS_EXTERNAL_DTD, "");

try (InputStream input =
         XmlExample.class.getResourceAsStream("/data/product.xml")) {

    Document document = factory.newDocumentBuilder().parse(input);
    Element root = document.getDocumentElement();
}

  • DOM builds a tree of nodes.

  • Easy to search, navigate, and modify.

  • Best when the document fits comfortably in memory.

  • Example: XmlExample.java

Reading DOM Values

int id = Integer.parseInt(root.getAttribute("id"));

String name = root
    .getElementsByTagName("name")
    .item(0)
    .getTextContent()
    .trim();

double price = Double.parseDouble(
    root.getElementsByTagName("price")
        .item(0)
        .getTextContent()
        .trim()
);

  • getAttribute(...) reads an attribute value.

  • getElementsByTagName(...) finds child elements.

  • XML values are text, so Java must convert numbers manually.

SAX Parsing: Push Model

DefaultHandler handler = new DefaultHandler() {
    private boolean inName = false;

    public void startElement(String uri, String localName,
                             String qName, Attributes attrs) {
        inName = "name".equals(qName);
    }

    public void characters(char[] ch, int start, int length) {
        if (inName) {
            System.out.println(new String(ch, start, length));
        }
    }

    public void endElement(String uri, String localName, String qName) {
        if ("name".equals(qName)) {
            inName = false;
        }
    }
};

parser.parse(input, handler);

  • SAX reads from beginning to end.

  • The parser calls our methods when events happen.

  • Good for large read-only XML files.

StAX Parsing: Pull Model

XMLInputFactory factory = XMLInputFactory.newInstance();
XMLStreamReader reader = factory.createXMLStreamReader(input);

while (reader.hasNext()) {
    int event = reader.next();

    if (event == XMLStreamConstants.START_ELEMENT
            && "name".equals(reader.getLocalName())) {
        reader.next();
        System.out.println(reader.getText());
    }
}

reader.close();

  • StAX also reads the XML as a stream.

  • Our code calls next() to move forward.

  • Good when the program needs more control than SAX.

Choosing a Parser

Parser Main Idea Best For
DOM Whole tree Easy navigation and editing
SAX Parser pushes events Large read-only files
StAX Code pulls events Large files with more control

  • DOM is the main practical parser for this course.

  • SAX and StAX are important to recognize for large XML files.

Config Precedence

Applications often receive settings from multiple sources.

Built-in default
  -> configuration file
  -> environment variable
  -> command-line argument

  • Defaults keep the application usable.

  • Files make configuration visible and repeatable.

  • Environment variables are useful in deployment.

  • Command-line arguments are useful for one-time overrides.

Secrets

Do not commit real secrets:

database.password=myActualPassword
api.key=abc123secret

Use environment names or a secret manager:

DATABASE_PASSWORD
API_KEY

Commit an example file:

application.properties.example
database.url=jdbc:mysql://localhost/inventory
database.username=YOUR_USERNAME
database.password=YOUR_PASSWORD

Do not commit the real local file.

Summary

Format to Java

  • Properties: Properties.load() reads key-value strings, then code converts and validates values.

  • JSON: Jackson ObjectMapper reads objects, lists, or JsonNode trees.

  • YAML: Jackson YAML or SnakeYAML reads configuration into records, maps, or trees.

  • XML: DOM, SAX, or StAX reads documents as trees or stream events.

  • Environment variables: System.getenv() reads named strings from the runtime environment.

Connections

  • JavaFX: FXML is XML-based, and CSS controls styling.

  • Spring Boot: applications commonly use properties or YAML configuration.

  • REST APIs: request and response bodies commonly use JSON.

  • Containers and deployment: tools commonly use YAML, environment variables, and secrets.

  • Databases: structured files are useful, but shared persistent data needs database support.

Takeaway

  • Configuration controls how an application runs; application data represents what it processes.

  • Before parsing, decide what Java representation you want.

  • Parsing a file is not the same as validating its meaning.

  • Secrets should stay out of source control and AI prompts.
